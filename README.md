# VPN Tunnel Enforcer

Клиент VPN для Windows 10/11 x64: изоляция трафика и обход блокировок. Версия 2.0.0, состояние на 13.11.2026.

С версии 2.0 клиент написан на Rust (редакция 2024, rustc 1.99) и полностью заменяет прежний клиент на
Electron/TypeScript (последняя версия 1.1.24); код старого клиента из репозитория удалён. Интерфейс —
Dioxus 0.7.10 desktop в WebView2, в одном процессе с остальной программой: нет IPC-слоя, Node.js, PowerShell
и вспомогательных скриптов. Трафик обрабатывают дочерние процессы sing-box 1.14.4 (с `libcronet.dll` и
`wintun.dll`) и Xray 26.11.9. Конфигурация уходит им через stdin, ключи на диск не пишутся; дочерние процессы
сидят в Job Object и завершаются вместе с приложением.

## Режимы и права

| Режим | Права | Как берётся трафик |
| --- | --- | --- |
| «Прокси» (Soft) | не нужны | движок слушает loopback-вход `mixed` (HTTP + SOCKS5) на `127.0.0.1`; приложение направляет на него системный прокси пользователя, по выбору — переменные окружения, Git, Gradle, Android Studio |
| «Туннель» (Hard) | служба-помощник (или запуск от имени администратора) | sing-box в службе поднимает TUN-адаптер Wintun (`auto_route` + `strict_route`, IPv4 и IPv6, перехват DNS) |

- Служба-помощник `vpnte-service` (решение владельца 12.11.2026): служба Windows от LocalSystem в
  `%ProgramFiles%\VPN Tunnel Enforcer Service\`, запускается вместе с Windows, в простое — несколько МБ и
  ни одного таймера. Движок «Туннеля» работает внутри неё, как у Happ. Установщик ставит её без вопросов:
  Windows показывает своё окно один раз. Отказ или нет прав администратора — приложение работает в
  «Прокси», а в настройках рядом с выбором режима есть кнопка «Установить службу-помощник».
- Приложение никогда не повышает себе права. Единственный шаг с правами — установка службы её же
  командой, с окном Windows. Без службы и без прав «Туннель» и WFP kill switch показаны недоступными
  с причиной «нужна служба-помощник», а не работающими; запущенное от имени администратора приложение без
  службы делает всё само, как раньше.
- Первый запуск без службы выбирает «Прокси». Молча «Туннель» на «Прокси» не меняется.
- В «Прокси» программы, которые не используют системный прокси, идут напрямую, и интерфейс это пишет.
- Kill switch: «Выключен» (по умолчанию), «При обрыве» и «Всегда». «При обрыве» ставит интернет на паузу,
  только если VPN оборвался сам и уже был поднят; «Отключить» и выход возвращают интернет сразу. Пауза
  видна на главной и в трее, с кнопками «Подключить» и «Продолжить без VPN». В «Прокси» kill switch
  действует через системный прокси, в «Туннеле» — фильтрами WFP службы в своём провайдере и подслое.
  «Всегда» доступно со службой: она держит фильтры и после выхода из приложения, и после перезагрузки.
- Если окно приложения упало, служба не обрывает VPN: при следующем запуске приложение подхватывает
  сессию и показывает её. «Выход» и «Отключить» останавливают VPN как обычно.
- Удаление: деинсталлятор сообщает службе, что пользователь ушёл (без окна прав); с уходом последнего
  пользователя служба убирает свои фильтры, регистрацию и файлы.

## Что есть

- Список серверов и подписки: ссылки VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, NaïveProxy, AnyTLS,
  WireGuard, SOCKS, HTTP; JSON, Clash YAML, WireGuard `.conf`, deep links; группы, архив, фоновое
  обновление, проверка ключей, страны и пинги. Движок выбирается в настройках («авто», sing-box или Xray);
  в «авто» профиль, которому нужен Xray (XHTTP, VLESS Encryption и др.), идёт через Xray, остальные — через
  sing-box.
- Маршрутизация: Smart RU (локальные наборы правил `geoip-ru.srs`, `geosite-category-gov-ru.srs` и списки
  заблокированных в РФ сайтов и адресов runetfreedom, которые идут через VPN сразу после правил
  пользователя; наборы обновляются раз в сутки), раздельное туннелирование по приложениям и доменам,
  импорт профиля маршрутизации Happ с предпросмотром, профили DNS. Правила пользователя всегда главнее
  Smart RU. В «Прокси» — список «Не через прокси» и автоматические записи только там, где маршрут напрямую
  известен заранее.
- Обход блокировок: TLS-трюки для sing-box и Xray (дробление записей и ClientHello, `fragment=` из ссылок),
  выбор сервера с учётом сети (белые списки, резка UDP), DoH Яндекса при старте в сети с подменой DNS,
  проверка всех серверов с ограничением рукопожатий.
- Ссылки и QR с телефона: `happ://`, `incy://`, `v2raytun://`, `sing-box://`, `clash://`, `hiddify://`;
  схемы чужих клиентов приложение берёт, только пока они свободны.
- Проверки: публичный IP и утечки, доступность сайтов, тест скорости, живая проверка сервера с вердиктами.
- Внешние прокси: нумерованные слоты `127.0.0.1:<порт>` (sing-box, при необходимости Xray), локальный API
  управления на `127.0.0.1:17873` с токеном и консольный клиент `vpnte-proxy.exe`.
- Автоматизация: расписание, ротация серверов, AutoPilot, адаптивный обход.
- Статистика трафика, история доменов, выгрузка диагностики в ZIP; захват пакетов (pktmon + ETW) — только
  от администратора.
- Данные: `%APPDATA%\VPN Tunnel Enforcer\` (JSON с атомарной записью, секреты под DPAPI). Данные старой
  версии из `%APPDATA%\vpn-tunnel-enforcer\` один раз импортируются и не изменяются.
- Следы старой версии в системе (правила брандмауэра, задачи планировщика, старый слой WFP) удаляются
  один раз — только от администратора.
- Обновления: подписанная лента для приложения и движков (minisign, свои ключи); новый движок в «Прокси»
  включается без перезапуска приложения, при сбоях пробного запуска возвращается прежняя версия. Пока
  владелец не создал ключи, клиент обновления не проверяет.
- Плановые функции WP-12 (процессный монитор, изоляция аккаунтов) не реализованы; mihomo для AmneziaWG
  есть только в лабораторной сборке (флаг `lab`), в обычную не входит.

## Сторонние сервисы

Своего сервера у клиента нет, разработчику он ничего не отправляет: без аналитики и телеметрии. Сам он
обращается только к сервисам ниже (по коду на 13.11.2026). «Через VPN» — через ваш сервер, «напрямую» — с
вашего настоящего адреса. «Служебный маршрут» — настройка «Маршрут служебных загрузок»: по умолчанию
напрямую, при неудаче через локальный прокси (Happ и т. п.); при работающем «Туннеле» такие запросы идут
через VPN, как у любой программы. Обновления клиент проверяет, только когда в сборке есть ключи подписи
ленты; до первого подписанного релиза он их не проверяет.

## Поставка

- Установщик на пользователя `VPN-Tunnel-Enforcer-Setup-2.0.0.exe` (NSIS): ставит программу в
  `%LOCALAPPDATA%\Programs\VPN Tunnel Enforcer` и пишет только в HKCU и ярлыки пользователя. После этого он
  ставит службу-помощник `vpnte-service` в Program Files: Windows один раз показывает окно UAC. Если права не
  дали, установка продолжается и работает «Прокси»; службу можно поставить позже кнопкой в настройках. При
  обновлении на ту же версию службы окна нет. Удаление программы окна UAC не показывает: служба удаляет себя
  сама, когда уходит последний пользователь.
- Переносной архив `VPN-Tunnel-Enforcer-2.0.0-portable.zip`: распаковать и запустить, без установки и прав.
- Внутри: `VPN Tunnel Enforcer.exe`, `vpnte-service.exe`, `vpnte-proxy.exe` с прежними именами
  `vpnte-proxy.cmd` / `.ps1`, `resources\` (движки и наборы правил), `licenses\`. CRT собран статически,
  VC++ Redistributable не нужен.

## Сборка и запуск

Нужны Windows 10/11 x64, Rust 1.99 (MSVC, через rustup) и WebView2 Runtime (есть в Windows 11). NSIS
`cargo xtask` скачивает сам; Node.js для клиента не нужен (только для `website/`).

```bash
cd vpn-tunnel-enforcer
cargo xtask engines            # закреплённые sing-box, Xray, Wintun: скачать, сверить SHA-256, положить в resources/
cargo xtask verify             # resources/ совпадает с resources/engines.toml
cargo build -p vpnte-app       # target/debug/vpn-tunnel-enforcer.exe
cargo test --workspace         # тесты; группы elevated_* и system_* по умолчанию пропускаются
cargo xtask dist               # target/dist/: установщик, переносной архив, checksums.txt
```

Собранный в `target/debug` exe ищет движки в `<папка exe>\resources`. Для запуска из исходников укажите
абсолютный путь в `VPNTE_RESOURCES_DIR` (например, `<репозиторий>\vpn-tunnel-enforcer\resources`), а чтобы не
трогать свои данные — отдельную папку в `VPNTE_DATA_DIR`; затем `cargo run -p vpnte-app`. Если на этом ПК
установлена служба-помощник, а запуск из исходников не должен её трогать, задайте `VPNTE_NO_SERVICE=1`
(тесты не видят установленную службу всегда).

## Крейты

Рабочее пространство — `vpn-tunnel-enforcer/Cargo.toml`, крейты — `vpn-tunnel-enforcer/crates/<имя>`
(пакет `vpnte-<имя>`). Карта API каждого крейта — в его `API.md`, общие правила — в `crates/CONTRACT.md`.

| Крейт | Что внутри |
| --- | --- |
| `base` | общий контракт: `AppError`, `Msg`, общие перечисления, поиск строк i18n, настройки HTTP/TLS |
| `core` | папки данных, JSON-документы с атомарной записью, секреты DPAPI, настройки, редактирование логов, журналы, разбор адресов, SOCKS5, разрешение имён, реестр операций, чтение данных старой версии |
| `winnet` | слой Windows: адаптеры и маршруты, процессы и Job Object, счётчики, ICMP, WFP kill switch и защита от утечек, реестр, окружение, системный прокси пользователя, права, автозапуск (`HKCU\…\Run`), единственный экземпляр, буфер обмена, события питания, уведомления |
| `profiles` | типизированная модель профиля, импорт (ссылки, JSON, Clash YAML, WireGuard, deep links), генератор конфигурации sing-box, граф Xray, экспорт |
| `view` | чистая логика стартовой страницы: состояние, подписи, расчёты трафика, поведение маскота |
| `ui` | интерфейс Dioxus: окно, оболочка, стартовая страница «Пломба», маскот, трей, все страницы; бэкенд не вызывает, только трейты `XxxApi` |
| `servers` | список серверов: группы, подписки, выбор, архив, результаты проверок, фоновое обновление |
| `engine` | sing-box и Xray: конфигурации, процессы и их сбои, Clash API, маршрутизация и DNS, наборы правил Smart RU |
| `forensics` | статистика трафика, история доменов, захват пакетов (pktmon + ETW), архив диагностики |
| `automation` | расписание, ротация, AutoPilot, адаптивный обход, обратимые настройки режима «Прокси», защита браузеров и геолокации |
| `probes` | измерения: IP и утечки, диагностика, доступность, скорость, пинги, страна и ASN, здоровье ключей, живая проверка сервера |
| `tunnel` | актор подключения (старт, надзор, переключение, стоп), полоса жизненного цикла, конечный автомат, история подключений |
| `proxies` | слоты внешних прокси, локальный API управления, клиент `vpnte-proxy.exe` |
| `cleanup` | одноразовое удаление следов старой версии из системы |
| `app` | бинарник `VPN Tunnel Enforcer.exe`: запуск, связывание интерфейса с бэкендом, команды установщика `--setup` |

Вне `crates/`: `xtask/` (закрепление движков, NSIS, `dist`, `smoke-install`), `installer/` (сценарий NSIS и
шимы), `resources/` (`engines.toml`, наборы правил; движки кладёт `cargo xtask engines`). Устройство и порядок
ревью — `vpn-tunnel-enforcer/docs/architecture/`.

## Что проверено и что нет

- Локально, без прав администратора (13.11.2026, коммит f7a1c65): `cargo fmt --check`, `cargo clippy
  --workspace --all-targets -- -D warnings` без предупреждений (и с лабораторным флагом); `cargo test
  --workspace` — 3401 тест пройден, 0 упало, 57 пропущено (требуют прав администратора, меняют реальные
  настройки пользователя, требуют интернета, рабочего стола или реальных ресурсов системы). Режим «Прокси»
  с настоящим sing-box на loopback покрыт тестами; системный прокси при этом подменён фейком.
- Только в CI, на одноразовом раннере с правами администратора: TUN, фильтры WFP, тесты `system_*`,
  служба-помощник (установка, канал, сессия TUN, удаление) и установщик (тихая установка, обновление
  поверх себя, удаление). Прогон на f7a1c65 (13.11.2026) зелёный целиком, включая джоб с правами
