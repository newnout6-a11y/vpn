# Внешний локальный прокси

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/0364ee3d-d6fd-4bf4-9de8-09e94f157a53

## Feature Summary

Фича реализует независимые локальные HTTP-прокси для профилей серверов из @Внешний локальный прокси. Каждый прокси работает на `127.0.0.1` в отдельном слоте и направляет трафик через выбранный профиль без системного TUN. Пользователь управляет слотами из карточки внешних прокси, а автоматизированные клиенты используют локальный управляющий API и поставляемые скрипты.

## Component Blueprint Composition

* Фича использует `ServerProfile` и операции `serverPicker` для получения доступных профилей, исключения активного системного профиля и профилей, удалённых из подписки.
* Фича использует `ensureKillSwitchProgramAllowed` для разрешения исполняемого файла внешнего прокси в правилах kill-switch.
* Фича использует `managedChildProcess` для записи и удаления PID-файла управляемого процесса.

## Feature-Specific Components

### Main process

```component
name: ExternalProxyManager
container: Electron Main Process
responsibilities:
	- Управляет состоянием прокси-слотов и независимыми процессами sing-box.
	- Строит конфигурацию с mixed inbound на 127.0.0.1, отдельным портом слота и fail-closed маршрутизацией.
	- Запускает, останавливает, меняет и массово запускает прокси-слоты.
	- Хранит состояние профиля, процесса, порта, внешнего IP, задержки, ошибок и поколения маршрута.
```

```component
name: ExternalProxyHealthMonitor
container: Electron Main Process
responsibilities:
	- Проверяет внешний IP и отдельный HTTPS-запрос через HTTP-прокси.
	- Разделяет состояние процесса и готовность data-plane.
	- Планирует проверки, применяет задержки после транспортных ошибок и отключает слот после четырёх последовательных сбоев.
```

```component
name: ExternalProxyControlApi
container: Electron Main Process
responsibilities:
	- Принимает локальные HTTP-запросы на 127.0.0.1:17873 или на выбранном свободном loopback-порту.
	- Требует X-VPNTE-Control-Token или Bearer-токен для чтения и изменения состояния.
	- Обслуживает статус, список профилей, запуск, подключение, смену профиля, проверки здоровья, аренду и остановку слотов.
```

```component
name: ExternalProxyCard
container: Electron Renderer Process
responsibilities:
	- Показывает доступные профили, запущенные слоты, адреса прокси, внешний IP, задержку и состояние здоровья.
	- Запускает выбранный профиль, меняет профиль, останавливает слот или все слоты.
	- Обновляет состояние по событиям приложения, фокусу и таймеру с более частым опросом нестабильных слотов.
```

### Сценарии командной строки

```component
name: VpnteProxyScripts
container: Windows PowerShell and Command Prompt
responsibilities:
	- Запускает приложение при недоступном API и вызывает локальные операции внешнего прокси.
	- Читает endpoint и управляющий токен из файлов приложения или переменных окружения.
	- Поддерживает текстовый и JSON-вывод для операций управления.
```

#ExternalProxyCard вызывает #ExternalProxyControlApi через preload IPC для получения списка профилей и статуса. Действия карточки передают выбранный `profileId` или номер слота, после чего состояние обновляется без перехода к системному VPN.

#ExternalProxyControlApi вызывает #ExternalProxyManager для операций над слотами. API нормализует параметры, проверяет метод и управляющий токен, а затем возвращает JSON или текстовое представление результата.

#ExternalProxyHealthMonitor передаёт результат проверки #ExternalProxyManager. Готовым считается только прокси с работающим процессом, готовым состоянием, свежим успешным внешним IP и отсутствием дубликата внешнего IP среди готовых слотов.

## System Contracts

### Key Contracts

* Каждый слот использует отдельный локальный порт. Порт слота 1 по умолчанию равен 17990, следующие слоты получают следующие порты.
* Внешний прокси слушает только `127.0.0.1`. Основной управляющий API по умолчанию использует порт 17873 и при занятом порте может перейти на свободный loopback-порт.
* Прокси не считается готовым только по живому дочернему процессу. Нужна свежая успешная проверка внешнего IP и HTTPS.
* Управляющий токен генерируется для текущего запуска и сохраняется в файле `external-proxy-control-token`; endpoint сохраняется в `external-proxy-control-endpoint.json`.
* Аренда выбирает свободный готовый слот со свежим уникальным внешним IP. Срок аренды по умолчанию составляет 120 секунд, максимальный срок равен одному часу. Аренды предыдущего процесса удаляются при запуске.
* Повторяющиеся транспортные ошибки используют интервалы 15, 30 и 60 секунд. После четырёх последовательных сбоев слот автоматически отключается.

### Integration Contracts

* `GET /status`, `GET /instances`, `GET /list` и `GET /healthcheck` возвращают состояние, экземпляры, профили или результат проверки; эти чтения также требуют управляющий токен.
* `POST /start`, `/rotate`, `/connect`, `/trigger`, `/stop`, `/healthcheck`, `/profiles/healthcheck`, `/connect-profiles`, `/instances/prewarm`, `/instances/status-batch`, `/instances/reserve`, `/instances/renew` и `/instances/release` изменяют или запускают операции внешнего прокси и требуют управляющий токен.
* API принимает параметры из query string и JSON-тела, поддерживает `format=text`, а неизвестные пути и методы возвращают ошибку без выполнения операции.
* Preload предоставляет renderer операции `externalProxyStatus`, `externalProxyStart`, `externalProxyStartProfiles`, `externalProxyStop`, `externalProxyStopAll`, `externalProxyList` и `externalProxyRotate`.
* `vpnte-proxy.ps1` и `vpnte-proxy.cmd` вызывают API. PowerShell проверяет, что управляющий URL является HTTP loopback-адресом; командный скрипт такой проверки не содержит.

## Architecture Decision Records

### ADR-001: Независимые loopback-прокси вместо системного TUN

**Context:** Пользователю нужен маршрут через конкретный сервер для отдельной программы или браузера без изменения системной маршрутизации.

**Decision:** Для каждого слота запускать отдельный процесс sing-box с mixed inbound на loopback-порту, outbound выбранного профиля и маршрутом по умолчанию `block-out`.

**Consequences:** Несколько профилей могут работать одновременно и не требуют системного TUN. Каждый процесс требует отдельного контроля жизненного цикла, проверки здоровья и разрешения в kill-switch.

### ADR-002: Готовность определяется data-plane проверкой

**Context:** Живой процесс не доказывает, что запросы действительно проходят через выбранный сервер.

**Decision:** Проверять внешний IP и отдельный HTTPS-запрос через адрес слота, хранить результат и отделять `processRunning` от `running` и `ready`.

**Consequences:** Клиенты получают проверяемый маршрут и диагностические данные. Доступность внешних сервисов проверки влияет на состояние здоровья.

### ADR-003: Токен для локального API

**Context:** Loopback API должен принимать команды только от локальных клиентов, которым приложение передало доступ.

**Decision:** Требовать токен текущего запуска для чтения и изменения состояния, принимать его в заголовке `X-VPNTE-Control-Token` или в Bearer-форме.

**Consequences:** Случайные локальные запросы не получают данные и не запускают операции. Защита Host от DNS rebinding и права файла токена остаются открытыми вопросами аудита.
