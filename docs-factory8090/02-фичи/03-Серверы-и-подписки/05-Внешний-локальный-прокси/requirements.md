# Внешний локальный прокси

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/requirements/1e33f9d4-698f-41bf-b969-7941486c0294

## Overview

Фича позволяет открыть для выбранного сервера отдельный локальный HTTP/SOCKS-прокси на компьютере пользователя. Отдельная программа или браузер может направить трафик через этот конкретный сервер, не включая системный TUN. Прокси слушает loopback-адрес, а приложение показывает его локальный адрес, выбранный сервер и состояние проверки.

Пользователь может запустить несколько независимых прокси-слотов, сменить сервер в слоте, остановить один или все слоты и проверить, что запросы действительно выходят через выбранный сервер. Для автоматизированного управления приложение предоставляет локальный API с токеном и скрипты командной строки. Система должна ограничивать доступ к локальному управлению и отключать прокси после повторяющихся сбоев проверки.

## Terminology

* **Внешний локальный прокси**: отдельный прокси-сервис приложения, через который другая программа направляет трафик через выбранный профиль сервера без системного TUN.
* **Профиль сервера**: сохранённая запись с данными VPN-сервера, определённая в родительской фиче «Серверы и подписки».
* **Прокси-слот**: независимый экземпляр внешнего локального прокси с собственным локальным портом, выбранным профилем и состоянием.
* **Управляющий API**: локальный HTTP-интерфейс приложения для просмотра состояния и выполнения операций над прокси-слотами.
* **Управляющий токен**: секрет текущего запуска приложения, который клиент передаёт управляющему API для просмотра состояния и изменения прокси.
* **Проверка работоспособности**: проверка выхода через прокси по внешнему IP и отдельному HTTPS-запросу.
* **Аренда слота**: временная эксклюзивная привязка готового прокси-слота к владельцу автоматизированного клиента.
* **Скрипты прокси**: поставляемые PowerShell- и командный скрипты для запуска приложения и обращения к управляющему API.

## Requirements

### REQ-SRV-XP-001: Запуск прокси для выбранного сервера

**User Story:** Как пользователь, я хочу запустить отдельный локальный прокси для выбранного профиля сервера, чтобы направить через него трафик конкретной программы без системного TUN.

**Acceptance Criteria:**

* **AC-SRV-XP-001.1:** Когда пользователь выбирает доступный профиль сервера и запускает внешний локальный прокси, система shall создать прокси-слот для этого профиля.
* **AC-SRV-XP-001.2:** Когда прокси-слот запущен, система shall предоставить локальный адрес прокси на loopback-интерфейсе.
* **AC-SRV-XP-001.3:** Когда пользователь запускает несколько прокси-слотов, система shall назначить им разные локальные порты.
* **AC-SRV-XP-001.4:** Если профиль выбран как активный профиль системного VPN или удалён из подписки, система shall не разрешать использовать его для нового внешнего прокси.
* **AC-SRV-XP-001.5:** Если запуск не выполнен, система shall сообщить об ошибке и не показывать слот как запущенный.

### REQ-SRV-XP-002: Управление слотами

**User Story:** Как пользователь, я хочу видеть и управлять запущенными прокси-слотами, чтобы использовать нужные серверы и освобождать ресурсы.

**Acceptance Criteria:**

* **AC-SRV-XP-002.1:** Когда пользователь открывает управление внешними прокси, система shall показывать запущенные слоты, выбранные профили и локальные адреса прокси.
* **AC-SRV-XP-002.2:** Когда пользователь останавливает слот, система shall прекратить работу соответствующего внешнего прокси.
* **AC-SRV-XP-002.3:** Когда пользователь выбирает смену профиля слота, система shall запустить этот слот с другим доступным профилем.
* **AC-SRV-XP-002.4:** Когда пользователь выбирает остановку всех прокси, система shall остановить все запущенные внешние прокси.
* **AC-SRV-XP-002.5:** Если слот остановлен или его процесс завершён, система shall показывать слот отдельно от работающих прокси и сохранять доступный результат диагностики, если он есть.

### REQ-SRV-XP-003: Проверка работоспособности и автоотключение

**User Story:** Как пользователь, я хочу видеть, работает ли внешний прокси через выбранный сервер, чтобы не направлять трафик через неисправный маршрут.

**Acceptance Criteria:**

* **AC-SRV-XP-003.1:** После запуска прокси система shall проверять внешний IP и выполнять отдельный HTTPS-запрос через адрес этого прокси.
* **AC-SRV-XP-003.2:** Когда обе проверки проходят, система shall показывать прокси как работоспособный и отображать внешний IP и задержку.
* **AC-SRV-XP-003.3:** Если проверка завершается ошибкой, система shall показывать состояние ошибки и причину последней ошибки.
* **AC-SRV-XP-003.4:** Когда прокси получает четыре последовательных сбоя проверки транспорта, система shall автоматически отключить этот слот.
* **AC-SRV-XP-003.5:** Пока прокси не прошёл свежую проверку работоспособности, система shall не считать его готовым для автоматической аренды.

### REQ-SRV-XP-004: Управляющий API

**User Story:** Как автоматизированный клиент, я хочу управлять локальными прокси через управляющий API, чтобы запускать, проверять, менять и останавливать слоты без действий в окне приложения.

**Acceptance Criteria:**

* **AC-SRV-XP-004.1:** Управляющий API shall принимать запросы только через loopback-интерфейс.
* **AC-SRV-XP-004.2:** Управляющий API shall требовать управляющий токен для выполнения операций над прокси-слотами.
* **AC-SRV-XP-004.3:** Управляющий API shall предоставлять операции просмотра состояния, просмотра списка профилей, запуска, смены профиля, подключения конкретного профиля, проверки работоспособности, проверки группы профилей и остановки прокси.
* **AC-SRV-XP-004.4:** Когда клиент вызывает неподдерживаемый метод или путь, управляющий API shall вернуть ошибку без изменения состояния прокси.
* **AC-SRV-XP-004.5:** Если управляющий API не может занять основной локальный порт, система shall выбрать свободный loopback-порт и сохранить фактический адрес для локальных клиентов.

### REQ-SRV-XP-005: Скрипты прокси

**User Story:** Как пользователь или автоматизированный клиент, я хочу использовать поставляемые скрипты прокси, чтобы управлять внешним прокси из командной строки.

**Acceptance Criteria:**

* **AC-SRV-XP-005.1:** Скрипты прокси shall поддерживать запуск, смену профиля, подключение профиля, проверку состояния, получение списка профилей, проверку здоровья группы и остановку прокси.
* **AC-SRV-XP-005.2:** Когда скрипт обращается к управляющей операции, он shall передавать управляющий токен.
* **AC-SRV-XP-005.3:** Когда приложение не запущено, скрипт shall попытаться запустить упакованное приложение и сообщить об ошибке, если API остаётся недоступным.
* **AC-SRV-XP-005.4:** Скрипт PowerShell shall отклонять управляющий URL, который не является HTTP-адресом loopback.

### REQ-SRV-XP-006: Временная аренда готового слота

**User Story:** Как автоматизированный клиент, я хочу временно арендовать готовый прокси-слот, чтобы использовать уникальный маршрут и освободить его после завершения работы.

**Acceptance Criteria:**

* **AC-SRV-XP-006.1:** Когда клиент запрашивает аренду, система shall выбрать свободный слот с успешной свежей проверкой и уникальным внешним IP.
* **AC-SRV-XP-006.2:** Когда клиент уже имеет активную аренду, система shall отклонить новую аренду для этого владельца.
* **AC-SRV-XP-006.3:** Когда срок аренды истекает, система shall освободить слот автоматически.
* **AC-SRV-XP-006.4:** Когда клиент продлевает или освобождает аренду по её токену, система shall изменить или удалить соответствующую аренду.
* **AC-SRV-XP-006.5:** После перезапуска приложения система shall удалить аренды, которые были сохранены от предыдущего процесса, вместо блокировки слотов.

* Как согласовать документацию управляющего API и фактическую аутентификацию чтения `/status` и `/list`, включая новые пути `/instances/*` и `/connect-profiles`? Журнал аудита фиксирует это как F-115.
* Нужно ли добавить проверку заголовка `Host` для защиты управляющего API от DNS rebinding? Журнал аудита фиксирует это как F-006.
* Нужно ли исключить прямой bootstrap DNS для endpoint VPN, который может обходить внешний прокси? Журнал аудита фиксирует это как F-114.
