# Экспорт ключей

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/25355e71-7ad9-4053-98e1-da2b37127b1c

## Feature Summary

Фича компонует возможности страницы `Servers`, preload IPC и основного процесса Electron для переноса сохранённых профилей VPN. Она выполняет экспорт поддерживаемого профиля в URI, копирует один URI в буфер обмена, сохраняет один URI в текстовый файл или записывает поддерживаемые URI всех профилей в один файл. Полная конфигурация приложения в этот поток не входит.

## Component Blueprint Composition

* **Страница Servers** — использует действия строки профиля для индивидуального экспорта и отдельные действия для группового экспорта. Страница показывает подтверждение успеха, отмены или ошибки без отображения экспортируемого URI в собственной разметке.
* **Preload bridge Electron** — предоставляет renderer методы `serversExportKey`, `serversExportKeyToFile` и `serversExportAllKeysToFile`, которые вызывают IPC-каналы экспорта.
* **@Серверы и подписки** — предоставляет сохранённые профили серверов. Экспорт использует профиль как источник имени, протокола и `outbound`.

## Feature-Specific Components

### Renderer

```component
name: ServersExportActions
container: Client App
responsibilities:
	- Запрашивает индивидуальный экспорт профиля через `serversExportKey`.
	- Записывает возвращённый URI в системный буфер обмена.
	- Запрашивает сохранение индивидуального URI через `serversExportKeyToFile`.
	- Запрашивает групповой экспорт через `serversExportAllKeysToFile` и показывает количество экспортированных и пропущенных профилей.
```

### Main Process

```component
name: ServerKeyExportHandlers
container: Main Process
responsibilities:
	- Находит профиль по идентификатору и преобразует его `outbound` в URI через существующий экспортный преобразователь.
	- Возвращает индивидуальный URI renderer-процессу, если профиль существует и его протокол представим одной строкой.
	- Открывает системный диалог сохранения и записывает индивидуальный URI одной строкой в текстовый файл.
	- Собирает поддерживаемые URI всех профилей, записывает их по одному на строку и возвращает количество пропущенных профилей.
	- Возвращает причины отсутствия профиля, данных outbound, поддерживаемого URI или записи файла.
```

`ServersExportActions` вызывает `ServerKeyExportHandlers` через IPC. Для копирования полный URI проходит через IPC в renderer, после чего renderer передаёт его системному буферу обмена. Это подтверждено текущим кодом и является предметом открытого вопроса по защите секрета.

## System Contracts

### Key Contracts

* `servers:export-key` возвращает успешный результат с URI только для существующего профиля с объектом `outbound`, который поддерживает преобразование в одну строку.
* `servers:export-key-file` сохраняет только URI профиля и возвращает отмену отдельно от ошибки записи.
* `servers:export-all-keys-file` экспортирует по одному URI на строку, пропускает профили без поддерживаемого URI и возвращает счётчики `total`, `exported` и `skipped`.
* Пустой набор профилей и набор, в котором нет ни одного поддерживаемого URI, являются отдельными неуспешными результатами группового экспорта.
* Экспорт ключей не вызывает сбор и запись полной конфигурации приложения.

### Integration Contracts

* `Servers.tsx` вызывает `window.electronAPI.serversExportKey(id)` и передаёт успешное поле `uri` в `navigator.clipboard.writeText`.
* `Servers.tsx` вызывает `window.electronAPI.serversExportKeyToFile(id)` для индивидуального файла и `window.electronAPI.serversExportAllKeysToFile()` для группового файла.
* `preload/index.ts` публикует эти методы через IPC-каналы `servers:export-key`, `servers:export-key-file` и `servers:export-all-keys-file`.
* Файл индивидуального экспорта содержит URI и завершающий перевод строки. Файл группового экспорта содержит служебный заголовок и экспортируемые URI по одному на строку.

## Architecture Decision Records

### ADR-001: Экспорт только переносимых URI

**Context:** Профили могут содержать outbound, который нельзя представить одной строкой URI. Код также содержит отдельную подсистему полной конфигурации приложения.

**Decision:** Экспорт ключей ограничивается URI-представлениями профилей. Непредставимые профили пропускаются в групповом экспорте и возвращают ошибку в индивидуальном экспорте. Полная конфигурация остаётся отдельной фичей.

**Consequences:** Поддерживаемые клиенты получают компактные переносимые ключи. Профили в пользовательском формате JSON не переносятся этим потоком и требуют отдельного решения.

### ADR-002: Текущий IPC-поток передаёт URI в renderer

**Context:** `servers:export-key` возвращает полный URI в renderer, где он записывается в буфер обмена. Документация проекта заявляет, что секреты не попадают в UI, а находка F-140 указывает на это расхождение.

**Decision:** В blueprint фиксируется наблюдаемое поведение без выбора целевой политики маскировки или подтверждения.

**Consequences:** Реализация соответствует текущему коду, но решение о допустимости полного URI в renderer остаётся открытым и требует отдельного решения безопасности.
