# Серверы и подписки

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/48edfb35-6624-4367-b392-ef927b7f877d

## Feature Summary

Фича объединяет страницу Servers и два быстрых элемента выбора на Dashboard вокруг единого набора профилей серверов. Она показывает сохранённые профили, сохраняет активный профиль, переключает сервер с последующим обновлением прямого VPN-туннеля и исключает профили, удалённые из подписки, из доступного выбора.

Реализация состоит из React-компонентов `Servers`, `ProfileSelectorInline` и быстрого списка серверов в `DashboardSide`, а также main-компонентов `serverPicker`, `serverGroups` и парсеров профилей `vpnProfiles`. Данные профилей и групп хранятся в локальных экземплярах `electron-store`.

## Component Blueprint Composition

* Дочерние фичи «Импорт ключей», «Подписки и группы», «Проверка серверов», «Экспорт ключей» и «Внешний локальный прокси» поставляют или используют профили через общий поток `serverPicker`; их внутреннее устройство в этом Blueprint не описывается.
* `serverPicker` управляет списком профилей, активным идентификатором, IPC-операциями списка и выбора, а также переключением прямого VPN при выборе профиля.
* `serverGroups` хранит происхождение профилей, связывает профили с подписками и помечает отсутствующие в успешном обновлении профили как удалённые из подписки.

## Feature-Specific Components

### Пользовательские поверхности

```component
name: Servers
container: Electron Renderer
responsibilities:
	- Отображает доступные и удалённые из подписки профили серверов на странице Servers.
	- Даёт пользователю выбрать доступный профиль и удалить сохранённый профиль.
	- Показывает активный профиль и состояние профилей, полученное через IPC.
```

```component
name: ProfileSelectorInline
container: Electron Renderer
responsibilities:
	- Показывает компактный список профилей на Dashboard.
	- Выбирает доступный профиль через `servers:select` и обновляет состояние после события смены сервера.
```

```component
name: DashboardSide
container: Electron Renderer
responsibilities:
	- Показывает быстрый список серверов в боковой части Dashboard.
	- Периодически обновляет список и отражает активный профиль.
	- Не позволяет выбрать профиль, удалённый из подписки.
```

### Main-процесс

```component
name: ServerPicker
container: Electron Main
responsibilities:
	- Хранит профили и идентификатор активного профиля в `server-picker`.
	- Обслуживает IPC-операции `servers:list`, `servers:select`, `servers:get-active` и операции проверки доступности.
	- При выборе профиля выполняет защищённое переключение прямого VPN-туннеля, если туннель уже работает.
```

```component
name: ServerGroups
container: Electron Main
responsibilities:
	- Хранит группы профилей в `server-groups`.
	- Сохраняет происхождение профилей и архивирует профили, отсутствующие в успешном ответе подписки.
	- Оставляет прежний набор профилей при пустом или неуспешном обновлении подписки.
```

```component
name: VpnProfiles
container: Electron Main
responsibilities:
	- Преобразует входные VPN URI и ответы подписок в профили с outbound-конфигурацией.
	- Сохраняет исходный URI профиля, если он доступен после разбора.
```

`Servers`, `ProfileSelectorInline` и `DashboardSide` читают единый список через IPC `servers:list` и активный профиль через `servers:get-active`. Выбор из любой поверхности вызывает `servers:select`; renderer уведомляет остальные поверхности событием смены сервера, поэтому они обновляют один источник состояния.

`ServerGroups` обновляет профили, связанные с группой подписки, через общий store профилей. Профили, отсутствующие в успешном непустом ответе, остаются в массиве с признаком удаления и отключаются для выбора, чтобы UI мог показать их отдельно без использования в подключении.

## System Contracts

### Key Contracts

* `ServerPicker` сохраняет профиль и `activeProfileId` в локальном `server-picker` store; `ServerGroups` сохраняет группы в локальном `server-groups` store.
* `servers:select` принимает только существующий, включённый и не удалённый из подписки профиль.
* Если сохранённый активный идентификатор не указывает на доступный профиль, `getActiveProfile` выбирает первый доступный профиль или возвращает отсутствие профиля при пустом списке.
* Успешный непустой refresh группы является источником истины для состава группы. Отсутствующие профили архивируются, отключаются и сохраняются для отдельного отображения.
* Ошибка или пустой результат обновления подписки не должен превращать текущие профили в удалённые.
* В текущей реализации чувствительные поля профиля, включая `outbound` и `sourceUri`, записываются в `electron-store` открытым текстом. Требование о защите сохранённых ключей остаётся нерешённым до выбора политики хранения.

### Integration Contracts

* Renderer вызывает IPC-каналы `servers:list`, `servers:select`, `servers:get-active`, `servers:ping-all`, `servers:resolve-ips` и `servers:ping-one`.
* `servers:get-active` возвращает активный `profile` и `activeId`; при отсутствии доступных профилей `profile` отсутствует.
* Renderer публикует событие смены сервера после успешного выбора, а `ProfileSelectorInline` и `DashboardSide` используют его для обновления локального списка.
* `ServerProfile` содержит идентификатор, имя, протокол, endpoint-поля и outbound-конфигурацию; `ServerGroup` связывает профили с источником, включая подписку, и хранит статус группы.

## Architecture Decision Records

### ADR-001: Единый источник профилей для выбора сервера

**Context:** Страница Servers и быстрые селекторы Dashboard должны показывать один активный профиль и не расходиться после выбора в другом месте.

**Decision:** Использовать `serverPicker` и его локальный store как общий источник списка и активного идентификатора, а renderer-компонентам обновляться через IPC и событие смены сервера.

**Consequences:** Выбор сервера синхронизирован между поверхностями. Изменения профилей должны проходить через общий поток записи, иначе независимые read-modify-write операции могут затереть друг друга.

### ADR-002: Сохранять удалённые из подписки профили отдельно от актуальных

**Context:** Успешное обновление подписки может больше не содержать ранее сохранённый профиль, но пользователю нужен контекст этого изменения.

**Decision:** Оставлять профиль в хранилище с признаком `removedFromSubscriptionAt`, сохранять его исходное состояние включения и отключать для выбора.

**Consequences:** UI может показать архивные записи отдельно, а активное подключение не использует профиль, которого больше нет в актуальном наборе подписки.
