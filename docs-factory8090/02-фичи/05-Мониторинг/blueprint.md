# Мониторинг

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/922a4ecc-77bc-49b3-a290-b7978a878172

## Feature Summary

Функция реализует требования @Мониторинг и показывает состояние соединения во время включённой защиты. Техническая реализация разделена между главным процессом Electron, который собирает и сохраняет сетевые данные, и renderer-представлениями, которые показывают текущие показатели, историю и результаты измерений.

## Component Blueprint Composition

Функция использует следующие наблюдаемые подсистемы и представления:

* `ipMonitor` получает публичный IP через несколько HTTPS-провайдеров и сравнивает его с сохранённой VPN-базой для определения признака утечки. `trafficMonitor` читает статистику VPN-адаптера в Windows и публикует текущие скорости, объёмы и сглаженные значения.
* `trafficConnections` периодически запрашивает локальный Clash API sing-box на `127.0.0.1`, отбрасывает инфраструктурные домены и сохраняет агрегаты доменов и байтов. `trafficHistory` объединяет эти данные с разбором текущего и предыдущего логов sing-box.
* `connectionHistory` хранит локальные записи сеансов подключения, поддерживает фильтрацию, агрегацию и экспорт в CSV и JSON.
* `urlAvailability` выполняет сетевые проверки HTTP(S) через native-путь и, при активном VPN, через direct-out Clash API. `geoBlockDetect` сравнивает сигналы страниц для оценки региональной блокировки.
* `speedTest` выполняет измерения задержки, загрузки и отправки через внешние тестовые endpoints, сообщает прогресс renderer и сохраняет результаты локально.
* `Dashboard`, `BrowserIpCard`, `TrafficHistory`, `Availability`, `SpeedTest` и `Logs` предоставляют renderer-представления для текущих показателей, браузерного IP/WebRTC, истории, проверок, теста скорости и журналов. `ServerDetailModal` также выполняет geo-IP lookup для отображаемого сервера.

## Feature-Specific Components

### Главный процесс

```component
name: IpMonitor
container: Electron main process
responsibilities:
	- Получает публичный IP через IP_CHECK_URLS с параллельным резервированием провайдеров.
	- Сравнивает текущий IP с VPN-базой и уведомляет подписчиков об изменении и признаке утечки.
	- Приостанавливает публикацию результата во время защищённого перехода остановки или смены профиля.
```

```component
name: TrafficMonitor
container: Electron main process
responsibilities:
	- Читает статистику VPN-адаптера через длительно работающий PowerShell reader.
	- Публикует текущие входящие и исходящие скорости, объёмы, пики и показатели burstiness.
	- Возобновляет reader после неожиданного завершения с задержкой.
```

```component
name: TrafficConnectionsSampler
container: Electron main process
responsibilities:
	- Опросит локальный Clash API `/connections` с bearer-секретом.
	- Нормализует и фильтрует домены, исключая IP-литералы, локальные имена, DoH-инфраструктуру и хосты VPN-серверов.
	- Накопительно сохраняет количество соединений и байты по доменам в локальном electron-store.
```

```component
name: TrafficHistoryService
container: Electron main process
responsibilities:
	- Разбирает текущий и предыдущий логи sing-box и объединяет домены с данными TrafficConnectionsSampler.
	- Хранит данные истории локально и предоставляет IPC для чтения и очистки.
	- Запускает фоновое обогащение доменов, когда оно включено настройками.
```

```component
name: ConnectionHistoryService
container: Electron main process
responsibilities:
	- Хранит локальные записи сеансов подключения с ограничением количества записей.
	- Фильтрует записи, агрегирует время и байты за день, неделю или месяц.
	- Экспортирует историю в CSV и JSON через IPC.
```

```component
name: UrlAvailabilityService
container: Electron main process
responsibilities:
	- Нормализует HTTP(S)-адрес и выполняет проверки DNS, TCP, TLS и HTTP.
	- При активном VPN запрашивает direct-out через локальный Clash API для сравнения с туннельным путём.
	- Возвращает результат доступности, этап ошибки и итоговый verdict.
```

```component
name: GeoBlockDetector
container: Electron main process
responsibilities:
	- Оценивает признаки геоблокировки по HTTP-статусу, конечному URL, заголовку и короткому тексту страницы.
	- Сравнивает внешний и локальный рендер страницы для дифференциального вывода.
```

```component
name: SpeedTestService
container: Electron main process
responsibilities:
	- Измеряет задержку, загрузку и отправку через набор внешних endpoints с резервными вариантами.
	- Передаёт фазы и процент прогресса в renderer через IPC.
	- Проверяет наличие активного VPN до запуска и сохраняет результаты локально.
```

### Renderer

```component
name: MonitoringViews
container: Electron renderer process
responsibilities:
	- Показывает состояние публичного IP, сравнение main-процесса и браузера, IPv6 и WebRTC-кандидатов.
	- Показывает текущий трафик, историю доменов и подключений, результаты доступности и тестов скорости.
	- Отображает состояния загрузки, ошибки и недоступность измерений без подстановки неподтверждённых значений.
```

`MonitoringViews` получает данные через IPC, зарегистрированные в `main/index.ts` и сервисах мониторинга. `IpMonitor`, `TrafficMonitor`, `TrafficHistoryService`, `ConnectionHistoryService`, `UrlAvailabilityService` и `SpeedTestService` остаются владельцами состояния и локального хранения, а renderer отвечает за отображение и запуск пользовательских проверок.

## System Contracts

### Key Contracts

* Данные истории трафика, доменов, подключений и тестов скорости сохраняются локально в electron-store или локальных файлах приложения.
* `IpMonitor` не публикует новое решение об утечке, пока мониторинг приостановлен во время защищённого перехода.
* `TrafficConnectionsSampler` обращается только к loopback Clash API с bearer-секретом и не направляет этот запрос через системный или заданный proxy.
* Сетевое измерение должно сообщать ошибку или состояние недоступности, если обязательный этап не завершён.
* Передача IP внешним сервисам определения IP и ASN зависит от решения по открытым вопросам приватности. Текущая реализация использует `ipapi.co` и `ipwho.is` в отдельных путях приложения, включая `ServerDetailModal`.

### Integration Contracts

* Главный процесс публикует изменения IP, статистику трафика и события прогресса теста скорости в renderer через IPC.
* `trafficConnections` потребляет локальный endpoint Clash API `/connections` и поля `metadata.host`, `metadata.sniffHost`, `upload` и `download`.
* `urlAvailability` потребляет локальный endpoint Clash API `/proxies/direct-out/delay` для direct-сравнения при активном VPN.
* Внешние HTTP(S)-границы включают провайдеры публичного IP, `ipapi.co` и `ipwho.is` для geo-IP/ASN, а также endpoints задержки, загрузки и отправки теста скорости.
* Планируемый процессный монитор трафика остаётся отдельной дочерней фичей и не получает здесь технической реализации.

## Architecture Decision Records

### ADR-001: Локальное хранение наблюдений

**Context:** Мониторинг должен сохранять историю трафика, доменов, подключений и тестов скорости, а пользовательские данные не должны уходить во внешние сервисы без необходимости измерения.

**Decision:** Сохранять историю в локальном хранилище Electron и передавать наружу только запросы, требуемые конкретным измерением или определением IP/ASN.

**Consequences:** История доступна после перезапуска приложения, но правила приватности для внешних geo-IP запросов требуют отдельного решения.

### ADR-002: Резервные внешние источники публичного IP

**Context:** Один провайдер публичного IP может быть недоступен или ограничен по частоте запросов.

**Decision:** Использовать несколько HTTPS-провайдеров публичного IP и принимать первый корректный ответ.

**Consequences:** Повышается вероятность получить актуальный IP, но запросы к нескольким провайдерам раскрывают внешний сетевой факт и требуют контроля частоты и приватности.
