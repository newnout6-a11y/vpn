# Процессный монитор трафика (план)

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/requirements/b8734d33-d1bc-434d-8256-3da167b99af0

## Обзор

Статус: **план**. Функция должна постоянно наблюдать сетевую активность по процессам во время работы VPN и показывать, какое приложение передаёт данные, с какими направлениями оно взаимодействует и какой объём трафика создаёт. Она нужна для пользовательского контроля трафика и для понимания того, какое приложение инициировало сетевое соединение.

Функция расширяет общий «Мониторинг», но не заменяет «Форензику трафика». В текущей реализации ETW-сайдкар существует для форензики по запросу и сбора диагностических материалов. Постоянный процессный мониторинг, связывание событий DNS и сетевых соединений с процессами и показ объединённых данных в интерфейсе остаются планом.

## Терминология

* **Процессный монитор трафика**: планируемая функция постоянного наблюдения за сетевой активностью с группировкой данных по процессам.
* **Процесс**: запущенное приложение или служба, которая инициирует сетевую активность.
* **Идентификатор процесса (PID)**: системный идентификатор, по которому сетевое событие связывается с процессом.
* **Имя процесса**: имя исполняемого файла, сопоставленное с PID.
* **Сетевое событие**: наблюдаемое событие установки или использования TCP/UDP-соединения, включая направление и доступные адреса.
* **DNS-событие**: наблюдаемый запрос или результат разрешения доменного имени.
* **Объединённый поток**: результат сопоставления DNS-событий и сетевых событий с одним процессом и направлением трафика.
* **Направление трафика**: удалённый адрес или домен, с которым взаимодействует процесс.
* **Форензика трафика**: отдельная функция сбора диагностических артефактов по запросу для анализа утечек, блокировок, DNS и сетевых отказов.
* **ETW-сайдкар**: отдельный компонент Windows для получения нормализованных событий ETW и записи диагностических артефактов в рамках форензики трафика.

## Требования

### REQ-MON-PROC-001: Статус и область процессного наблюдения

**История пользователя:** Как пользователь VPN, я хочу видеть статус процессного мониторинга, чтобы понимать, доступна ли постоянная атрибуция трафика к приложениям.

**Критерии приёмки:**

* **AC-MON-PROC-001.1:** Пока функция не реализована, продукт должен явно обозначать процессный монитор трафика как планируемую возможность.
* **AC-MON-PROC-001.2:** Описание процессного монитора должно отличать постоянное наблюдение от форензики трафика, которая запускается по запросу для диагностического сбора.
* **AC-MON-PROC-001.3:** Процессный монитор не должен представляться доступным только потому, что ETW-сайдкар доступен для форензики трафика.

### REQ-MON-PROC-002: Наблюдение трафика по процессам

**История пользователя:** Как пользователь VPN, я хочу видеть сетевую активность по процессам, чтобы понимать, какое приложение передаёт данные.

**Критерии приёмки:**

* **AC-MON-PROC-002.1:** После реализации монитор должен связывать доступные сетевые события с PID процесса.
* **AC-MON-PROC-002.2:** После реализации монитор должен показывать имя процесса для сетевого события, если имя можно надёжно получить по PID.
* **AC-MON-PROC-002.3:** Если PID или имя процесса нельзя сопоставить, монитор должен явно показывать отсутствие атрибуции вместо вымышленного имени.
* **AC-MON-PROC-002.4:** Монитор должен различать как минимум TCP- и UDP-события, если соответствующие сведения доступны источнику событий.

### REQ-MON-PROC-003: Направления и объём трафика

**История пользователя:** Как пользователь VPN, я хочу видеть направления и объём трафика каждого процесса, чтобы оценивать его сетевую активность.

**Критерии приёмки:**

* **AC-MON-PROC-003.1:** После реализации монитор должен показывать доступное направление трафика для каждого процесса.
* **AC-MON-PROC-003.2:** После реализации монитор должен агрегировать наблюдаемые данные по процессу.
* **AC-MON-PROC-003.3:** Если домен нельзя получить из DNS-события, монитор должен сохранять доступный IP-адрес или явно указывать, что домен неизвестен.
* **AC-MON-PROC-003.4:** При отсутствии данных монитор должен показывать состояние недоступности или неполной атрибуции, а не нулевой объём как подтверждённый результат.

### REQ-MON-PROC-004: Сопоставление DNS и сетевых событий

**История пользователя:** Как пользователь VPN, я хочу видеть домен рядом с процессом и соединением, чтобы понимать, куда приложение обращается.

**Критерии приёмки:**

* **AC-MON-PROC-004.1:** После реализации монитор должен сопоставлять DNS-события с сетевыми событиями по доступным признакам времени, адреса и соединения.
* **AC-MON-PROC-004.2:** Если сопоставление неоднозначно или невозможно, монитор не должен приписывать процессу неподтверждённый домен.
* **AC-MON-PROC-004.3:** Монитор должен сохранять различие между подтверждённым доменом, известным IP-адресом и отсутствующим результатом сопоставления.

### REQ-MON-PROC-005: Постоянная работа и границы сбора

**История пользователя:** Как пользователь VPN, я хочу, чтобы процессный монитор работал во время активной защиты без сбора содержимого пакетов, чтобы получать полезную статистику с ограниченным риском для приватности.

**Критерии приёмки:**

* **AC-MON-PROC-005.1:** После реализации монитор должен собирать метаданные сетевой активности без необходимости сохранять содержимое пакетов для базового режима.
* **AC-MON-PROC-005.2:** После реализации монитор должен работать постоянно в пределах выбранного жизненного цикла VPN-сессии или другого явно определённого режима.
* **AC-MON-PROC-005.3:** Монитор должен ограничивать рост накопленных данных и поддерживать определённую политику агрегации, ротации или хранения.
* **AC-MON-PROC-005.4:** При остановке или недоступности источника событий монитор должен сообщить о неполном наблюдении и не выдавать данные как полные.
