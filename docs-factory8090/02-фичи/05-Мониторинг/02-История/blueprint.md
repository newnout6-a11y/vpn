# История трафика и подключений

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/e4fa272a-9664-431f-a9bc-a628e0105fca

## Feature Summary

Функция реализует локальный просмотр истории доменов и сеансов VPN-защиты, включая время наблюдения, объём данных, профиль, длительность и итог сеанса. Она покрывает REQ-MON-HIST-001–REQ-MON-HIST-006 через main-process сервисы Electron и renderer-представление истории трафика.

## Component Blueprint Composition

Компонентные Blueprints для этой функции в переданных материалах не определены. Функция напрямую соединяет локальное хранилище `electron-store`, журналы sing-box, сэмплер соединений Clash API и IPC-границу Electron.

## Feature-Specific Components

### История трафика

```component
name: TrafficHistoryService
container: Electron main process
responsibilities:
	- Разбирать текущий и предыдущий sing-box журнал, начиная с ограниченного хвоста файла и затем читая только добавленные данные.
	- Объединять доменные записи из `sing-box.log`, `sing-box.prev.log` и сохранённых записей сэмплера соединений.
	- Сохранять время первого и последнего наблюдения, число наблюдений, публичный VPN IP и доступные `bytesUp` и `bytesDown`.
	- Удалять журналы истории, записи сэмплера и обогащение по команде очистки.
	- Предоставлять IPC операции `traffic-history:list` и `traffic-history:clear`.
```

### Представление истории трафика

```component
name: TrafficHistoryPage
container: Electron renderer process
responsibilities:
	- Загружать историю через `trafficHistoryList` при открытии страницы и при активной защите с интервалом 15 секунд.
	- Искать по домену без учёта регистра и отображать пустое состояние при отсутствии записей или результатов.
	- Показывать последние 300 отображаемых записей, группировать их по локальной календарной дате и показывать доступные объёмы данных и VPN IP.
	- Запускать очистку через `trafficHistoryClear` и оставлять последний список при фоновой ошибке чтения.
```

### История подключений

```component
name: ConnectionHistoryService
container: Electron main process
responsibilities:
	- Хранить записи `ConnectionLogEntry` в `electron-store` с ограничением 1000 записей.
	- Добавлять записи сеансов и удалять самые старые записи при превышении лимита.
	- Фильтровать записи по причине завершения, диапазону времени начала и тексту в профиле, режиме, причине, сообщении ошибки или итоге.
	- Рассчитывать статистику за последние 24 часа, 7 дней или 30 дней, включая время завершённых сеансов и весь доступный трафик.
	- Исключать попытки с итогом `start-failed` из числа подключений в статистике.
	- Экспортировать записи в CSV и JSON и предоставлять IPC операции `connection-history:list`, `connection-history:add`, `connection-history:filter`, `connection-history:stats`, `connection-history:export-csv`, `connection-history:export-json` и `connection-history:clear`.
```

### Итог сеанса

```component
name: SessionOutcome
container: Electron main process, Electron renderer process
responsibilities:
	- Преобразовывать `SessionOutcomeKind` в совместимую категорию `disconnectReason`.
	- Формировать русское однострочное сообщение по типу итога и доступным `SessionOutcomeEvidence`.
	- Сохранять структурированный тип итога и дополнительные сведения, включая код завершения sing-box, сетевой переход, неисправность внешнего узла и число авто-перезапусков.
```

`TrafficHistoryPage` вызывает #TrafficHistoryService через IPC. #TrafficHistoryService получает домены из журнала sing-box и #ConnectionHistoryService, затем объединяет их по домену, чтобы источник сэмплера имел приоритет по счётчикам и байтам, а журнал расширял временной диапазон.

#ConnectionHistoryService получает записи сеансов от main process при запуске, остановке, смене сервера и ошибках туннеля. Он использует `SessionOutcome` для формирования локализованного итога и сохраняет запись в `electron-store`.

## System Contracts

### Key Contracts

* Локальная история не требует удалённого журнала.
* #TrafficHistoryService читает не более 1 MiB за один первичный хвост журнала и кэширует смещение успешно обработанного файла.
* #TrafficHistoryService ограничивает отображение 300 записями, но поиск выполняется по полному результату чтения.
* #ConnectionHistoryService хранит не более 1000 последних записей; при добавлении новой записи удаляются самые старые.
* Статистика использует окна 24 часа, 7 дней и 30 дней относительно текущего времени.
* Незавершённые записи не добавляют длительность в общую сумму. Записи с итогом `start-failed` исключаются из числа подключений статистики.
* Ошибка фонового чтения истории трафика не должна заменять последний успешно загруженный список.
* Текущая реализация разбирает timestamp журнала после добавления `Z` и отбрасывает исходное смещение `+0300`. Это подтверждённое расхождение F-081 и открытый вопрос требований.
* Возрастной срок хранения истории трафика в коде не подтверждён. Подтверждён только лимит 1000 записей истории подключений.

### Integration Contracts

* `traffic-history:list` возвращает список `TrafficHistoryEntry`; аргументы могут передавать VPN IP и признак постановки обогащения в очередь.
* `traffic-history:clear` очищает историю трафика и возвращает результат успеха.
* `connection-history:list` возвращает сохранённые `ConnectionLogEntry`.
* `connection-history:add` принимает запись без `id`, добавляет UUID и возвращает созданную запись.
* `connection-history:filter` принимает `ConnectionHistoryFilters` с AND-логикой активных условий.
* `connection-history:stats` принимает период `day`, `week` или `month`.
* `connection-history:export-csv` возвращает CSV с полями записи и итога. `connection-history:export-json` возвращает JSON исходных записей.
* `connection-history:clear` удаляет все сохранённые записи подключений.
* Событие `traffic-history:enrichment-updated` уведомляет renderer об обновлении метаданных доменов.

## Architecture Decision Records

### ADR-001: Локальное хранилище с ограничением истории подключений

**Context:** История должна быть доступна после перезапуска и не должна расти без ограничений. Код хранит историю подключений в `electron-store` и задаёт предел 1000 записей.

**Decision:** Сохранять записи подключений локально и при добавлении новой записи удалять самые старые записи после достижения лимита 1000.

**Consequences:** История переживает перезапуск, размер набора ограничен, но записи старше лимита недоступны. Отдельный возрастной срок хранения трафика остаётся нерешённым.

### ADR-002: Комбинация сэмплера и журнала sing-box для истории трафика

**Context:** Сэмплер содержит реальные домены и байты, а журнал sing-box позволяет восстановить короткие потоки, которые сэмплер не успел зафиксировать.

**Decision:** Использовать сохранённые записи сэмплера как основной источник домена и байтов, а записи текущего и предыдущего журнала использовать для расширения временного диапазона и восстановления пропущенных доменов.

**Consequences:** История содержит больше наблюдений и доступные байты, но её полнота зависит от ротации журналов и работы сэмплера.

### ADR-003: Отдельное представление доменной истории

**Context:** Переданный renderer-код содержит страницу `TrafficHistory`, но отдельная страница списка истории подключений в доступных материалах не подтверждена.

**Decision:** Документировать подтверждённые IPC операции истории подключений отдельно от подтверждённой страницы истории трафика. Не считать наличие UI истории подключений установленным фактом.

**Consequences:** Main process API и требования готовы к пользовательскому представлению, но его конкретная поверхность остаётся открытым вопросом.
