# Проверка доступности сайтов

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/c23b7557-50a1-4d09-a586-27adacca2be5

## Feature Summary

Функция реализована в Windows-приложении на Electron 42. Она принимает адрес сайта или HTTP(S)-URL и через IPC запускает проверку доступности. При активном туннеле выполняются параллельные измерения через TUN и через direct-out sing-box без отключения VPN; при выключенном туннеле выполняется только нативное прямое измерение. Результат содержит вердикт, рекомендацию, время и доступную детализацию DNS, TCP, TLS, HTTP и ASN.

Соответствует требованиям @Проверка доступности сайтов. Renderer-компонент `Availability` показывает ввод, состояние выполнения, результат, две карточки путей и последние проверки. Main-компонент `UrlAvailability` нормализует адрес, выполняет измерения, применяет анализ региональной блокировки по сигналам отрендеренной страницы и сохраняет историю.

## Component Blueprint Composition

* Общая интеграция приложения через Electron IPC предоставляет канал проверки, чтения истории и очистки истории. Renderer вызывает эти операции через preload API `urlAvailabilityCheck`, `urlAvailabilityHistory` и `urlAvailabilityClearHistory`.
* `tunController` предоставляет состояние VPN, порт direct-out и сведения о Clash API. `UrlAvailability` использует состояние туннеля для выбора одного или двух путей и получает прямую оценку через endpoint `/proxies/direct-out/delay`.
* `geoBlockDetect` предоставляет сигналы отрендеренной страницы и сравнение результатов. `UrlAvailability` использует эти данные для отметки региональной блокировки и пересчёта вердикта.
* `settingsStore` передаёт в проверку флаг `disableGeoLookup`; при его включении ASN не запрашивается.

## Feature-Specific Components

### Renderer

```component
name: Availability
container: Electron Renderer
responsibilities:
	- Отображает ввод адреса, кнопку проверки, состояние выполнения и ошибку ввода или проверки.
	- Показывает итоговый `UrlAvailabilityResult`, рекомендацию и отдельные `PathReport` для VPN и прямого пути.
	- Показывает этапы DNS, TCP, TLS и HTTP, время в миллисекундах, ASN, региональную блокировку и оценочный источник direct-out, если эти данные присутствуют.
	- Загружает историю при открытии, показывает последние записи, выбирает запись для просмотра и очищает историю.
	- Запускает отдельную проверку маршрутизации только при активном VPN и показывает её IP и вердикт.
```

### Main

```component
name: UrlAvailability
container: Electron Main
responsibilities:
	- Разбирает вход в `ParsedUrl`, принимает HTTP(S) и добавляет HTTPS для адреса без схемы.
	- Выполняет `probeNative` с DNS, TCP, TLS и HTTP этапами, включая таймауты и сообщения ошибок.
	- Выполняет `probeViaClashApi` через `direct-out` при активном VPN и маркирует такой отчёт источником `clash-direct-out`.
	- Запрашивает ASN через внешний HTTPS-сервис, если это разрешено настройками.
	- Выполняет `applyGeoBlock` через `probePageSignal`, `scoreSinglePage` и `compareRenders`, затем вызывает `deriveVerdict`.
	- Сохраняет максимум 50 результатов в `electron-store` с именем `url-availability`.
	- Регистрирует IPC-обработчики `url-availability:check`, `url-availability:history` и `url-availability:clear-history`.
```

`Availability` передаёт введённую строку через preload в `UrlAvailability`. `UrlAvailability` возвращает `UrlAvailabilityResult`; renderer отображает исходные данные без подмены отсутствующего отчёта успешным результатом другого пути.

### Тестовые компоненты

`urlAvailabilityVerdict.test.ts` проверяет geo-block-aware ветки `deriveVerdict`: доступность только через VPN, блокировку VPN-выхода, блокировку обоими путями, доступность обоими путями и случай HTTP 200 против 403. `mainIpcRegression.test.ts` проверяет передачу `disableGeoLookup` в обработчик проверки URL.

## System Contracts

### Key Contracts

* Вход допускает HTTP(S)-URL и hostname без схемы. Неподдерживаемая схема или неразбираемый адрес завершаются ошибкой до сохранения результата.
* При активном VPN два измерения запускаются параллельно: нативное измерение через туннель и оценка direct-out. При выключенном VPN direct report является нативным, а tunnel report равен `null`.
* Нативный путь останавливается на первом неуспешном этапе DNS, TCP или TLS и возвращает `errorStage`, `errorMessage` и доступные предыдущие сведения.
* `probeViaClashApi` возвращает сокращённый `PathReport` без DNS, TCP, TLS и ASN. Успешный ответ delay сейчас получает `available: true` и HTTP status 200, хотя реальный HTTP-ответ direct-out не проверяется.
* Результат содержит один из `works-both`, `works-only-with-vpn`, `works-only-without-vpn`, `blocked-everywhere` или `unknown` и человекочитаемую рекомендацию.
* Региональная блокировка может изменить `available`, `geoBlocked`, `errorStage` и `errorMessage` после транспортной проверки. Если сигнал страницы не получен, проверка блокировки пропускается.
* Каждый завершённый результат добавляется в начало локальной истории. История ограничена 50 элементами; renderer показывает до 20 последних записей.
* ASN lookup может отправить первый разрешённый IP в `https://ipapi.co/{ip}/json/`; настройка `disableGeoLookup` отключает этот запрос.

### Integration Contracts

* `url-availability:check` принимает строку URL через preload и возвращает `UrlAvailabilityResult`.
* `url-availability:history` возвращает массив `UrlAvailabilityResult` из локального хранилища.
* `url-availability:clear-history` очищает локальную историю и не возвращает результат проверки.
* Renderer использует `window.electronAPI` и не получает прямой доступ к Node API.
* `UrlAvailability` зависит от localhost Clash API, настроек `disableGeoLookup`, активного TUN и offscreen BrowserWindow для анализа страницы.

## Architecture Decision Records

### ADR-001: Сравнивать VPN и прямой путь без отключения туннеля

**Context:** Пользователю нужен ответ, помогает ли VPN, но отключение защиты во время проверки меняет состояние системы и создаёт окно без защиты.

**Decision:** При активном VPN использовать нативный путь через TUN и direct-out sing-box. Direct-out возвращает только задержку, поэтому отчёт явно хранит источник `clash-direct-out` и неполную детализацию.

**Consequences:** Сравнение выполняется без остановки VPN и даёт быстрый результат. Прямой путь имеет меньше диагностических данных и текущий успешный delay может считаться доступностью без реального HTTP-ответа.

### ADR-002: Использовать отрендеренную страницу для региональной блокировки

**Context:** HTTP 200 или транспортное соединение не доказывают, что сайт доступен пользователю. Сайт может вернуть страницу с сообщением о региональном запрете.

**Decision:** Для достигнутых путей получать `PageSignal`, применять одиночную оценку или дифференциальное сравнение и отмечать `geoBlocked` в соответствующем отчёте.

**Consequences:** Вердикт учитывает содержимое страницы и сравнение регионов. Рендер увеличивает время проверки и может не дать сигнала, тогда транспортный результат остаётся основой классификации.

### ADR-003: Сохранять историю локально

**Context:** Пользователю нужно возвращаться к результатам предыдущих измерений, а результаты мониторинга относятся к локальному использованию приложения.

**Decision:** Хранить результаты в `electron-store` в LRU-списке максимум из 50 элементов и предоставлять IPC-операции чтения и очистки.

**Consequences:** История доступна после повторного открытия приложения и не требует отдельного сервиса. Формат и размер истории зависят от локального хранилища.
