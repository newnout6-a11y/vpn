# Тест скорости

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/508cb0ed-7714-4591-92fa-302e8420273f

## Feature Summary

Функция измеряет задержку, скорость загрузки и скорость отправки через активное VPN-соединение. `#SpeedTestPage` показывает ход фаз и результат, а `#SpeedTestService` выполняет измерение, проверяет состояние туннеля, сохраняет до 50 последних `SpeedTestResult` и предоставляет историю через IPC. Функция реализует @Тест скорости и уточняет сетевые измерения из @Мониторинг.

## Component Blueprint Composition

Общая capability-blueprint для этой функции не подтверждена. Функция использует `#TunController` для проверки, что VPN-туннель запущен, и `#IpMonitor` для попытки сопоставить внешний IP с текущим IP мониторинга.

## Feature-Specific Components

### Main process

```component
name: SpeedTestService
container: Electron main process
responsibilities:
	- Проверяет состояние `TunStatus` перед запуском измерения.
	- Последовательно измеряет задержку, загрузку и отправку через внешние HTTPS-сервисы.
	- Выбирает первый сервис задержки с минимум тремя успешными ответами.
	- Переключается между сервисами загрузки Cloudflare, OVH и Tele2 при ошибке.
	- Публикует события `speed-test:progress` с фазой и процентом выполнения.
	- Сохраняет `SpeedTestResult` в локальном electron-store и ограничивает историю 50 записями.
	- Обслуживает IPC-каналы `speed-test:run` и `speed-test:history`.
```

### Renderer process

```component
name: SpeedTestPage
container: Electron renderer process
responsibilities:
	- Показывает предупреждение, когда VPN-туннель не запущен.
	- Запускает `speed-test:run` и блокирует повторный запуск во время измерения.
	- Отображает фазу и процент выполнения через события `speed-test:progress`.
	- Показывает задержку, скорости загрузки и отправки, сервис загрузки, VPN-профиль и время результата.
	- Загружает и отображает локальную историю через `speed-test:history`.
```

`#SpeedTestPage` вызывает `#SpeedTestService` через IPC. Сервис возвращает `SpeedTestResult` только после завершения всех фаз и отправляет промежуточные события для отображения состояния.

`#SpeedTestService` использует `#TunController` как источник состояния VPN и `#IpMonitor` для проверки egress IP. Несовпадение IP логируется как ошибка проверки, но текущая реализация подавляет эту ошибку и продолжает формировать результат.

## System Contracts

### Key Contracts

* Тест нельзя запускать без состояния `running` у VPN-туннеля.
* Одновременно выполняется не более одного теста скорости.
* Фазы выполняются в порядке: задержка, загрузка, отправка.
* Результат не сохраняется, если основное измерение завершается ошибкой.
* История хранится локально и содержит не более 50 последних результатов.
* Сервисы задержки проверяются по фиксированному порядку. Сервис выбирается после минимум трёх успешных ответов; один прогревочный запрос не учитывается.
* Сервисы загрузки проверяются по фиксированному порядку. Для Cloudflare используется динамический объём данных, для OVH и Tele2 используются статические файлы с cache-buster.
* Ошибка проверки egress IP не прерывает измерение в текущей реализации.

### Integration Contracts

* `speed-test:run` запускает тест и возвращает `SpeedTestResult`.
* `speed-test:history` возвращает массив `SpeedTestResult` из локального хранилища.
* `speed-test:progress` передаёт renderer-окну объект с `percent` и `phase`. Наблюдаемые фазы: `latency`, `download`, `upload`, `complete`, `error`.
* `SpeedTestResult` содержит `id`, `timestamp`, `downloadMbps`, `uploadMbps`, `latencyMs`, `serverName` и `profileUsed`.
* Внешние адреса задержки: `https://speed.cloudflare.com/__down?bytes=0`, `https://www.google.com/generate_204`, `https://connectivitycheck.gstatic.com/generate_204`, `https://detectportal.firefox.com/success.txt`, `https://1.1.1.1`.
* Внешние сервисы загрузки: Cloudflare, OVH и Tele2. Сервис отправки: `https://speed.cloudflare.com/__up`.
* Проверка egress IP использует `https://api.ipify.org?format=json` и текущий IP из `#IpMonitor`.

## Architecture Decision Records

### ADR-001: Последовательные фазы и резервные сервисы

**Context:** Измерение должно дать три показателя при временной недоступности отдельных внешних сервисов.

**Decision:** Выполнять фазы последовательно. Для задержки использовать первый подходящий адрес из упорядоченного списка. Для загрузки переходить к следующему сервису при ошибке. Для отправки использовать Cloudflare.

**Consequences:** Тест получает отдельные показатели и может завершиться при отказе одного сервиса загрузки. Результат зависит от выбранного сервиса загрузки и доступности внешних платформ.

### ADR-002: Локальная история ограниченного размера

**Context:** Пользователю нужны предыдущие измерения, а история не должна расти без ограничения.

**Decision:** Хранить результаты в локальном electron-store и оставлять максимум 50 последних записей.

**Consequences:** История доступна между открытиями страницы и ограничивает расход локального хранилища. Экспорт и удаление отдельных записей кодом не подтверждены.
