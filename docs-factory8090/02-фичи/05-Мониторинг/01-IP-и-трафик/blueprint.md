# IP и трафик в реальном времени

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/40400f44-6fe1-4964-83b0-fe14ef1987cd

## Feature Summary

Функция реализует @IP и трафик в реальном времени и дополняет @Мониторинг показателями текущего VPN-соединения. Главный процесс Electron получает публичный IP, сравнивает его с VPN-базой, считывает статистику VPN-адаптера и наблюдает активные соединения. Renderer показывает эти данные на `Dashboard`, в `DashboardSide` и `BrowserIpCard`, включая состояние недоступности и предупреждения о возможных утечках.

Функция также предоставляет браузерную проверку IP и WebRTC, а модуль `geoBlockDetect` оценивает признаки региональной блокировки по сигналам страниц и сравнению VPN- и прямого пути. История доменов и текущие данные собираются локально. Внешние HTTP(S)-сервисы используются для публичного IP, географии IP и браузерной проверки.

## Component Blueprint Composition

Функция напрямую композирует компоненты главного процесса и renderer, которые уже входят в родительский blueprint @Мониторинг:

* `ipMonitor` получает публичный IP через набор `IP_CHECK_URLS`, принимает первый корректный результат, хранит `vpnIp`, вычисляет `isLeak` и публикует изменения. Во время остановки или защищённой смены профиля #IpMonitor приостанавливает публикацию промежуточных результатов.
* `trafficMonitor` считывает `Get-NetAdapterStatistics` для VPN-адаптера через длительно работающий PowerShell reader. Он публикует `TrafficStats` с текущими, сглаженными и пиковыми скоростями, общими и сессионными байтами.
* `trafficConnections` опрашивает локальный Clash API sing-box на `/connections`, фильтрует инфраструктурные хосты и накапливает домены, количество соединений и байты в локальном electron-store.
* `geoBlockDetect` получает `PageSignal` от сетевого измерения и возвращает `GeoBlockVerdict` на основании HTTP 451/403, конечного URL, заголовка, текста страницы и различия VPN- и прямого рендера.

## Feature-Specific Components

### Главный процесс Electron

```component
name: IpMonitor
container: Electron main process
responsibilities:
	- Получает публичный IP через `IP_CHECK_URLS` с таймаутом и резервными HTTPS-провайдерами.
	- Сравнивает текущий адрес с `vpnIp`, публикует изменение IP и признак утечки подписчикам.
	- Приостанавливает расчёт и публикацию признака утечки во время защищённых переходов.
```

```component
name: TrafficMonitor
container: Electron main process
responsibilities:
	- Публикует `TrafficStats` с состоянием VPN-адаптера, скоростями, объёмами, пиками и burstiness.
	- Сэмплирует адаптер один раз в секунду через постоянный PowerShell reader.
	- Сбрасывает сессионные базовые счётчики при запуске и остановке мониторинга.
```

```component
name: TrafficConnectionsSampler
container: Electron main process
responsibilities:
	- Опросит локальный Clash API `/connections` с bearer-секретом через loopback.
	- Нормализует имена хостов и исключает IP-литералы, локальные имена, службы обнаружения, DoH-инфраструктуру и хосты VPN-серверов.
	- Сохраняет агрегаты `TrafficDomainRecord` с первым и последним наблюдением, количеством соединений и байтами.
```

```component
name: GeoBlockDetector
container: Electron main process
responsibilities:
	- Оценивает `PageSignal` по HTTP-статусу, конечному URL, заголовку и короткому тексту.
	- Сравнивает foreign- и local-рендеры и возвращает `GeoBlockVerdict` с уверенностью и причинами.
```

### Renderer Electron

```component
name: DashboardMonitoringViews
container: Electron renderer process
responsibilities:
	- Показывает публичный IP, страну и город при подтверждённом VPN-IP, скорости и сессионные объёмы трафика.
	- Показывает состояние утечки и отдельные состояния загрузки или недоступности.
	- Передаёт данные трафика в `DashboardSide` для графика текущих скоростей.
```

```component
name: BrowserIpCard
container: Electron renderer process
responsibilities:
	- Получает браузерные IPv4 и IPv6 через внешние IP-сервисы.
	- Собирает WebRTC-кандидаты через Google STUN и классифицирует публичные, локальные и mDNS-адреса.
	- Сравнивает браузерный IP с IP главного процесса и показывает предупреждения о возможной утечке.
```

`DashboardMonitoringViews` получает обновления состояния через store и IPC. `DashboardSide` использует опубликованные данные `TrafficStats` для краткого графика загрузки и отдачи, а также читает последние домены через IPC истории трафика. `BrowserIpCard` запускает пользовательскую проверку, отменяет устаревшую проверку при смене контекста и отображает результат.

## System Contracts

### Key Contracts

* `IpMonitor` принимает только корректные IPv4 или IPv6 адреса от IP-провайдера и показывает недоступность, если все провайдеры завершились ошибкой.
* `IpMonitor` не публикует промежуточный адрес как новую утечку, пока мониторинг приостановлен; явное rebaseline устанавливает новый `vpnIp`.
* `TrafficMonitor` публикует `adapterFound: false`, если VPN-адаптер не найден, и не подставляет неподтверждённые скорости или байты.
* `TrafficMonitor` сбрасывает базовые и сессионные счётчики при обратном уменьшении счётчика адаптера или начале нового сеанса.
* `TrafficConnectionsSampler` не направляет loopback-запрос через системный или заданный proxy и не создаёт записи для отфильтрованных хостов.
* `BrowserIpCard` отменяет предыдущую проверку при запуске новой и не применяет результат после смены идентификатора проверки.
* `GeoBlockDetector` возвращает `blocked: false` с нулевой уверенностью, если foreign-рендер сам выглядит заблокированным, и не выдаёт неподтверждённый вывод.
* Известные расхождения, требующие отдельного решения: потеря точности больших счётчиков в `trafficMonitor` (F-082), повторное использование `connection.id` в `trafficConnections` (F-083), лишние запросы IP-провайдеров (F-088), таймеры после размонтирования Dashboard (F-155) и фоновые опросы без проверки скрытого документа (F-156).

### Integration Contracts

* `ipMonitor` публикует изменения текущего IP и признака утечки через callback подписчика; renderer получает состояние через IPC `getPublicIp`.
* `trafficMonitor` публикует `TrafficStats` через callback и предоставляет текущий снимок для IPC renderer.
* `trafficConnections` потребляет локальный `http://127.0.0.1:<port>/connections` с `Authorization: Bearer <secret>`, читает `metadata.host` или `metadata.sniffHost`, `upload` и `download`.
* `Dashboard` показывает публичный IP и `TrafficStats`; `DashboardSide` показывает скорости, график за последние отсчёты и последние домены; `BrowserIpCard` показывает браузерные IPv4, IPv6 и WebRTC-кандидаты.
* Внешние границы включают `IP_CHECK_URLS`, `ipapi.co` и `ipwho.is` для географии подтверждённого VPN-IP, `api.ipify.org`, `api.myip.com`, `api6.ipify.org` для браузерной проверки и `stun:stun.l.google.com:19302` для ICE.
* `geoBlockDetect` потребляет `PageSignal` и возвращает `GeoBlockVerdict` для вызывающего сетевого измерения. Техническая реализация проверки доступности URL остаётся в родительской функции и не дублируется здесь.

## Architecture Decision Records

### ADR-001: Резервные провайдеры публичного IP

**Context:** Публичный IP должен оставаться доступным при недоступности одного внешнего сервиса.

**Decision:** `IpMonitor` запрашивает четыре HTTPS-адреса из `IP_CHECK_URLS` и принимает первый корректный адрес, проверенный как IPv4 или IPv6.

**Consequences:** Повышается устойчивость к отказу одного провайдера, но параллельные проигравшие запросы могут продолжаться и раскрывать IP нескольким сервисам. Нужна отдельная политика отмены и приватности.

### ADR-002: Локальный сбор текущего трафика

**Context:** Показ текущих скоростей и активных доменов должен работать без передачи этих данных внешнему сервису.

**Decision:** `TrafficMonitor` читает локальные счётчики VPN-адаптера, а `TrafficConnectionsSampler` обращается к loopback Clash API и сохраняет агрегаты локально.

**Consequences:** Текущие показатели и домены доступны без внешнего хранилища. Форматы локального API и идентификаторы соединений требуют контроля при обновлении sing-box.
