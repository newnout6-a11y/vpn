# Восстановление сети после сбоя

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/requirements/b11b44d0-6a3e-41eb-9eb3-d075796c75b3

## Обзор

Функция «Восстановление сети после сбоя» возвращает сеть в безопасное и управляемое состояние после аварийного завершения VPN Tunnel Enforcer, сбоя туннеля или перезагрузки Windows. Она восстанавливает только те системные изменения, которые приложение может связать с предыдущей сессией, и сохраняет защитное состояние, если подтверждённого отката нет или операция завершилась с предупреждениями.

Функция работает при запуске приложения, через задачу Windows при загрузке системы и по ручному действию из Dashboard. Она охватывает stale baseline, kill-switch, блокировку физических адаптеров, DNS, переменные прокси окружения и оставшийся виртуальный TUN-адаптер. Восстановление должно учитывать, что часть изменений может быть выполнена до сбоя, а манифест отката может отсутствовать или быть неполным.

## Терминология

* **Восстановление после сбоя**: возврат системных сетевых ресурсов из незавершённого состояния предыдущей сессии.
* **Stale baseline**: сохранённый признак применённого сетевого baseline, который остался после завершения процесса без штатного отката.
* **Манифест блокировки адаптеров**: сохранённое описание состояния физических адаптеров, DNS, IPv6, переходных адаптеров и DNS-политик до изменений приложения.
* **Kill-switch**: правила и политика Windows Firewall, блокирующие исходящий трафик вне защищённого туннеля.
* **Блокировка физических адаптеров**: системные изменения, ограничивающие физические адаптеры, IPv6, DNS и переходные адаптеры на время защиты.
* **Orphaned DNS**: DNS-настройки VPNTE, оставшиеся на сетевом адаптере без действующей сессии приложения.
* **Env autoconfig**: переменные прокси окружения HTTP_PROXY, HTTPS_PROXY, ALL_PROXY и NO_PROXY, настроенные приложением.
* **Boot Recovery**: задача Windows «VPNTE Boot Recovery», запускающая восстановление от имени SYSTEM при старте Windows.
* **Dashboard**: основной экран приложения, с которого пользователь запускает ручные действия и видит состояние защиты.
* **Предупреждение восстановления**: результат, показывающий, что восстановление завершилось частично или не подтвердило все операции.

## Требования

### REQ-LEAK-RCV-001: Восстановление при запуске приложения

**История пользователя:** Как пользователь VPN, я хочу, чтобы приложение проверяло остатки предыдущей сессии при запуске, чтобы сбой не оставлял сеть в изменённом состоянии.

**Критерии приёмки:**

* **AC-LEAK-RCV-001.1:** Когда приложение запускается после незавершённой сессии и защищённый процесс не работает, система должна восстановить сохранённый сетевой baseline.
* **AC-LEAK-RCV-001.2:** Когда приложение запускается после незавершённой сессии, система должна проверить и обработать оставшийся kill-switch.
* **AC-LEAK-RCV-001.3:** Когда приложение запускается после незавершённой сессии, система должна проверить и обработать оставшуюся блокировку физических адаптеров.
* **AC-LEAK-RCV-001.4:** Когда приложение запускается после незавершённой сессии, система должна удалить обнаруженные orphaned DNS.
* **AC-LEAK-RCV-001.5:** Когда приложение запускается после незавершённой сессии, система должна откатить env autoconfig, кроме случая, когда текущий режим Soft требует сохранить эти настройки.
* **AC-LEAK-RCV-001.6:** Если восстановление отдельной области завершается ошибкой, система должна записать предупреждение и продолжить обработку остальных областей.

### REQ-LEAK-RCV-002: Восстановление при загрузке Windows

**История пользователя:** Как пользователь Windows, я хочу, чтобы сеть восстанавливалась до входа в приложение после сбоя или перезагрузки, чтобы остаточные системные изменения не блокировали сеть.

**Критерии приёмки:**

* **AC-LEAK-RCV-002.1:** Когда Windows запускает задачу Boot Recovery, система должна выполнить восстановление доступных манифестов, kill-switch, DNS, IPv6, переходных адаптеров и env autoconfig.
* **AC-LEAK-RCV-002.2:** Когда Boot Recovery находит манифест блокировки адаптеров, система должна восстановить только ресурсы, описанные этим манифестом.
* **AC-LEAK-RCV-002.3:** Когда Boot Recovery обнаруживает orphaned VPNTE-правила или DNS без манифеста, система должна выполнить предусмотренное восстановление и записать результат.
* **AC-LEAK-RCV-002.4:** После успешного восстановления Boot Recovery должна удалить обработанный манифест.
* **AC-LEAK-RCV-002.5:** Если восстановление завершилось с предупреждениями, Boot Recovery должна сохранить манифест для последующего разбора.

### REQ-LEAK-RCV-003: Ручное восстановление

**История пользователя:** Как пользователь VPN, я хочу запустить восстановление из Dashboard, чтобы исправить остаточное сетевое состояние без ожидания следующего запуска.

**Критерии приёмки:**

* **AC-LEAK-RCV-003.1:** Когда пользователь запускает ручное восстановление, система должна выполнить целевые операции очистки VPNTE-состояния.
* **AC-LEAK-RCV-003.2:** Когда пользователь запускает ручное восстановление, система не должна изменять активный защищённый туннель.
* **AC-LEAK-RCV-003.3:** После ручного восстановления Dashboard должен показать результат операции.

### REQ-LEAK-RCV-004: Безопасное поведение при неполном восстановлении

**История пользователя:** Как пользователь VPN, я хочу видеть неполное восстановление как проблему, чтобы не считать сеть восстановленной без подтверждения.

**Критерии приёмки:**

* **AC-LEAK-RCV-004.1:** Если отсутствует манифест исходного состояния, система должна сохранить текущие системные значения, для которых исходное состояние нельзя подтвердить.
* **AC-LEAK-RCV-004.2:** Если операция восстановления не подтверждена, система должна показать предупреждение восстановления.
* **AC-LEAK-RCV-004.3:** Если восстановление kill-switch требует выбора между сохранением Block и возвратом Allow при отсутствии манифеста, система должна применить утверждённую политику после решения открытого вопроса F-017/F-030.

## Открытые вопросы

* Какое нормативное поведение выбрать для kill-switch, если манифест отсутствует или не записался: сохранять Windows Firewall в состоянии Block или возвращать Allow? Это конфликт F-017/F-030.
* Нужно ли включать kill-switch при нормализации настроек, если соответствующее поле отсутствует? Нормативное поведение не подтверждено находкой F-146.
* Должна ли задача Boot Recovery считаться обязательной функцией после установки, если синхронизация автозапуска не была вызвана? Код создаёт её только через путь синхронизации автозапуска, а ошибки создания подавляет. Это связано с F-150.
* Должна ли функция «Восстановление сети после сбоя» включать постоянную совместимость Epic Online Services из `vpnte-eos-compat.ps1`? Скрипт изменяет IPv6 prefix policy, hosts и правило Codex, а обратный откат в предоставленных материалах не подтверждён.
