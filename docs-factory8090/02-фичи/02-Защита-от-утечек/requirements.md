# Защита от утечек

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/requirements/24532e19-3ab7-4516-8bec-7a4de4d708c3

## Обзор

Функция «Защита от утечек» предотвращает выход трафика за пределы защищённого туннеля, пока защита включена. Она сохраняет безопасное состояние при потере туннеля или прокси, показывает пользователю текущее состояние защиты и позволяет выполнить экстренный сброс Windows Firewall из Dashboard.

Функция задаёт общие правила для защиты сети. Детали отдельных областей вынесены в дочерние функции: «Kill-switch и исключения», «Блокировка физических адаптеров, IPv6 и DNS», «Защита браузеров» и «Восстановление сети после сбоя».

## Терминология

* **Защита от утечек**: режим работы приложения, при котором трафик вне защищённого туннеля блокируется.
* **Защищённый туннель**: сетевой путь, через который приложение направляет защищённый трафик.
* **Состояние защиты**: доступное пользователю описание того, включена ли защита и блокируется ли трафик вне туннеля.
* **Dashboard**: основной экран приложения, на котором пользователь видит состояние защиты и выполняет доступные действия.
* **Системное изменение**: изменение Windows Firewall, DNS, IPv6, сетевых адаптеров или маршрутов, выполненное приложением.
* **Откат**: восстановление состояния системного ресурса до системного изменения.
* **Экстренный сброс Windows Firewall**: действие пользователя, которое восстанавливает безопасное состояние Windows Firewall через Dashboard.
* **Дочерняя функция**: отдельная функция, расширяющая «Защиту от утечек» и описанная в собственном документе требований.

## Требования

### REQ-LEAK-001: Блокировка трафика вне туннеля

**История пользователя:** Как пользователь VPN, я хочу, чтобы трафик вне защищённого туннеля блокировался, чтобы сетевые данные не уходили в обход защиты.

**Критерии приёмки:**

* **AC-LEAK-001.1:** Пока защита от утечек включена, система должна блокировать трафик, который не проходит через защищённый туннель.
* **AC-LEAK-001.2:** Если защищённый туннель или прокси становится недоступен, система должна сохранять блокировку трафика вне защищённого туннеля.
* **AC-LEAK-001.3:** Если включение защиты не завершилось успешно, система должна сообщить о неуспешном включении и не считать защиту включённой.

Детали реализации этой способности описаны в дочерней функции «Kill-switch и исключения».

### REQ-LEAK-002: Обратимость системных изменений

**История пользователя:** Как пользователь VPN, я хочу, чтобы изменения системной сети можно было отменить, чтобы после остановки, сбоя или выхода приложения вернуть сеть в исходное состояние.

**Критерии приёмки:**

* **AC-LEAK-002.1:** Для каждого системного изменения система должна сохранять сведения, необходимые для отката.
* **AC-LEAK-002.2:** После остановки защиты система должна проверять результат отката.
* **AC-LEAK-002.3:** Если откат завершился с ошибкой или проверка результата не пройдена, система должна сообщить о проблеме и сохранить защитное состояние до разрешения конфликта.

Детали реализации этой способности описаны в дочерней функции «Восстановление сети после сбоя».

### REQ-LEAK-003: Видимость состояния защиты

**История пользователя:** Как пользователь VPN, я хочу видеть состояние защиты в приложении, чтобы понимать, защищён ли мой трафик.

**Критерии приёмки:**

* **AC-LEAK-003.1:** Dashboard должен показывать текущее состояние защиты.
* **AC-LEAK-003.2:** Системный трей должен показывать текущее состояние защиты.
* **AC-LEAK-003.3:** Если состояние защиты изменилось из-за потери туннеля, сбоя или восстановления, Dashboard и системный трей должны обновить отображаемое состояние.

Детали реализации этой способности описаны в дочерних функциях «Kill-switch и исключения» и «Восстановление сети после сбоя».

### REQ-LEAK-004: Экстренный сброс Windows Firewall

**История пользователя:** Как пользователь VPN, я хочу выполнить экстренный сброс Windows Firewall из Dashboard, чтобы восстановить управление сетевыми правилами при проблеме с защитой.

**Критерии приёмки:**

* **AC-LEAK-004.1:** Dashboard должен предоставлять пользователю действие экстренного сброса Windows Firewall.
* **AC-LEAK-004.2:** При запуске экстренного сброса система должна удалить правила защиты, созданные приложением, и восстановить сохраненные значения Windows Firewall, если они доступны.
* **AC-LEAK-004.3:** После экстренного сброса система должна показать пользователю результат операции.

## Открытые вопросы

* Какое поведение является правильным, если манифест отката отсутствует или не записался: оставить Windows Firewall в состоянии Block или вернуть его в состояние Allow? Конфликт наблюдается в случаях F-017 и F-030.
* Нужно ли считать функцию включённой, если нормализация настроек включает kill-switch при отсутствии соответствующего поля? Случай F-146 требует решения о корректном поведении.
