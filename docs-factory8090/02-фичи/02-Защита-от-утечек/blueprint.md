# Защита от утечек

## Feature Summary

Функция соответствует требованиям `REQ-LEAK-001`–`REQ-LEAK-004` документа требований «Защита от утечек». В приложении для Windows на Electron 42 она объединяет блокировку исходящего трафика вне туннеля, системные изменения для снижения риска утечек, восстановление после остановки или сбоя, отображение состояния в Dashboard и системном трее, а также экстренный сброс правил Windows Firewall.

Ниже описано только общее устройство родительской функции. Детали дочерних функций «Kill-switch и исключения», «Блокировка физических адаптеров, IPv6 и DNS», «Защита браузеров» и «Восстановление сети после сбоя» здесь не дублируются.

## Component Blueprint Composition

* Дочерняя функция «Kill-switch и исключения» использует `#FirewallKillSwitch` и `#GranularKillSwitch`. `#FirewallKillSwitch` применяет Windows Firewall с `DefaultOutboundAction=Block`, а `#GranularKillSwitch` выбирает уровни `off`, `standard` и `strict` и хранит исключения.
* Дочерняя функция «Блокировка физических адаптеров, IPv6 и DNS» использует `#PhysicalAdapterLockdown` и `#SystemNetworkBaseline` для изменения состояния физических адаптеров, IPv6 и DNS с последующим откатом.
* Дочерняя функция «Защита браузеров» использует `#BrowserHardening` для Chromium-браузеров и Firefox. Эта область не раскрывается в родительской функции.
* Дочерняя функция «Восстановление сети после сбоя» использует `#ProtectionRecovery` для автоматического восстановления после остановки, выхода и аварийного завершения приложения. Эта область не раскрывается в родительской функции.

## Feature-Specific Components

### Защита и системное состояние

```component
name: FirewallKillSwitch
container: Electron Main Process
responsibilities:
	- Применяет правила Windows Firewall и устанавливает `DefaultOutboundAction=Block` для блокировки трафика вне разрешённых направлений.
	- Сохраняет манифест с исходными значениями профилей Windows Firewall и удаляет созданные приложением правила при восстановлении.
	- Проверяет наличие собственных правил и застрявшего состояния Block перед восстановлением.
```

```component
name: GranularKillSwitch
container: Electron Main Process
responsibilities:
	- Управляет уровнями `off`, `standard` и `strict`.
	- Пересчитывает политику блокировки при изменении уровня и состояния VPN.
	- Синхронизирует уровень с устаревшей настройкой `firewallKillSwitch` и возвращает предыдущее значение при неуспешном применении.
```

```component
name: PhysicalAdapterLockdown
container: Electron Main Process
responsibilities:
	- Отключает IPv6 на физических сетевых адаптерах и переходные адаптеры Teredo, 6to4 и ISATAP.
	- Сохраняет сведения об адаптерах, DNS и политиках Windows для последующего восстановления.
```

```component
name: SystemNetworkBaseline
container: Electron Main Process
responsibilities:
	- Применяет системный сетевой baseline, включая DNS-настройки, и сохраняет манифест текущего изменения.
	- Выполняет проверенный откат baseline при остановке, выходе или сбое.
```

```component
name: BrowserHardening
container: Electron Main Process
responsibilities:
	- Применяет защиту от утечек браузера для обнаруженных Chromium-браузеров и Firefox.
	- Создаёт резервные копии изменяемых политик и файлов и восстанавливает их по манифесту.
```

### Состояние приложения и пользовательские границы

```component
name: ProtectionRecovery
container: Electron Main Process
responsibilities:
	- Запускает автоматическое восстановление системного состояния после остановки, выхода или аварийного завершения приложения.
	- Сохраняет манифест восстановления при предупреждениях или ошибках, чтобы повторная попытка не потеряла сведения для отката.
```

```component
name: ProtectionStatusPresenter
container: Electron Main Process, Electron Renderer Process
responsibilities:
	- Передаёт состояние Windows Firewall и защиты через проверенный IPC-канал.
	- Обновляет состояние при переходах туннеля, включая состояние `killswitch-active`, когда туннель остановлен, но блокировка остаётся активной.
	- Показывает состояние защиты в Dashboard и системном трее.
```

```component
name: FirewallEmergencyReset
container: Electron Main Process, Electron Renderer Process
responsibilities:
	- Принимает действие экстренного сброса Windows Firewall из Dashboard через IPC.
	- Удаляет правила защиты приложения, восстанавливает сохранённые значения профилей, очищает манифест и возвращает результат операции в Dashboard.
```

`#GranularKillSwitch` передаёт выбранную политику в `#FirewallKillSwitch`, а `#ProtectionStatusPresenter` получает фактическое состояние Firewall после переходов туннеля. Такой порядок позволяет интерфейсу показывать блокировку как состояние защиты, а не как устаревшее состояние сбоя.

`#PhysicalAdapterLockdown`, `#SystemNetworkBaseline` и `#BrowserHardening` сохраняют исходные значения до изменения системных ресурсов. `#ProtectionRecovery` использует эти сведения при автоматическом откате; результат восстановления передаётся в `#ProtectionStatusPresenter`.

`#FirewallEmergencyReset` является отдельной пользовательской границей к `#FirewallKillSwitch`. Он не изменяет настройки дочерних функций и сообщает результат только после завершения удаления правил и восстановления доступных сохранённых значений.

## System Contracts

### Key Contracts

* Пока защита включена, исходящий трафик вне защищённого туннеля должен оставаться заблокированным. При потере прокси блокировка не должна сниматься автоматически.
* Каждое изменение Windows Firewall, DNS, IPv6, сетевых адаптеров или маршрутов должно иметь сведения для отката и проверку результата восстановления.
* Если применение защиты или откат завершается ошибкой, состояние операции должно быть явно передано в пользовательский интерфейс, а защитная блокировка не должна считаться снятой без подтверждения результата.
* Состояние защиты в Dashboard и системном трее должно отражать фактическое состояние, включая активную блокировку при остановленном туннеле.
* Идемпотентность, порядок повторных попыток и нормативное действие при отсутствующем или незаписанном манифесте не определены полностью. Случаи F-017 и F-030 оставлены открытыми.
* Нормализация настроек может включить kill-switch при отсутствии поля. Нормативное поведение случая F-146 оставлено открытым.

### Integration Contracts

* Основной процесс Electron предоставляет renderer-процессу проверенные IPC-операции чтения состояния защиты, изменения уровня kill-switch и запуска экстренного сброса Windows Firewall.
* `#FirewallKillSwitch` взаимодействует с Windows Firewall через PowerShell cmdlets и использует манифест `manifest.json` для сохранения исходных профилей.
* `#PhysicalAdapterLockdown` использует манифест `latest-physical-adapter-lockdown.json`; `#SystemNetworkBaseline` использует манифест `latest-tun-network-baseline.json`; `#BrowserHardening` использует манифест `latest-browser-hardening.json`.
* `#ProtectionRecovery` должен быть доступен при аварийном завершении и при загрузке Windows. Точная граница запуска восстановления через задачу SYSTEM подтверждена артефактами, но не раскрывается в этом родительском блюпринте.

## Architecture Decision Records

### ADR-001: Блокировать трафик по умолчанию при активной защите

**Context:** Потеря туннеля или локального прокси может направить трафик через физический интерфейс. Найденная реализация использует Windows Firewall и блокирует исходящий трафик через `DefaultOutboundAction=Block`.

**Decision:** Считать активную блокировку базовым контрактом родительской функции. Уровни и исключения описывать в дочерней функции «Kill-switch и исключения».

**Consequences:** Сбой туннеля сохраняет защиту, но отсутствие решения по восстановлению без манифеста может оставить систему в неопределённом состоянии F-017/F-030.

### ADR-002: Все изменения должны быть обратимыми и проверяемыми

**Context:** Функция изменяет Firewall, DNS, IPv6, физические адаптеры и настройки браузеров. Документы архитектуры заявляют rollback и проверку результата как инвариант, а код хранит манифесты для нескольких областей.

**Decision:** Каждый компонент, который меняет системное состояние, создаёт резервное описание до изменения, проверяет результат применения и сохраняет сведения для повторного восстановления при ошибке.

**Consequences:** Откат сохраняет пользовательские настройки, но корректное действие при отсутствующем или незаписанном манифесте требует решения владельца продукта.
