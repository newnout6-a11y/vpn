# Изоляция аккаунтов в браузерных профилях (план)

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/requirements/47ca1095-07f4-46ce-b945-230aee757e48

## Обзор

Функция описывает целевую возможность создавать и запускать изолированные браузерные профили, называемые боксами. Каждый бокс должен отделять сетевой выход через выбранный VPN-сервер от cookies, localStorage, кэша и расширений других боксов. Это позволит одновременно использовать несколько аккаунтов и браузерных сессий без смешивания их данных и сетевых маршрутов.

Функция **не реализована**. Этот документ фиксирует целевое поведение по плану `docs/multi-account-isolation-plan.md`, который имеет статус черновика и ожидает одобрения. В текущем коде не обнаружена реализация browser boxes.

## Терминология

* **Бокс**: изолированная браузерная среда с отдельным каталогом данных и назначенным сетевым выходом.
* **Профиль сервера**: сохранённая конфигурация VPN-сервера, которую можно назначить боксу как сетевой выход.
* **Каталог данных бокса**: отдельное хранилище профиля браузера для cookies, localStorage, кэша и расширений.
* **Сетевой выход бокса**: VPN-маршрут, связанный с выбранным профилем сервера; также допускается прямой выход без VPN.
* **Браузер бокса**: поддерживаемый Chromium-браузер, выбранный для запуска бокса: Chrome, Edge, Yandex Browser или Brave.
* **Бокс запущен**: состояние, в котором для бокса работают браузер и его сетевой прокси-процесс.
* **Бокс остановлен**: состояние, в котором процессы бокса завершены.
* **Fingerprint-изоляция**: отдельное изменение canvas, WebGL, шрифтов, часового пояса, языка и user-agent. Она не входит в MVP.

## Требования

### REQ-ISO-001: Просмотр и создание боксов

**Пользовательская история:** Как пользователь VPN Tunnel Enforcer, я хочу просматривать список боксов и создавать новый бокс, чтобы управлять отдельными браузерными сессиями.

**Критерии приёмки:**

* **AC-ISO-001.1:** Когда пользователь открывает страницу «Боксы», система должна показывать список существующих боксов и действие создания нового бокса.
* **AC-ISO-001.2:** Когда пользователь создаёт бокс, система должна сохранять его имя, выбранный браузер, выбранный профиль сервера или прямой сетевой выход и отдельный каталог данных.
* **AC-ISO-001.3:** Если пользователь не выбирает профиль сервера, система должна обозначать для бокса прямой сетевой выход.
* **AC-ISO-001.4:** Когда пользователь создаёт бокс, система должна назначать ему уникальный идентификатор и состояние «остановлен».

### REQ-ISO-002: Изолированные данные браузера

**Пользовательская история:** Как пользователь, я хочу, чтобы каждый бокс имел собственные данные браузера, чтобы аккаунты и сессии не смешивались.

**Критерии приёмки:**

* **AC-ISO-002.1:** Когда система запускает бокс, браузер должен использовать каталог данных, отдельный от каталогов всех других боксов.
* **AC-ISO-002.2:** Когда пользователь запускает два бокса, данные cookies, localStorage, кэша и расширений одного бокса не должны использоваться другим боксом.
* **AC-ISO-002.3:** Когда пользователь удаляет бокс, система должна остановить его, если он запущен, и удалить его каталог данных.

### REQ-ISO-003: Запуск браузера через назначенный сетевой выход

**Пользовательская история:** Как пользователь, я хочу запускать бокс через выбранный VPN-сервер, чтобы разные профили выходили через разные сетевые маршруты.

**Критерии приёмки:**

* **AC-ISO-003.1:** Когда пользователь запускает остановленный бокс с назначенным профилем сервера, система должна открыть выбранный браузер с сетевым выходом этого профиля.
* **AC-ISO-003.2:** Когда пользователь запускает бокс с прямым сетевым выходом, система должна открыть выбранный браузер без VPN-маршрута бокса.
* **AC-ISO-003.3:** Когда пользователь меняет профиль сервера остановленного или работающего бокса, система должна сохранять новое назначение без создания нового бокса.
* **AC-ISO-003.4:** Если сетевой прокси бокса не может запуститься, система не должна считать бокс запущенным и должна сообщить о неудаче запуска.

### REQ-ISO-004: Управление жизненным циклом бокса

**Пользовательская история:** Как пользователь, я хочу запускать и останавливать отдельный бокс, чтобы управлять его ресурсами независимо от других боксов.

**Критерии приёмки:**

* **AC-ISO-004.1:** Когда пользователь запускает бокс, система должна сначала подготовить его сетевой прокси, дождаться его готовности и затем открыть браузер.
* **AC-ISO-004.2:** Когда пользователь останавливает бокс, система должна завершить браузер бокса и его сетевой прокси, после чего показать состояние «остановлен».
* **AC-ISO-004.3:** Когда пользователь закрывает браузер бокса, система должна обнаружить завершение процесса и остановить сетевой прокси этого бокса.
* **AC-ISO-004.4:** Когда приложение завершается при работающих боксах, система должна применить согласованное с пользователем действие к этим боксам; вариант действия пока не определён.

### REQ-ISO-005: Выбор и обнаружение браузера

**Пользовательская история:** Как пользователь, я хочу выбрать установленный Chromium-браузер для бокса, чтобы запускать нужную браузерную среду.

**Критерии приёмки:**

* **AC-ISO-005.1:** Система должна поддерживать выбор Chrome, Edge, Yandex Browser или Brave для бокса.
* **AC-ISO-005.2:** При создании бокса система должна предлагать первый найденный поддерживаемый браузер как значение по умолчанию.
* **AC-ISO-005.3:** Если выбранный браузер не найден, система не должна запускать бокс и должна сообщить пользователю о необходимости выбрать доступный браузер.

### REQ-ISO-006: Индикация состояния и обслуживание данных

**Пользовательская история:** Как пользователь, я хочу видеть состояние бокса и размер его данных, чтобы понимать, какие сессии активны и сколько места они занимают.

**Критерии приёмки:**

* **AC-ISO-006.1:** В списке боксов система должна показывать имя, выбранный браузер, сетевой выход и состояние каждого бокса.
* **AC-ISO-006.2:** Для работающего бокса система должна показывать время, прошедшее с момента запуска.
* **AC-ISO-006.3:** Система должна показывать размер каталога данных бокса.
* **AC-ISO-006.4:** Когда пользователь запускает очистку кэша бокса, система должна удалить кэш этого бокса, не удаляя сам бокс и остальные данные его профиля.

### REQ-ISO-007: Ограничения MVP по fingerprint-изоляции

**Пользовательская история:** Как пользователь, я хочу понимать границы изоляции бокса, чтобы не считать базовое разделение профиля полной fingerprint-защитой.

**Критерии приёмки:**

* **AC-ISO-007.1:** В MVP система должна обеспечивать изоляцию сетевого выхода и данных браузера без изменения fingerprint.
* **AC-ISO-007.2:** В MVP система не должна заявлять, что canvas, WebGL, шрифты, часовой пояс, язык или user-agent автоматически различаются между боксами.

## Открытые вопросы

Архитектура сетевого прокси, DNS-изоляция, жизненный цикл боксов и процессов, шифрование каталогов данных, fingerprinting и восстановление после сбоя требуют решения до реализации. Они оставлены открытыми комментариями к документу.
