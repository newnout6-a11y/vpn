# Подключение VPN

## Обзор

Функция позволяет пользователю включать и выключать защиту VPN из основного экрана или системной области приложения. Она показывает текущее состояние защиты и поддерживает единый жизненный цикл туннеля: запуск, работу, остановку и обработку ошибки.

Функция даёт пользователю понятный контроль над тем, проходит ли трафик через VPN, и сообщает о переходных состояниях. Выбор способа подключения ограничен двумя вариантами на уровне общей функции. Детали вариантов вынесены в дочерние функции.

## Терминология

* **Защита VPN**: активное состояние приложения, в котором сетевой трафик направляется через выбранное VPN-подключение.
* **Туннель**: сетевой канал, который приложение запускает для защиты трафика и останавливает при выключении защиты.
* **Основной экран**: экран приложения, на котором пользователь управляет защитой и видит её состояние.
* **Системная область приложения**: область приложения, из которой пользователь может управлять защитой без открытия основного окна.
* **Состояние защиты**: отображаемое состояние жизненного цикла защиты: подключение, работает, отключение или ошибка.
* **Способ подключения**: один из двух вариантов запуска VPN: через локальный прокси или прямой VPN.
* **Режимы подключения: через локальный прокси и прямой VPN**: дочерняя функция, которая описывает два способа подключения.
* **Автовосстановление и защищённый перезапуск**: дочерняя функция, которая описывает восстановление и перезапуск защиты.
* **Адаптивный обход блокировок**: дочерняя функция, которая описывает адаптацию подключения при сетевых ограничениях.
* **Альтернативное ядро mihomo (план)**: дочерняя функция, запланированная для отдельного описания альтернативного ядра.
* **Протокол AmneziaWG (план)**: дочерняя функция, запланированная для отдельного описания протокола.

## Требования

### REQ-CONN-001: Запуск защиты

**История пользователя:** Как пользователь, я хочу включить защиту VPN из основного экрана или системной области приложения, чтобы начать защищённое подключение.

**Критерии приёмки:**

* **AC-CONN-001.1:** Когда пользователь включает защиту из основного экрана, система должна начать жизненный цикл подключения и отобразить состояние «подключение».
* **AC-CONN-001.2:** Когда пользователь включает защиту из системной области приложения, система должна начать жизненный цикл подключения и сохранить единое состояние защиты с основным экраном.
* **AC-CONN-001.3:** Когда подключение успешно установлено, система должна отобразить состояние «работает».
* **AC-CONN-001.4:** Если подключение не может быть установлено, система должна отобразить состояние «ошибка» и сообщить пользователю, что защита не включена.

### REQ-CONN-002: Остановка защиты

**История пользователя:** Как пользователь, я хочу выключить защиту VPN из Dashboard или Tray, чтобы завершить защищённое подключение.

**Критерии приёмки:**

* **AC-CONN-002.1:** Когда пользователь выключает защиту из основного экрана, система должна отобразить состояние «отключение» до завершения остановки.
* **AC-CONN-002.2:** Когда пользователь выключает защиту из системной области приложения, система должна выполнить тот же жизненный цикл остановки, что и при выключении из основного экрана.
* **AC-CONN-002.3:** Когда остановка завершена, система должна отобразить, что защита выключена.
* **AC-CONN-002.4:** Если остановка завершается с ошибкой, система должна сообщить об ошибке и сохранить наблюдаемое состояние, соответствующее фактическому результату остановки.

### REQ-CONN-003: Отображение состояния защиты

**История пользователя:** Как пользователь, я хочу видеть состояние VPN-защиты, чтобы понимать, защищён ли мой трафик.

**Критерии приёмки:**

* **AC-CONN-003.1:** Пока защита подключается, система должна отображать состояние «подключение».
* **AC-CONN-003.2:** Пока защита работает, система должна отображать состояние «работает».
* **AC-CONN-003.3:** Пока защита отключается, система должна отображать состояние «отключение».
* **AC-CONN-003.4:** Если жизненный цикл защиты не может продолжиться из-за ошибки, система должна отображать состояние «ошибка».
* **AC-CONN-003.5:** Основной экран должен отображать текущий статус защиты, а также доступные сведения о подключении, времени работы и трафике.

### REQ-CONN-004: Выбор способа подключения

**История пользователя:** Как пользователь, я хочу выбрать способ подключения, чтобы использовать подходящий для меня вариант VPN-защиты.

**Критерии приёмки:**

* **AC-CONN-004.1:** Когда пользователь выбирает способ подключения, система должна использовать выбранный способ при следующем запуске защиты.
* **AC-CONN-004.2:** Система должна предоставлять ровно два способа подключения на уровне этой функции: через локальный прокси и прямой VPN.
* **AC-CONN-004.3:** Детали способов подключения должны быть определены в дочернем документе «Режимы подключения: через локальный прокси и прямой VPN».
