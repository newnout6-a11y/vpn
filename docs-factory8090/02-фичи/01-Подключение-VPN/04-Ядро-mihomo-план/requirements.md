# Альтернативное ядро mihomo (план)

## Обзор

Статус: план. Эта дочерняя функция описывает будущую возможность использовать mihomo как альтернативное ядро для VPN-подключения после выделения общей границы ядра. В текущем состоянии проект остаётся sing-box-first: код тесно связан с sing-box, а Xray используется только для отдельных REALITY-сценариев. Поддержка mihomo не реализована.

Цель плана состоит в том, чтобы подготовить безопасный путь для второго runtime без превращения главного процесса в трудно диагностируемый гибрид. Сначала должна появиться общая граница ядра и сохраниться текущая работа sing-box. Только после этого можно оценивать прототип mihomo sidecar и связанные режимы.

## Терминология

* **Альтернативное ядро mihomo**: запланированный второй runtime для выполнения VPN-операций после появления общей границы ядра.
* **Ядро VPN**: runtime, который генерирует конфигурацию, запускается, останавливается, сообщает состояние, выполняет проверки работоспособности, предоставляет диагностику и очищает временные данные.
* **Граница ядра**: планируемый контракт между приложением и конкретным ядром VPN, скрывающий engine-specific детали.
* **CoreAdapter**: планируемый адаптер, который предоставляет приложению операции ядра VPN через общую границу.
* **SingBoxAdapter**: планируемый адаптер, сохраняющий текущее поведение sing-box за границей ядра.
* **MihomoAdapter**: планируемый адаптер, который может подключить mihomo только после появления и проверки границы ядра.
* **mihomo sidecar**: планируемый отдельный runtime mihomo, запускаемый как изолированный процесс после готовности адаптерной границы.
* **Режим sing-box-first**: инвариант проекта, при котором текущая реализация и пользовательское поведение остаются основанными на sing-box, пока не принято отдельное решение о втором ядре.
* **Диагностика ядра**: сведения о состоянии, проверках работоспособности, ошибках и runtime-specific деталях конкретного ядра.
* **Прототип mihomo**: ограниченная проверка интеграции mihomo после выделения границы, а не готовая пользовательская поддержка.

## Требования

### REQ-CONN-CORE-001: Подготовка общей границы ядра

**История пользователя:** Как разработчик продукта, я хочу выделить общую границу ядра VPN, чтобы позднее оценить альтернативный runtime без нарушения текущего sing-box-поведения.

**Критерии приёмки:**

* **AC-CONN-CORE-001.1:** До появления рабочего `CoreAdapter` система должна сохранять режим sing-box-first.
* **AC-CONN-CORE-001.2:** `CoreAdapter` должен определять операции генерации конфигурации, подготовки runtime, запуска, остановки, получения состояния, проверки работоспособности, диагностики и очистки.
* **AC-CONN-CORE-001.3:** После выделения границы `SingBoxAdapter` должен сохранять текущее поведение sing-box без пользовательских регрессий.
* **AC-CONN-CORE-001.4:** Если выделение границы приводит к ошибке или неполному покрытию операции ядра, система не должна скрывать engine-specific детали под общей ошибкой туннеля.

### REQ-CONN-CORE-002: Отложенная оценка mihomo

**История пользователя:** Как разработчик продукта, я хочу оценить mihomo после подготовки границы ядра, чтобы не добавлять второй runtime в тесно связанный с sing-box главный процесс.

**Критерии приёмки:**

* **AC-CONN-CORE-002.1:** До появления проверенной границы ядра система не должна запускать mihomo runtime.
* **AC-CONN-CORE-002.2:** После появления проверенной границы команда разработки должна иметь возможность оценить `MihomoAdapter` и `mihomo sidecar` как изолированный прототип.
* **AC-CONN-CORE-002.3:** Прототип mihomo должен оставлять запуск, остановку и очистку sing-box независимыми от экспериментального runtime.
* **AC-CONN-CORE-002.4:** Прототип не должен становиться пользовательским режимом по умолчанию без отдельного решения о поддержке и диагностике.

### REQ-CONN-CORE-003: Сохранение диагностируемости

**История пользователя:** Как оператор, я хочу получать сведения, специфичные для выбранного ядра, чтобы отличать ошибки runtime от общей ошибки VPN-подключения.

**Критерии приёмки:**

* **AC-CONN-CORE-003.1:** Каждая поддержанная реализация ядра должна предоставлять точки расширения для диагностики.
* **AC-CONN-CORE-003.2:** При ошибке ядра диагностика должна сохранять сведения, необходимые для определения конкретного runtime.
* **AC-CONN-CORE-003.3:** При остановке или очистке ядра диагностика должна позволять отличить успешное завершение от ошибки очистки.

## Планируемые границы

План опирается на будущую декомпозицию обязанностей в `tunController`, `systemDiagnostics`, `diagnosticsExport`, `vpnProfiles`, `serverPicker` и `urlAvailability`. Точные интерфейсы, схемы конфигурации, способ запуска mihomo и границы процесса пока не определены.

Текущий `proxyEngine.ts` является реальной точкой расширения: он выбирает sing-box или Xray для upstream proxy. Он не является `CoreAdapter` и не предоставляет границу для mihomo. Поэтому blueprint связывает его только как существующую точку выбора движка, а не как реализацию альтернативного ядра.
