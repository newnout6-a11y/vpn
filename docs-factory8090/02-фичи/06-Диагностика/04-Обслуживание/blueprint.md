# Обслуживание

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/f8a8899a-e540-4641-af2a-04ecbc412f9d

## Feature Summary

Обслуживание предоставляет в расширенном режиме страницу для проверки состояния VPNTE, ограниченной автоматической починки, проверки защиты активного туннеля и экспорта диагностического архива. Страница показывает промежуточные и итоговые результаты, блокирует восстановительные действия при активном туннеле и отделяет аварийный сброс всего Windows Firewall от целевой починки.

## Component Blueprint Composition

* **@Диагностика** — предоставляет системные диагностические результаты, сведения о туннеле, сети, прокси и маршрутизации, которые страница обслуживания отбирает для показа проблемных и предупреждающих областей.
* **@Диагностика** — предоставляет проверку утечек, маршрутизации и экспорт диагностического архива, которые страница обслуживания запускает через IPC-мост.

## Feature-Specific Components

### Renderer

```component
name: MaintenancePage
container: Electron renderer
responsibilities:
	- Показывает состояние обслуживания и результат последнего действия.
	- Запускает проверку состояния, автоматическую починку, проверку защиты, экспорт диагностического архива и аварийный сброс брандмауэра через `ElectronAPI`.
	- Отображает последовательные шаги починки и состояния `ok`, `warn`, `fail` и `running`.
	- Показывает страницу только при включённом `advancedMode` и возвращает пользователя на обычную страницу после его выключения.
```

### Main process

```component
name: MaintenanceIpcHandlers
container: Electron main process
responsibilities:
	- Обрабатывает проверку состояния VPNTE Firewall и целевую починку правил VPNTE.
	- Блокирует откат блокировки адаптеров, починку правил и завершение runtime-процессов при активном туннеле.
	- Выполняет восстановление DNS физических адаптеров, откат сетевого baseline, откат блокировки адаптеров и завершение принадлежащих VPNTE runtime-процессов.
	- Требует подтверждение `RESET_WINDOWS_FIREWALL_CONFIRMED` для полного сброса Windows Firewall.
```

### Rule-set management

```component
name: SmartRouteRuleSetManager
container: Electron main process
responsibilities:
	- Хранит состояние managed rule-set файлов и их метаданные.
	- Выбирает bundled или managed источник в зависимости от режима и полноты managed cache.
	- Обновляет rule-set файлы последовательно через curl с несколькими маршрутами bootstrap и сохраняет размер, SHA-256, маршрут и ошибку.
	- Запускает автоматическое обновление при включённых smart-route настройках.
```

`MaintenancePage` вызывает `MaintenanceIpcHandlers` через `ElectronAPI`. После автоматической починки страница повторно запускает диагностику и проверку состояния Firewall. `SmartRouteRuleSetManager` входит в IPC-мост приложения и связан с обслуживанием через состояние и обновление Smart-RU rule-set, но отдельная кнопка обновления rule-set на `MaintenancePage` в проверенном коде не подтверждена.

## System Contracts

### Key Contracts

* Страница обслуживания доступна только при `advancedMode = true`; при выключении режима навигация и текущая страница удаляются из доступного пользовательского потока.
* Автоматическая починка требует подтверждения до начала действий и не запускается для активного VPN-туннеля.
* Автоматическая починка выполняет шаги последовательно: firewall-правила VPNTE, сетевой baseline Windows, блокировка адаптеров, осиротевший DNS и зависшие процессы VPNTE runtime.
* Ошибка одного шага отображается на этом шаге, а следующие шаги продолжают выполняться.
* Проверка защиты при выключенном туннеле возвращает состояние, что проверка доступна только при активном VPN. Неоднозначный результат не считается успешной защитой.
* Полный сброс Windows Firewall выполняется только после явного подтверждения и затрагивает все правила Windows Firewall. Перед сбросом приложение предупреждает о резервной копии `.wfw`.
* Managed rule-set считается полным только когда каждый локальный файл существует и имеет ненулевой размер. Состояние также содержит SHA-256, время проверки, время обновления, выбранный маршрут и последнюю ошибку.
* Известные ограничения текущего поведения: аудит указывает на отсутствие финальной маскировки некоторых сведений ZIP (F-004, F-097), ошибки DNS leak результата (F-092, F-095), ложное состояние при недоступном логе sing-box (F-093) и неполную локализацию страницы (F-020).

### Integration Contracts

* `MaintenancePage` использует `runSystemDiagnostics`, `firewallRepairHealth`, `getTunStatus`, `firewallRepairVpnteRules`, `rollbackTunNetworkBaseline`, `rollbackAdapterLockdown`, `repairOrphanedDns`, `killStaleSingbox`, `runLeakSelfTest`, `runRoutingSelfTest`, `exportDiagnostics`, `firewallNuclearReset` и повторные вызовы проверки состояния.
* `MaintenanceIpcHandlers` предоставляет каналы `firewall:repair-health`, `firewall:repair-vpnte-rules`, `network:repair-orphaned-dns`, `network:rollback-adapter-lockdown`, `tun:kill-stale-singbox` и `firewall:nuclear-reset`.
* `SmartRouteRuleSetManager` предоставляет состояние и обновление через `smart-route:rule-sets-state` и `smart-route:rule-sets-refresh`; автоматическое обновление запускается при готовности приложения и изменениях соответствующих настроек.
* Результат проверки Firewall содержит сводку, сообщение, количество правил VPNTE, наличие манифеста, состояние политики блокировки по умолчанию, службы, профили и рекомендованные действия.
* Результат rule-set обновления содержит состояние активного источника, полноту managed cache, метаданные файлов, время запуска и завершения, признак успеха и последнюю ошибку.

## Architecture Decision Records

### ADR-001: Ограниченная починка перед полным сбросом

**Context:** Целевая починка должна восстанавливать состояние VPNTE и не удалять правила других программ. Полный сброс Windows Firewall нужен только как аварийный путь.

**Decision:** Сначала предлагать проверку и последовательную починку только объектов VPNTE. Полный сброс отделить в отдельное аварийное действие с предупреждением и токеном подтверждения.

**Consequences:** Обычный сценарий имеет меньший радиус воздействия. Аварийный путь остаётся доступным при повреждённом или потерянном состоянии VPNTE, но может нарушить настройки других программ.

### ADR-002: Блокировка восстановления при активном туннеле

**Context:** Изменение DNS, IPv6, сетевого baseline, правил Firewall или завершение runtime-процессов во время активной защиты может нарушить работающий туннель.

**Decision:** IPC-обработчики проверяют состояние туннеля и возвращают заблокированный результат с объяснением вместо выполнения опасного действия.

**Consequences:** Пользователь должен отключить VPN перед целевой починкой. Активная защита не прерывается обслуживанием.
