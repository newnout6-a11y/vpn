# Проверка утечек и маршрутов

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/90adb4f8-863c-42eb-85e1-6f155c7e74c2

## Feature Summary

Фича реализует проверки выхода трафика и маршрутизации для @Проверка утечек и маршрутов. Основные результаты формируются компонентами `LeakSelfTestResult`, `RoutingSelfTestResult`, `LeakCheckResult` и `SystemDiagnosticResult`, а `DiagnosticsCard` запускает проверки и показывает их пользователю.

## Component Blueprint Composition

Фича использует компоненты VPN runtime и системной диагностики приложения для получения состояния TUN, физических адаптеров, DNS, прокси, маршрутов и журналов. `runSystemDiagnostics` агрегирует результаты `runLeakCheck` и связанных системных проверок в `SystemDiagnosticResult`.

## Feature-Specific Components

### Проверка физического выхода

```component
name: LeakSelfTest
container: Electron main process
responsibilities:
	- Проверяет публичный IP через основной маршрут.
	- Находит активные физические адаптеры Windows с IPv4 и выполняет привязанный запрос для каждого адаптера.
	- Формирует `LeakSelfTestResult` с физическим выходом, несовпадением публичных IP, DNS/IP-деталями и кратким сообщением.
	- Записывает результат в журнал и передаёт событие в форензику трафика.
	- Отменяет устаревший запуск при смене сессии и объединяет одновременные вызовы.
```

`LeakSelfTest` получает вход через `run-leak-self-test` и используется периодически или после изменения сетевого окружения. `DiagnosticsCard` передаёт результат в renderer, а main process создаёт снимок при подтверждённом физическом выходе или несовпадении IP.

### Диагностика DNS и внешнего выхода

```component
name: LeakDiagnostics
container: Electron main process
responsibilities:
	- Получает публичные IPv4 и IPv6 через набор внешних IP-сервисов с резервными способами запроса.
	- Проверяет DNS через Windows `Resolve-DnsName` или `nslookup`.
	- Собирает сведения о VPN-подобных адаптерах, DNS-серверах, прокси и журнале sing-box.
	- Формирует элементы `LeakCheckItem` и сводный `LeakCheckResult`.
```

### Проверка маршрутизации

```component
name: RoutingSelfTest
container: Electron main process
responsibilities:
	- Сравнивает внешний IP через VPN-путь и прямой путь через локальный SOCKS-маршрут.
	- Вычисляет вердикт `ok`, `partial`, `leak`, `tunnel-off` или `inconclusive`.
	- При включённом Smart-RU проверяет выход российского узла через обычный TUN-путь.
	- Формирует `RoutingSelfTestResult` и записывает сводный результат с обезличенными последними октетами IP.
```

`RoutingSelfTest` вызывается через `run-routing-self-test`. Компонент использует состояние `tunController` и настройки `smartRuSplit`, а для проверки прямого пути получает порт через `getDirectProxyPort`.

### Системная диагностика

```component
name: SystemDiagnostics
container: Electron main process
responsibilities:
	- Параллельно собирает результаты по runtime, бинарникам, прокси, сети Windows, процессам, конечным точкам, службам, журналам, форензике, Smart-RU и маршрутизации.
	- Объединяет результаты в `SystemDiagnosticResult`.
	- Различает критические ошибки сети, TUN, прокси, интернета и маршрутизации, предупреждения и успешные результаты.
	- Сохраняет отдельные области результата при недоступности другой области.
```

### Пользовательская поверхность

```component
name: DiagnosticsCard
container: Electron renderer
responsibilities:
	- Запускает активную проверку утечки через `runLeakSelfTest`.
	- Показывает краткий результат и записывает его в пользовательский журнал приложения.
	- Отображает состояние фонового сбора форензики и периодически обновляет его.
	- Предоставляет запуск экспорта диагностики и открытие папки снимков.
```

`DiagnosticsCard` классифицирует результат как ошибочный, если установлен `physicalAdapterReached`, `publicIpMismatch` или `dnsLeakDetected`. Поэтому корректное заполнение DNS-вердикта является обязательным для передачи DNS-утечки в UI.

## System Contracts

### Key Contracts

* `LeakSelfTestResult` должен явно различать физический выход, несовпадение IP, DNS-утечку, отмену и невозможность определить основной IP.
* Проверка не должна показывать отменённый или неполный результат как подтверждённо безопасный.
* Одновременные вызовы активной проверки должны использовать один текущий запуск, а отменённый запуск не должен создавать позднее уведомление об утечке.
* `RoutingSelfTestResult` должен различать выключенный туннель, подтверждённое разделение, совпадающие IP и неполное измерение.
* `SystemDiagnosticResult` должен сохранять отдельные диагностические элементы при частичном отказе отдельных проверок.
* DNS/IP-расхождение должно выставлять DNS-вердикт как обнаруженную утечку, если оба публичных IP доступны и различаются.

### Integration Contracts

* `run-leak-self-test` возвращает `LeakSelfTestResult` в renderer.
* `run-routing-self-test` возвращает `RoutingSelfTestResult` в renderer.
* `diagnostics:run-leak-check` возвращает `LeakCheckResult`.
* `runSystemDiagnostics` возвращает `SystemDiagnosticResult` и используется системной диагностикой и экспортом.
* Событие `leak-self-test-result` передаёт результаты в подсистему форензики трафика.

## Architecture Decision Records

### ADR-001: Разделение активных проверок

**Context:** Одна проверка физического выхода не подтверждает корректность Smart-RU и не заменяет системную сводку.

**Decision:** Оставить отдельные компоненты для физического leak self-test, общей диагностики утечек, проверки маршрутов и системной диагностики, а пользовательскую поверхность использовать для их запуска и отображения.

**Consequences:** Результаты можно проверять отдельно и связывать с конкретными условиями. Сводка требует явного различения неполных и ошибочных областей.

### ADR-002: Известный дефект DNS-вердикта

**Context:** F-092 подтверждён в `src/main/leakSelfTest.ts:266-300`: `dnsLeakDetected` инициализируется как `false` и не становится `true`, хотя `dnsLeakDetail` получает текст расхождения. `src/main/index.ts:1719-1728` и форензика читают флаг.

**Decision:** Целевой контракт сохраняет DNS/IP-расхождение как обнаруженную утечку. Текущий дефект фиксируется как расхождение реализации и требований, без изменения кода в рамках reverse engineering.

**Consequences:** До исправления флага UI и потребители, зависящие от `dnsLeakDetected`, могут не показать DNS-утечку как утечку. Деталь расхождения остаётся доступной в результате и журнале.
