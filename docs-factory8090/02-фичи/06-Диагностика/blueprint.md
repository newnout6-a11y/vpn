# Диагностика

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/5baba2e5-3ca5-4fa3-bf3d-eab4cb6ed8f7

## Feature Summary

Диагностика объединяет сведения о состоянии приложения, туннеля, прокси, DNS, маршрутах, сетевых адаптерах, правилах защиты и результатах проверок, чтобы пользователь и поддержка могли определить причину неработающего соединения или признаки утечки. Реализация относится к Electron-приложению для Windows и включает структурированный журнал событий, снимки состояния, диагностический архив и, при наличии данных, нормализованные материалы форензики трафика.

Этот блюпринт реализует REQ-DIAG-001–REQ-DIAG-003. Специализированные сценарии дочерних фич «Проверка утечек и маршрутов», «Экспорт диагностики и журналы», «Форензика трафика» и «Обслуживание» здесь только подключаются по назначению и не раскрываются повторно.

## Component Blueprint Composition

Общая реализация собрана из компонентов внутри Electron main process и renderer process. Отдельные компонентные блюпринты для этой области в проекте не обнаружены.

* `runSystemDiagnostics` собирает результаты проверки состояния приложения, TUN, прокси, Windows-сети, процессов, endpoint-проверок, журналов событий, smart-route и форензики.
* `logEvent` записывает события в JSONL, сериализует записи через очередь, выполняет redaction топологии и чувствительных значений и ограничивает файл ротацией.
* `exportDiagnosticsZip` формирует ZIP через временный каталог и PowerShell `Compress-Archive`, включая настройки, журналы, системные сведения, runtime-файлы, манифесты, снимки и нормализованные материалы форензики.
* `createForensicsRedactor` применяет устойчивые псевдонимы к адресам, MAC и именам хостов в рамках одного экспорта, чтобы сохранить связи между событиями без передачи исходных значений.

## Feature-Specific Components

### Main process

```component
name: AppLogger
container: Electron main process
responsibilities:
	- Записывает события приложения в JSONL через последовательную очередь.
	- Ограничивает app.log размером 5 MiB и хранит одну предыдущую генерацию app.prev.log.
	- Применяет redaction секретов, топологии, IP-адресов, MAC-адресов и чувствительного текста перед записью и чтением журналов.
```

```component
name: SystemDiagnostics
container: Electron main process
responsibilities:
	- Запускает параллельную проверку состояния приложения и Windows-сети.
	- Возвращает общий статус и элементы результатов по областям App, TUN, Proxy, Network, Internet, Routing и связанным областям.
	- Исключает или маскирует чувствительные значения в диагностических деталях.
```

```component
name: DiagnosticsExport
container: Electron main process
responsibilities:
	- Собирает диагностические файлы во временный каталог и создаёт ZIP после выбора пути пользователем.
	- Обрабатывает настройки, журналы, runtime JSON, снимки, манифесты и материалы форензики перед упаковкой.
	- Исключает raw-пакетные захваты, поскольку их payload нельзя безопасно редактировать.
```

```component
name: LeakDiagnostics
container: Electron main process
responsibilities:
	- Предоставляет сведения для проверки публичных IP, DNS, VPN-подобных адаптеров и сетевого состояния.
	- Передаёт события проверки утечки в подсистему форензики.
```

```component
name: LeakSelfTest
container: Electron main process, Electron renderer process
responsibilities:
	- Проверяет доступ физического адаптера наружу и сравнивает внешний IP по маршрутам.
	- Возвращает результат, пригодный для явного отображения признака утечки.
```

```component
name: RoutingSelfTest
container: Electron main process, Electron renderer process
responsibilities:
	- Сравнивает VPN- и direct-выходы и формирует verdict о работе маршрутизации.
	- Учитывает отдельную проверку Smart-RU, когда она включена.
```

```component
name: SystemSnapshot
container: Electron main process
responsibilities:
	- Сохраняет снимки сетевого и системного состояния при старте приложения, операциях TUN, периодически, вручную и при обнаружении утечки.
	- Ограничивает количество сохраняемых снимков и сохраняет ошибки отдельных секций как часть снимка.
```

```component
name: TrafficForensics
container: Electron main process
responsibilities:
	- Управляет сессиями глубокого сбора сетевых событий через pktmon или netsh и связанный sidecar.
	- Формирует нормализованные материалы и сводку с verdicts, счётчиками, timeline, flow, DNS, drop и TCP health данными.
	- Передаёт материалы экспорту после redaction и исключает raw-пакетные захваты из ZIP.
```

```component
name: DiagnosticsCard
container: Electron renderer process
responsibilities:
	- Показывает состояние диагностики и результаты активной проверки утечки.
	- Запускает проверку, перезапуск форензики, экспорт архива и открытие папки снимков через Electron API.
```

### Renderer surfaces

`Logs` предоставляет просмотр и фильтрацию истории соединений и сырых записей журнала, включая копирование диагностического представления записи. `Maintenance` показывает результаты health-check и действия восстановления; страница доступна только в расширенном режиме. Эти поверхности относятся к родительской диагностике как пользовательские точки доступа, а детальные правила дочерней фичи «Обслуживание» здесь не определяются.

Вспомогательные скрипты `diag/install.ps1`, `diag/run-test.ps1`, `diag/summary.ps1`, `diag/tail-log.ps1`, `diag/detect-tun.js` и связанные файлы являются инструментом разработчика. Они не являются пользовательской фичей и считаются устаревшим вспомогательным контуром, связанным с F-170–F-172.

## System Contracts

### Key Contracts

* `logEvent` сериализует запись через очередь. Ошибка записи не должна останавливать основную работу приложения.
* `app.log` ротируется при превышении 5 MiB. После ротации сохраняется максимум одна предыдущая генерация.
* Запись, чтение и экспорт журналов должны применять redaction. Redaction топологии заменяет IP, IPv6 и MAC, а ключи и значения, распознаваемые как чувствительные, маскируются.
* Диагностический архив должен проходить обработку настроек, журналов, runtime JSON, снимков и форензики до упаковки. Секреты не должны попадать в ZIP.
* Форензика сохраняет корреляцию событий через стабильные псевдонимы в пределах одного экспорта. Сырые ETL, pcapng и pktmon-trace не включаются в архив.
* Диагностические проверки возвращают отдельные статусы и общий статус. Невыполненная или ошибочная проверка не должна отображаться как успешная.

### Integration Contracts

* Renderer вызывает main process через `window.electronAPI` для запуска диагностики, проверки утечки, проверки маршрутизации, получения статуса форензики, экспорта и операций с журналами и снимками.
* `SystemDiagnosticResult` содержит время запуска, общий `summary` и массив `SystemDiagnosticItem` с категорией, статусом, значением и дополнительными деталями.
* `LeakSelfTestResult` содержит признаки доступа физического адаптера, несовпадения публичного IP, результаты по адаптерам и краткий verdict.
* `TrafficForensicsSummaryManifest` описывает версию схемы, сессию, движок, состояние, артефакты, sidecar и ошибки разбора.
* Архив содержит `diagnostics-manifest.json`, настройки, журналы, системную информацию, системную диагностику, runtime-файлы, манифесты, снимки и каталог нормализованной форензики, если её сбор выполнен.

## Architecture Decision Records

### ADR-001: Сохранять полезность диагностики при redaction

**Context:** Пользователь и поддержка должны связывать DNS, соединение, сброс и блокировку, но исходные адреса, имена хостов и сетевые идентификаторы могут раскрывать чувствительную информацию. Документы заявляют, что секреты не попадают в ZIP, однако F-004 фиксирует конфликт: код диагностического архива может включать нередактированные значения прокси из системной диагностики (`diagnosticsExport.ts:127-137`, `systemDiagnostics.ts:314-354`).

**Decision:** Использовать redaction для секретов и устойчивую псевдонимизацию для материалов форензики. Сохранять классы адресов и публичный суффикс домена только там, где это нужно для анализа утечек и split-routing. Прокси-настройки, IP-адреса и имена адаптеров остаются предметом открытого вопроса до согласования допустимого состава архива.

**Consequences:** Аналитическая связь между событиями сохраняется без передачи исходных адресов в форензике. При этом текущая реализация требует проверки и исправления пути системной диагностики, чтобы правило «секреты не попадают в диагностику» применялось ко всем данным архива.

### ADR-002: Не включать dev-скрипты в пользовательский контур

**Context:** В каталоге `diag/` есть PowerShell и JavaScript-скрипты для установки, запуска теста, сводки и просмотра журналов. Находки F-170–F-172 классифицируют их как устаревшие инструменты разработчика.

**Decision:** Описывать `diag/*` только как вспомогательный инструмент разработчика. Пользовательские требования и пользовательские API диагностики строятся вокруг main process и renderer surfaces.

**Consequences:** Старые скрипты не расширяют пользовательскую фичу и не определяют её поведение. Их состояние следует учитывать отдельно при техническом обслуживании проекта.
