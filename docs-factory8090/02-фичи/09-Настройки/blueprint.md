# Настройки

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/13f9bb36-2b19-4672-8824-a905be2c406b

## Feature Summary

Фича реализует страницу «Настройки» в Electron-клиенте VPN Tunnel Enforcer. Страница группирует параметры подключения и защиты, поддерживает локальный черновик с явным сохранением и предоставляет расширенный режим через параметр `advancedMode`. Технический путь покрывает REQ-SET-001–REQ-SET-004 из требований «Настройки».

## Component Blueprint Composition

Фича не ссылается на другие blueprints. Она отделяет собственную страницу настроек от функций «Маршрутизация» и «Защита от утечек», которые владеют DNS, маршрутизацией и kill-switch.

## Feature-Specific Components

### Хранилище и нормализация

```component
name: SettingsStore
container: Electron Main Process
responsibilities:
	- Хранит объект `AppSettings` в локальном `electron-store` с именем settings.
	- Объединяет сохранённые значения с defaults при чтении и перед сохранением.
	- Нормализует перечисления, строки, числовые диапазоны, булевы флаги и кэшированные VPN-профили.
	- Обновляет Windows login item при изменении `autoStart` и обеспечивает задачу boot recovery.
```

### Страница настроек

```component
name: SettingsPage
container: Electron Renderer Process
responsibilities:
	- Показывает страницу «Настройки» и её разделы языка, темы, подключения и защиты.
	- Ведёт `draft` и `baseline`, вычисляет изменённые ключи и состояние несохранённых изменений.
	- Сохраняет общий черновик только после явного нажатия «Сохранить».
	- Восстанавливает черновик из последнего сохранённого состояния при сбросе.
	- Управляет видимостью расширенных параметров по `advancedMode` и открывает страницу «Обслуживание».
	- Вызывает отдельно применяемые операции для разделов, которые сохраняются вне общего черновика.
```

`#SettingsPage` передаёт полный черновик через IPC в `#SettingsStore`. `#SettingsStore` возвращает нормализованный `AppSettings`, после чего страница заменяет им локальные `draft` и `baseline`.

## System Contracts

### Key Contracts

* `AppSettings` является общей формой настроек между main process и renderer process.
* При чтении и сохранении отсутствующие или некорректные значения проходят нормализацию. Текущие проверенные значения включают `connectionMode` (`localProxy` или `directVpn`), `routingMode` (`hard` или `soft`), `proxyType` (`socks5` или `http`), `bootstrapRouteMode`, `proxyEngine`, ограничение `checkInterval` от 5000 до 300000 мс и ограничение Smart-RU интервала от 1 до 720 часов.
* В модели `defaults` значение `firewallKillSwitch` равно `false`, `advancedMode` равно `false`, а `firstRunComplete` равно `false`. Реализация нормализации сейчас обрабатывает `firewallKillSwitch` как включённый при отсутствии явного `false`, что создаёт расхождение, зафиксированное открытым вопросом в требованиях.
* Изменения общего раздела остаются в `#SettingsPage` до вызова `saveSettings(draft)`. Успешный вызов возвращает нормализованный результат, который становится новым `draft` и `baseline`.
* Ошибка общего сохранения оставляет черновик в renderer и показывает сообщение об ошибке.
* Отдельно применяемые операции могут вызывать `saveSettings` немедленно и синхронизировать только изменённое поле с черновиком и базовым состоянием.

### Integration Contracts

* `#SettingsPage` использует `window.electronAPI.saveSettings` для передачи полного или частичного `AppSettings` в main process.
* `#SettingsStore` использует `electron-store` с именем `settings` как локальное хранилище.
* `#SettingsPage` вызывает `navigateTo('maintenance')` для перехода к странице «Обслуживание» из расширенного режима.
* Функции «Маршрутизация» и «Защита от утечек» остаются внешними владельцами соответствующих DNS, маршрутизационных и kill-switch операций.

## Architecture Decision Records

### ADR-001: Черновик и явное сохранение

**Context:** В `Settings.tsx` реализованы `draft`, `baseline`, dirty tracking и кнопка «Сохранить». README описывает auto-save с debounce 1,5 секунды, а код сохраняет общий черновик по кнопке. При этом отдельные операции уведомлений и kill-switch применяются сразу.

**Decision:** Зафиксировать в blueprint фактически реализованную модель: общий черновик сохраняется по кнопке, а отдельно применяемые разделы могут сохраняться немедленно. Выбор между этой моделью и auto-save требует продуктового решения.

**Consequences:** Документ отражает код и сохраняет конфликт как открытый вопрос. После решения потребуется синхронно обновить требования, blueprint и документацию.

### ADR-002: Значение kill-switch по умолчанию

**Context:** `settings.ts` задаёт `firewallKillSwitch: false` в `defaults`, но нормализация использует `merged.firewallKillSwitch !== false`, поэтому отсутствующее поле после слияния с defaults становится включённым.

**Decision:** В blueprint фиксируется проверенное расхождение без выбора нового поведения. Правильное значение по умолчанию должно быть подтверждено владельцем продукта.

**Consequences:** Реализованное и документированное поведение нельзя считать согласованным до решения по F-146.
