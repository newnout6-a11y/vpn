# Импорт и экспорт конфигурации

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/5d4a4dbf-1d7b-4597-89e7-fca858918f43

## Feature Summary

Функция сохраняет текущую конфигурацию VPN Tunnel Enforcer в JSON-файл версии `2.0` и восстанавливает выбранные разделы из файла. Она выполняет проверку формата, показывает доступные разделы и конфликты, а затем применяет данные в режиме замены или слияния. Реализация покрывает REQ-SET-CFG-001, REQ-SET-CFG-002 и REQ-SET-CFG-003.

## Component Blueprint Composition

Функция использует IPC-границу Electron для вызова операций между renderer и main process. `#ConfigManager` собирает данные из хранилищ, проверяет импорт, определяет конфликты и записывает выбранные разделы. `#ImportExportSettings` предоставляет в странице настроек действия экспорта и импорта, выбор разделов, отображение конфликтов и выбор режима применения.

## Feature-Specific Components

### Main process

```component
name: ConfigManager
container: Electron Main Process
responsibilities:
	- Собирает профили, группы серверов, расписания, split tunneling, DNS, доменные правила, темы, ротацию, kill-switch и уведомления в `ConfigExportData`.
	- Записывает экспорт в выбранный JSON-файл.
	- Проверяет версию `2.0`, наличие распознанных разделов и верхнеуровневые типы входных значений.
	- Определяет конфликты и применяет выбранные разделы в режимах `replace` и `merge`.
	- Восстанавливает активный DNS-профиль только при наличии его идентификатора среди записанных профилей.
	- Регистрирует IPC-каналы `config:export`, `config:import`, `config:import-apply` и `config:browse-import`.
```

### Renderer

```component
name: ImportExportSettings
container: Electron Renderer
responsibilities:
	- Показывает действия экспорта и импорта внутри страницы `Settings`.
	- Запрашивает выбор JSON-файла и отображает результат проверки.
	- Позволяет выбрать разделы импорта и режим `replace` или `merge`.
	- Показывает ошибки и состояния успешного экспорта или импорта.
```

`#ImportExportSettings` передаёт выбранный путь, разделы и режим через preload API в `#ConfigManager`. До применения импорт остаётся только результатом проверки, поэтому пользователь может отменить операцию.

## System Contracts

### Key Contracts

* `ConfigExportData` содержит версию `2.0`, отметку времени экспорта и поддерживаемые разделы конфигурации.
* Экспорт записывает `outbound` и `sourceUri` профилей VPN в открытом виде. Маскировка этих значений отсутствует.
* Проверка импорта принимает JSON-объект только с версией `2.0` и хотя бы одним распознанным разделом.
* Проверка разделяет массивные разделы и объектные разделы по верхнеуровневому типу, но не проверяет вложенные значения по схеме.
* В режиме `replace` входящий массив полностью заменяет выбранный раздел. В режиме `merge` элементы объединяются по `id`, при совпадении входящий элемент имеет приоритет.
* Если запись раздела завершается ошибкой, `ConfigManager` пытается записать снимок состояния до импорта для выбранных разделов. Такая последовательная запись не гарантирует атомарность.
* После применения `schedules`, `rotation` или `killSwitch` выполняется best-effort обновление соответствующего активного состояния.

## Integration Contracts

* `config:export` запускает экспорт и возвращает результат с признаком успеха, путём или ошибкой.
* `config:browse-import` открывает выбор JSON-файла и возвращает путь либо `null` при отмене.
* `config:import` принимает путь к файлу и возвращает признак успеха, доступные разделы, конфликты и ошибку при отказе.
* `config:import-apply` принимает путь, список разделов и `conflictResolution` со значением `replace` или `merge`, затем возвращает результат применения.
* `ConfigManager` читает и записывает данные через отдельные хранилища профилей, групп серверов, расписаний, split tunneling, DNS, маршрутизации доменов, тем, ротации, kill-switch и уведомлений.

## Architecture Decision Records

### ADR-001: JSON-файл с выборочным применением разделов

**Context:** Пользователю требуется переносить полную конфигурацию, но применять только часть данных и явно разрешать конфликты между текущим и входящим состоянием.

**Decision:** Хранить экспорт в одном JSON-файле версии `2.0`. Перед записью выполнять проверку файла, показывать доступные разделы и конфликты, а применение выполнять только для выбранных разделов в режиме замены или слияния.

**Consequences:** Пользователь получает контроль над составом импорта и разрешением конфликтов. Формат содержит чувствительные данные открытым текстом, а вложенная валидация и атомарность остаются ограничениями текущей реализации.

### ADR-002: Открытые решения по защите и частично неверному импорту

**Context:** Текущая реализация экспортирует секреты без защиты, а проверка импортируемого файла не определяет поведение для частично неверных вложенных данных.

**Decision:** Решение о парольном шифровании или другой защите файла, а также политика обработки частично неверного файла не фиксируются до ответа владельца продукта.

**Consequences:** Нельзя считать экспорт защищённым от раскрытия ключей. Нельзя считать поведение частично неверного импорта согласованным для всех вложенных элементов.
