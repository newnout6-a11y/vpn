# Автозапуск

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/4100045c-ec80-4135-9c9e-b36635e5fc3d

## Feature Summary

Функция связывает настройки поведения приложения при запуске с Windows и пользовательскими параметрами `autoStart`, `autoPilotEnabled` и `minimizeToTray`. В Windows упакованная версия регистрирует запуск через планировщик задач с повышенным уровнем выполнения; стандартный Electron login item на этой платформе принудительно отключается.

При синхронизации настроек функция также один раз за процесс обеспечивает задачу `VPNTE Boot Recovery`. Эта задача относится к подготовке восстановления сетевого состояния и не описывает его логику. Пользовательское автоподключение VPN при старте не подтверждено отдельным вызовом в проверенных местах кода.

## Component Blueprint Composition

* **`settings.ts`** — хранит и нормализует параметры `autoStart`, `autoPilotEnabled` и `minimizeToTray`, применяет изменения автозапуска и синхронизирует задачи Windows.
* **`index.ts`** — вызывает синхронизацию login item при готовности приложения, регистрирует IPC для изменения автозапуска и управляет окном и областью уведомлений.
* **`Settings.tsx`** — предоставляет переключатели автозапуска, сворачивания в трей и автопилота маршрута.

## Feature-Specific Components

```component
name: LoginItemSynchronizer
container: Electron main process
responsibilities:
	- Нормализует значение `autoStart` и сохраняет его в `electron-store` через #SettingsStore.
	- В упакованном Windows-приложении формирует команду планировщика задач для входа пользователя с уровнем выполнения HIGHEST.
	- Вызывает `app.setLoginItemSettings` с `openAtLogin: false` на Windows и с `openAtLogin: autoStart` на других платформах.
	- Подавляет ошибки выполнения команд планировщика.
```

```component
name: SettingsStore
container: Electron main process
responsibilities:
	- Хранит `autoStart`, `autoPilotEnabled` и `minimizeToTray` со значениями по умолчанию false, true и true соответственно.
	- Применяет синхронизацию login item только при изменении `autoStart`, при явной установке login item или при старте приложения.
	- Один раз за процесс инициирует регистрацию `VPNTE Boot Recovery` независимо от значения `autoStart`.
```

`#SettingsStore` передаёт нормализованное состояние `autoStart` в `#LoginItemSynchronizer`. При изменении настройки через renderer IPC применяется то же состояние, поэтому сохранение и системная регистрация используют один источник значения.

## System Contracts

### Key Contracts

* `autoStart` по умолчанию равен false, `autoPilotEnabled` по умолчанию равен true, `minimizeToTray` по умолчанию равен true.
* В упакованной Windows-версии задача запуска называется `VPN Tunnel Enforcer`, использует расписание `ONLOGON`, уровень `HIGHEST` и принудительно заменяется при создании или удалении.
* Синхронизация login item при готовности приложения запускается независимо от того, изменялись ли другие настройки.
* Регистрация `VPNTE Boot Recovery` выполняется не более одного раза за процесс. Ошибка каждой команды планировщика подавляется через обработчик отклонённого Promise.
* Техническая задача `VPNTE Boot Recovery` не дублирует требования и реализацию функции «Восстановление сети после сбоя».

### Integration Contracts

* Renderer вызывает IPC-операцию `set-login-item` с булевым значением, а main process передаёт это значение в `settingsStore.setLoginItem`.
* `settingsStore.syncLoginItem` вызывается в обработчике `app.whenReady` до создания главного окна.
* `Settings.tsx` сохраняет переключатели `autoStart`, `minimizeToTray` и `autoPilotEnabled` через общий обработчик настроек.
* Проверенные места кода не подтверждают, что `autoPilotEnabled` сам по себе запускает VPN-защиту при старте приложения.

## Architecture Decision Records

### ADR-001: Использовать планировщик задач Windows для запуска упакованного приложения

**Context:** Упакованное Windows-приложение должно запускаться при входе пользователя с повышенными правами, а стандартная настройка Electron login item не должна одновременно создавать второй механизм запуска.

**Decision:** Для Windows приложение отключает `app.setLoginItemSettings` через `openAtLogin: false` и выполняет повышенную команду `schtasks` для задачи `VPN Tunnel Enforcer`. На других платформах используется стандартный Electron login item.

**Consequences:** Windows получает один контролируемый механизм запуска с требуемым уровнем выполнения. Ошибки команды не передаются вызывающему коду, поэтому факт успешной регистрации задачи не подтверждается интерфейсом.

### ADR-002: Регистрировать задачу восстановления отдельно от автозапуска приложения

**Context:** Восстановление сетевого состояния после аварийного завершения должно быть доступно независимо от пользовательского выбора автозапуска приложения.

**Decision:** При синхронизации login item отдельно обеспечивается задача `VPNTE Boot Recovery` с запуском при старте Windows от имени SYSTEM. Её создание ограничено одним вызовом за процесс.

**Consequences:** Задача восстановления не зависит от `autoStart`, но её ошибка подавляется. Детали восстановления остаются во фиче «Восстановление сети после сбоя».
