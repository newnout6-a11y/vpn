# Доменные правила

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/requirements/3906696e-7977-4f33-bc24-088e7b5480ca

## Обзор

«Доменные правила» позволяют пользователю управлять направлением сетевого трафика по имени домена. Пользователь может добавить доменное правило, выбрать для совпавшего трафика прямой маршрут, маршрут через VPN или блокировку, изменить порядок правил и импортировать список доменов из текстового файла. Правила дополняют базовый маршрут функции «Маршрутизация» и позволяют точечно управлять исключениями без изменения профиля VPN.

При совпадении нескольких правил результат определяется их приоритетом. Точные доменные шаблоны и шаблоны поддоменов имеют различное назначение: точное имя домена должно соответствовать самому домену, а шаблон `*.example.com` предназначен для поддоменов. Изменение сохранённого правила применяется к активному подключению через перезапуск защиты, если подключение запущено; при невозможности такого применения правило сохраняется для следующего подключения.

Фактическая реализация в коде включает действие «блокировать», хотя родительская документация описывает только исключения из базового маршрута. Это действие включено в область данной фичи, потому что оно доступно в пользовательском интерфейсе и преобразуется в отклонение трафика при генерации конфигурации.

## Терминология

* **Доменное правило**: сохранённое условие по доменному имени и назначенное ему действие маршрутизации.
* **Шаблон домена**: введённое пользователем доменное имя, поддоменный шаблон или ключевое слово для сопоставления.
* **Точное доменное имя**: шаблон с доменной частью, который соответствует указанному домену и его поддоменам в текущем сопоставлении приложения.
* **Шаблон поддоменов**: шаблон вида `*.example.com`, который соответствует поддоменам базового домена и не соответствует самому базовому домену.
* **Действие доменного правила**: одно из направлений «через VPN», «напрямую» или «блокировать».
* **Приоритет доменного правила**: положение правила в порядке проверки; меньшее числовое значение означает более высокий приоритет.
* **Список доменов**: текстовый файл, содержащий доменные шаблоны по одному на строку.
* **Счётчик срабатываний**: отображаемое число совпадений доменного правила в текущем сеансе приложения.
* **Обогащение доменов Chromium**: отдельная настройка, которая получает название и описание HTTPS-страницы для домена и не закрепляет IP-адрес назначения.

## Требования

### REQ-ROUTE-DOM-001: Просмотр и создание доменных правил

**Пользовательская история:** Как пользователь VPN, я хочу просматривать и добавлять доменные правила, чтобы управлять маршрутом выбранных доменов.

**Критерии приёмки:**

* **AC-ROUTE-DOM-001.1:** При открытии раздела доменных правил система должна показать сохранённые доменные правила в порядке их приоритета.
* **AC-ROUTE-DOM-001.2:** Когда пользователь добавляет доменное правило с непустым шаблоном, система должна сохранить его с выбранным действием и приоритетом.
* **AC-ROUTE-DOM-001.3:** Если пользователь вводит пустой или недопустимый шаблон, система не должна сохранять правило и должна сообщить об ошибке.
* **AC-ROUTE-DOM-001.4:** Новое правило по умолчанию должно использовать действие «через VPN», если пользователь не выбрал другое действие.

### REQ-ROUTE-DOM-002: Сопоставление доменов и действия

**Пользовательская история:** Как пользователь VPN, я хочу, чтобы совпавший домен получал действие своего правила, чтобы трафик шёл по выбранному направлению.

**Критерии приёмки:**

* **AC-ROUTE-DOM-002.1:** Когда домен совпадает с правилом действия «напрямую», система должна направить его через прямой выход вместо VPN.
* **AC-ROUTE-DOM-002.2:** Когда домен совпадает с правилом действия «через VPN», система должна направить его через VPN-выход.
* **AC-ROUTE-DOM-002.3:** Когда домен совпадает с правилом действия «блокировать», система должна отклонить трафик.
* **AC-ROUTE-DOM-002.4:** Когда используется шаблон поддоменов `*.example.com`, система должна сопоставить поддомен `sub.example.com` и не должна сопоставить сам домен `example.com`.
* **AC-ROUTE-DOM-002.5:** Когда используется доменное имя с точкой, система должна учитывать совпадение указанного домена и его поддоменов согласно текущему поведению приложения.
* **AC-ROUTE-DOM-002.6:** Когда шаблон не содержит точки и не является шаблоном поддоменов, система должна искать его как ключевое слово домена.
* **AC-ROUTE-DOM-002.7:** Когда домен совпадает с несколькими правилами, система должна применить правило с более высоким приоритетом.
* **AC-ROUTE-DOM-002.8:** Когда домен не совпадает ни с одним правилом, система должна передать обработку базовому маршруту функции «Маршрутизация».

### REQ-ROUTE-DOM-003: Изменение и удаление правил

**Пользовательская история:** Как пользователь VPN, я хочу изменять, удалять и менять порядок доменных правил, чтобы поддерживать нужные исключения.

**Критерии приёмки:**

* **AC-ROUTE-DOM-003.1:** Когда пользователь изменяет шаблон или действие правила, система должна сохранить изменение для этого правила.
* **AC-ROUTE-DOM-003.2:** Когда пользователь удаляет правило, система не должна применять его к последующим конфигурациям VPN.
* **AC-ROUTE-DOM-003.3:** Когда пользователь меняет порядок правил, система должна переназначить приоритеты в новом порядке.
* **AC-ROUTE-DOM-003.4:** Если правило удалено, система не должна сохранять его счётчик срабатываний в текущем сеансе.

### REQ-ROUTE-DOM-004: Импорт списка доменов

**Пользовательская история:** Как пользователь VPN, я хочу импортировать список доменов из файла, чтобы быстро создать несколько правил.

**Критерии приёмки:**

* **AC-ROUTE-DOM-004.1:** Когда пользователь выбирает текстовый файл для импорта, система должна добавить по одному доменному правилу для каждой непустой строки.
* **AC-ROUTE-DOM-004.2:** При импорте система должна убрать пробелы по краям строки и пропустить пустые строки.
* **AC-ROUTE-DOM-004.3:** Импортированные правила должны получить действие «напрямую», если для них не задано другое действие.
* **AC-ROUTE-DOM-004.4:** Импортированные правила должны получить приоритеты после уже сохранённых правил.

### REQ-ROUTE-DOM-005: Применение изменений и отображение состояния

**Пользовательская история:** Как пользователь VPN, я хочу понимать, когда изменения доменных правил вступили в силу, чтобы не ошибиться в ожидаемом маршруте.

**Критерии приёмки:**

* **AC-ROUTE-DOM-005.1:** Когда пользователь добавляет, изменяет, удаляет или переупорядочивает правило при активном VPN, система должна попытаться применить обновлённые правила к активному подключению.
* **AC-ROUTE-DOM-005.2:** Если применение к активному подключению не удалось, система должна сохранить изменение для следующего подключения и записать предупреждение об ошибке применения.
* **AC-ROUTE-DOM-005.3:** Если VPN не активен, система должна сохранить изменение для применения при следующем подключении.
* **AC-ROUTE-DOM-005.4:** Счётчик срабатываний должен отображаться как состояние текущего сеанса, но система не должна обещать его увеличение, если источник фактических совпадений недоступен.

### REQ-ROUTE-DOM-006: Обогащение доменов Chromium

**Пользовательская история:** Как пользователь VPN, я хочу получать сведения о посещаемом домене, чтобы понимать назначение сетевого соединения.

**Критерии приёмки:**

* **AC-ROUTE-DOM-006.1:** Где включено обогащение доменов Chromium, система должна получать название и описание HTTPS-страницы домена через активное VPN-подключение.
* **AC-ROUTE-DOM-006.2:** Система должна хранить результаты обогащения локально.
* **AC-ROUTE-DOM-006.3:** Если VPN недоступен, система не должна выполнять новые запросы обогащения.
* **AC-ROUTE-DOM-006.4:** Обогащение домена не должно закреплять IP-адрес назначения за доменным именем.
