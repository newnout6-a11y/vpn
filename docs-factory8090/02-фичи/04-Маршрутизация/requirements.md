# Маршрутизация

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/requirements/987604d8-f8a3-4f8e-8e9c-4795a77f8d40

## Обзор

Функция «Маршрутизация» задаёт безопасное поведение сетевого трафика VPN Tunnel Enforcer: по умолчанию весь трафик направляется через VPN, а пользователь может определить исключения для отдельных процессов и доменов. Порядок правил определяет, какое исключение имеет приоритет, при этом базовый маршрут через VPN остаётся конечным правилом для трафика без совпадения.

Изменения набора правил должны применяться при следующем подключении. Если приложение поддерживает live-apply для текущего подключения, пользователь может применить изменения без переподключения. Набор правил имеет локальную копию, чтобы работа основного туннеля не зависела от доступности удалённых наборов правил.

Детализированные сценарии вынесены в дочерние фичи: «Smart RU», «Доменные правила», «Раздельное туннелирование приложений» и «DNS-профили».

## Терминология

* **Маршрутизация**: выбор направления для каждого сетевого потока внутри VPN Tunnel Enforcer.
* **Правило маршрутизации**: условие и назначенное ему направление трафика.
* **Набор правил**: локально сохранённая совокупность правил маршрутизации, используемая при построении конфигурации подключения.
* **Исключение**: правило, которое направляет совпавший трафик не по базовому маршруту через VPN.
* **Базовый маршрут**: направление через VPN, применяемое к трафику, который не совпал с исключением.
* **Приоритет правил**: порядок проверки правил, определяющий результат при совпадении нескольких правил.
* **Следующее подключение**: ближайший запуск VPN после сохранения изменения правил.
* **Live-apply**: применение изменения набора правил к активному VPN-подключению без его полного переподключения.
* **Smart RU**: дочерняя фича для отдельных правил маршрутизации российских назначений; подробности определяются документом дочерней фичи.
* **Доменные правила**: дочерняя фича для пользовательских правил по доменам; подробности определяются документом дочерней фичи.
* **Раздельное туннелирование приложений**: дочерняя фича для исключений по приложениям; подробности определяются документом дочерней фичи.
* **DNS-профили**: дочерняя фича для выбора DNS-поведения; подробности определяются документом дочерней фичи.

## Требования

### REQ-ROUTE-001: Базовый маршрут через VPN

**Пользовательская история:** Как пользователь VPN, я хочу, чтобы трафик по умолчанию шёл через VPN, чтобы соединения без явного исключения не выходили напрямую.

**Критерии приёмки:**

* **AC-ROUTE-001.1:** По умолчанию система должна направлять трафик через VPN.
* **AC-ROUTE-001.2:** Если трафик не совпал ни с одним исключением, система должна направлять его через VPN.
* **AC-ROUTE-001.3:** Если набор правил недоступен или не может быть загружен, система должна сохранять возможность запустить основной VPN-туннель без зависимости от удалённого набора правил.

### REQ-ROUTE-002: Исключения из базового маршрута

**Пользовательская история:** Как пользователь VPN, я хочу задавать исключения из маршрута через VPN, чтобы выбранный трафик имел другое направление.

**Критерии приёмки:**

* **AC-ROUTE-002.1:** Когда пользователь задаёт исключение, система должна сохранять его в наборе правил маршрутизации.
* **AC-ROUTE-002.2:** Когда трафик соответствует исключению, система должна направлять его согласно этому исключению вместо базового маршрута.
* **AC-ROUTE-002.3:** Когда исключений нет, система должна использовать только базовый маршрут через VPN.

### REQ-ROUTE-003: Приоритет правил

**Пользовательская история:** Как пользователь VPN, я хочу, чтобы правила проверялись в определённом порядке, чтобы результат при совпадении нескольких правил был предсказуемым.

**Критерии приёмки:**

* **AC-ROUTE-003.1:** Когда трафик соответствует нескольким правилам, система должна применить правило с более высоким приоритетом.
* **AC-ROUTE-003.2:** Система должна применять базовый маршрут после всех правил исключений.
* **AC-ROUTE-003.3:** Изменение приоритета правила должно изменять порядок, в котором система проверяет правила при следующем применении набора правил.

### REQ-ROUTE-004: Применение изменений

**Пользовательская история:** Как пользователь VPN, я хочу выбрать момент применения изменений маршрутизации, чтобы управлять влиянием изменений на активное подключение.

**Критерии приёмки:**

* **AC-ROUTE-004.1:** После сохранения изменения набора правил система должна применить его не позднее следующего подключения.
* **AC-ROUTE-004.2:** Если live-apply доступен для активного подключения, система должна применить выбранное изменение без полного переподключения.
* **AC-ROUTE-004.3:** Если live-apply недоступен или не подтверждён для изменения, система должна сохранить изменение для следующего подключения.

### REQ-ROUTE-005: Локальная копия набора правил

**Пользовательская история:** Как пользователь VPN, я хочу, чтобы набор правил имел локальную копию, чтобы удалённая ошибка обновления не останавливала основной туннель.

**Критерии приёмки:**

* **AC-ROUTE-005.1:** Система должна хранить локальную копию набора правил для использования при построении подключения.
* **AC-ROUTE-005.2:** Когда удалённый набор правил недоступен, система должна использовать доступную локальную копию.
* **AC-ROUTE-005.3:** Ошибка обновления набора правил не должна сама по себе препятствовать запуску основного VPN-туннеля.
