# Раздельное туннелирование приложений

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/8f8a0138-46b2-4662-bea9-dcd876461485

## Feature Summary

Функция `splitTunnel` в контейнере Electron Client App управляет маршрутами для записей приложений и команд. Она связывает интерфейс `SplitTunnel` с главным процессом через IPC, сохраняет локальный `SplitTunnelConfig` и формирует правила маршрутизации sing-box: записи с прямым маршрутом получают `direct-out`, остальные используют базовый маршрут через VPN. Функция реализует REQ-ROUTE-APP-001–006.

Взаимодействие с @Kill-switch и исключения ограничено отдельным списком исключений приложений. Прямой маршрут сам по себе не добавляет приложение в исключения kill-switch. Это отражает границу ответственности и REQ-ROUTE-APP-007.

## Component Blueprint Composition

* `@Маршрутизация` предоставляет базовый маршрут через VPN и порядок применения правил. `#SplitTunnelService` добавляет правила по процессам перед базовым маршрутом.
* `@Kill-switch и исключения` предоставляет политику разрешённых путей приложений при активной блокировке. `#GranularKillSwitch` читает отдельные исключения приложений и передаёт их в `firewallKillSwitch`; записи split tunneling не синхронизируются с этим списком автоматически.

## Feature-Specific Components

### Интерфейс и IPC

```component
name: SplitTunnelPage
container: Electron Client App
responsibilities:
	- Отображает локальный список `SplitTunnelApp`, поиск по имени и пути, состояние пустого списка и ошибки операций.
	- Позволяет выбрать исполняемый файл, пересканировать установленные приложения, добавить имя процесса и удалить запись.
	- Изменяет правило записи через `split-tunnel:set-rule` и показывает состояние ожидания операции.
```

```component
name: SplitTunnelService
container: Electron Main Process
responsibilities:
	- Сохраняет `SplitTunnelApp[]` и признак `splitTunnelEnabled` в локальном хранилище.
	- Обнаруживает приложения через реестр Windows и `%LOCALAPPDATA%\\Programs`, удаляет дубли по пути и уважает удалённые пути.
	- Для установленных приложений нормализует полный путь (`splitTunnelPath.ts`) и формирует правило `process_path_regex` с направлением `direct-out`; для голых имён процессов формирует `process_name`.
	- Регистрирует IPC-каналы получения, обновления, изменения, добавления и удаления записей.
	- Перезапускает активный туннель после изменения или удаления правила.
```

`#SplitTunnelPage` вызывает `#SplitTunnelService` через типизированные каналы `SplitTunnelChannels`. Сервис возвращает `SplitTunnelApp` с `kind: app` для файла или `kind: process` для имени процесса; для добавленной команды сразу устанавливается правило `direct`.

### Маршрутизация и защита

```component
name: SplitTunnelRouteGenerator
container: Electron Main Process
responsibilities:
	- Читает сохранённые записи и признак включения функции.
	- Отбирает записи с правилом `direct` и нормализует их до имён Windows-процессов.
	- Создаёт массив правил sing-box: `process_path_regex` для приложений (запись пути и каноническая запись 8.3/длинная) и `process_name` для голых имён, направление `direct-out`.
	- Не создаёт специальное правило для состояний `vpn` и `none`, поэтому действует базовый маршрут.
```

```component
name: GranularKillSwitch
container: Electron Main Process
responsibilities:
	- Хранит исключения kill-switch типов `app` и `ip` отдельно от настроек split tunneling.
	- Передаёт пути приложений из списка исключений в политику `firewallKillSwitch` при включении kill-switch.
	- Применяет изменения списка исключений при следующем применении политики kill-switch.
```

`#SplitTunnelService` вызывает `tunController.restartWithLastOptions` при изменении правила активного туннеля. `#SplitTunnelRouteGenerator` передаёт правила в конфигурацию sing-box, а `#GranularKillSwitch` применяет только явно добавленные исключения приложения. Поэтому ошибка перезапуска не должна трактоваться как успешное применение.

## System Contracts

### Key Contracts

* `SplitTunnelApp` имеет уникальный `id`, имя, путь или имя процесса и правило `vpn`, `direct` или `none`.
* Добавление существующего пути приложения или имени процесса идемпотентно и не создаёт вторую запись.
* Пересканирование сохраняет идентификаторы и выбранные правила существующих записей.
* Удалённый путь приложения сохраняется как tombstone и не возвращается при последующем пересканировании.
* При выключенном `splitTunnelEnabled` генератор возвращает пустой список специальных правил.
* Для голых имён процессов (`kind: process`) совпадение по-прежнему идёт по имени. Для установленных приложений с 2026-10-13 (PR #37, F-076) применяется полный путь, поэтому копия с тем же именем в другом каталоге правилом не затрагивается; живая egress-проверка (AT-06-008) не проводилась.

### Integration Contracts

* `SplitTunnelChannels` предоставляет IPC-операции `split-tunnel:get-apps`, `split-tunnel:refresh-apps`, `split-tunnel:set-rule`, `split-tunnel:add-app`, `split-tunnel:add-process`, `split-tunnel:remove-app` и `split-tunnel:get-config`.
* `SplitTunnelRouteGenerator` выдаёт правила sing-box `process_path_regex` (приложения) и `process_name` (голые имена) с `outbound: direct-out` только для прямых маршрутов; приложение с недействительным путём правила не получает.
* `GranularKillSwitch` принимает `KillSwitchException` с типом `app`, путём и подписью; это отдельный контракт @Kill-switch и исключения.
* При активном TUN изменение правила инициирует остановку и перезапуск sing-box с обновлённой конфигурацией, поэтому возможен краткий разрыв соединения.

## Architecture Decision Records

### ADR-001: Разделять приложение и имя процесса

**Context:** Пользователь должен настраивать как установленный `.exe` с известным путём, так и CLI-команду, которая может находиться в PATH или запускаться временно. Код поддерживает оба варианта через `kind`.

**Decision:** Для приложения хранить реальный путь и проверять его доступность при добавлении. Для команды хранить нормализованное имя процесса без проверки файла и сразу задавать прямой маршрут.

**Consequences:** Настройка CLI-команд становится возможной без поиска файла. Для голых имён процессов совпадение по имени не подтверждает путь к конкретному исполняемому файлу, и риск подмены имени остаётся осознанным ограничением этого вида записи; установленные приложения (F-076) этим риском больше не затронуты.

### ADR-002: Применять изменения активного туннеля перезапуском

**Context:** sing-box не поддерживает live reload конфигурации split tunneling в используемом кодовом пути.

**Decision:** После изменения или удаления записи при работающем TUN вызывать `tunController.restartWithLastOptions` и уведомлять интерфейс о применении.

**Consequences:** Изменение не требует ручного переподключения, но может вызвать краткий разрыв и может завершиться ошибкой, если перезапуск не удался.

### ADR-003: Не объединять split tunneling с исключениями kill-switch автоматически

**Context:** Split tunneling задаёт маршрут трафика, а kill-switch определяет, какие пути разрешены при блокировке. Код хранит и применяет эти списки раздельно.

**Decision:** Прямой маршрут не добавляет запись в `killSwitchExceptions`; приложение должно быть добавлено туда явно.

**Consequences:** Поведение при активном kill-switch остаётся явным и безопаснее, но пользователю нужно отдельно настроить исключение приложения.
