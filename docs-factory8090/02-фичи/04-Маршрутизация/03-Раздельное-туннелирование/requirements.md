# Раздельное туннелирование приложений

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/requirements/60d9d3b4-31a2-4b1b-89e7-c0378f7eef89

## Обзор

Функция позволяет пользователю выбирать приложения и команды, для которых сетевой трафик должен идти напрямую, минуя VPN, либо через VPN. Это даёт пользователю контроль над маршрутом отдельных приложений при сохранении базового поведения маршрутизации через VPN для остального трафика.

Пользователь может добавить установленное приложение выбором исполняемого файла, выбрать приложение из обнаруженного списка или указать имя процесса. Для каждой записи пользователь задаёт маршрут, а изменения сохраняются локально и применяются к активному подключению с кратким перезапуском туннеля, если туннель запущен.

## Терминология

* **Приложение**: установленная программа, представленная исполняемым файлом с путём на диске.
* **Команда**: имя исполняемого процесса без привязки к конкретному пути на диске.
* **Запись маршрута приложения**: сохранённое приложение или команда с выбранным маршрутом.
* **Маршрут через VPN**: направление трафика записи через VPN.
* **Прямой маршрут**: направление трафика записи мимо VPN.
* **Без специального правила**: состояние записи, при котором для неё не создаётся отдельное правило и действует базовый маршрут.
* **Список приложений**: локально сохранённый перечень записей маршрута приложения.
* **Пересканирование**: повторный поиск установленных приложений с добавлением новых записей без изменения существующих маршрутов.
* **Исключение kill-switch**: приложение, которому разрешён трафик при активной блокировке kill-switch; подробности определяются фичей «Kill-switch и исключения».

## Требования

### REQ-ROUTE-APP-001: Просмотр и поиск приложений

**Пользовательская история:** Как пользователь VPN, я хочу видеть сохранённые приложения и команды, чтобы понимать, для каких записей настроен отдельный маршрут.

**Критерии приёмки:**

* **AC-ROUTE-APP-001.1:** Когда пользователь открывает функцию, система должна отображать сохранённые записи маршрута приложения.
* **AC-ROUTE-APP-001.2:** Система должна различать приложение и команду в списке записей.
* **AC-ROUTE-APP-001.3:** Когда пользователь вводит поисковый запрос, список должен показывать записи, у которых запрос встречается в имени, полном пути или имени исполняемого файла.
* **AC-ROUTE-APP-001.4:** Если сохранённых записей нет, система должна отображать состояние пустого списка.

### REQ-ROUTE-APP-002: Добавление приложения

**Пользовательская история:** Как пользователь VPN, я хочу добавить установленное приложение, чтобы задать для него отдельный маршрут.

**Критерии приёмки:**

* **AC-ROUTE-APP-002.1:** Когда пользователь выбирает исполняемый файл приложения, система должна добавить его в список записей с состоянием «Без специального правила».
* **AC-ROUTE-APP-002.2:** Если выбранный исполняемый файл уже есть в списке, система не должна создавать дублирующую запись.
* **AC-ROUTE-APP-002.3:** Если пользователь отменяет выбор файла, список записей не должен изменяться.
* **AC-ROUTE-APP-002.4:** Если выбранный путь не указывает на доступный исполняемый файл, система должна отклонить добавление и сообщить об ошибке.

### REQ-ROUTE-APP-003: Обнаружение и пересканирование приложений

**Пользовательская история:** Как пользователь VPN, я хочу обновить список установленных приложений, чтобы настроить маршрут для приложения, добавленного после предыдущего сканирования.

**Критерии приёмки:**

* **AC-ROUTE-APP-003.1:** Когда список приложений ещё не сохранён, система должна выполнить обнаружение установленных приложений и сохранить найденные записи.
* **AC-ROUTE-APP-003.2:** Когда пользователь запускает пересканирование, система должна добавить новые найденные приложения без изменения маршрутов существующих записей.
* **AC-ROUTE-APP-003.3:** Если пользователь удалил обнаруженное приложение из списка, пересканирование не должно автоматически добавлять его снова.
* **AC-ROUTE-APP-003.4:** Если обнаружение приложений завершается ошибкой, система должна вернуть доступный список без остановки основного VPN-туннеля.

### REQ-ROUTE-APP-004: Добавление команды по имени процесса

**Пользовательская история:** Как пользователь VPN, я хочу указать имя команды или процесса, чтобы направить его трафик напрямую даже без фиксированного пути к исполняемому файлу.

**Критерии приёмки:**

* **AC-ROUTE-APP-004.1:** Когда пользователь указывает корректное имя команды без пути, система должна добавить команду в список с прямым маршрутом.
* **AC-ROUTE-APP-004.2:** Когда пользователь указывает имя команды без расширения, система должна использовать форму имени исполняемого файла Windows.
* **AC-ROUTE-APP-004.3:** Если указанное имя команды пустое или содержит недопустимые символы, система должна отклонить добавление и сообщить об ошибке.
* **AC-ROUTE-APP-004.4:** Если команда уже есть в списке, система не должна создавать дублирующую запись.

### REQ-ROUTE-APP-005: Выбор маршрута

**Пользовательская история:** Как пользователь VPN, я хочу выбрать маршрут для каждой записи, чтобы управлять направлением её трафика.

**Критерии приёмки:**

* **AC-ROUTE-APP-005.1:** Когда пользователь выбирает маршрут через VPN, система должна сохранить для записи направление через VPN.
* **AC-ROUTE-APP-005.2:** Когда пользователь выбирает прямой маршрут, система должна сохранить для записи направление мимо VPN.
* **AC-ROUTE-APP-005.3:** Когда пользователь выбирает состояние без специального правила, система должна удалить отдельное правило для записи и вернуть её к базовой маршрутизации.
* **AC-ROUTE-APP-005.4:** При запуске VPN система должна направлять трафик записей с прямым маршрутом мимо VPN, а трафик записей с маршрутом через VPN через VPN.
* **AC-ROUTE-APP-005.5:** Если функция раздельного туннелирования отключена, система не должна применять специальные правила приложений.

### REQ-ROUTE-APP-006: Сохранение и применение изменений

**Пользовательская история:** Как пользователь VPN, я хочу, чтобы изменения маршрутов сохранялись и применялись к активному подключению, чтобы не настраивать их повторно.

**Критерии приёмки:**

* **AC-ROUTE-APP-006.1:** Система должна сохранять список приложений, команд и их маршрутов локально.
* **AC-ROUTE-APP-006.2:** Когда пользователь изменяет или удаляет запись при остановленном VPN, система должна сохранить изменение для следующего подключения.
* **AC-ROUTE-APP-006.3:** Когда пользователь изменяет или удаляет запись при активном VPN, система должна применить изменение к активному подключению после перезапуска туннеля.
* **AC-ROUTE-APP-006.4:** Если применение изменения к активному подключению завершается ошибкой, система должна записать ошибку, не скрывая факт неуспешного применения.

### REQ-ROUTE-APP-007: Взаимодействие с kill-switch

**Пользовательская история:** Как пользователь VPN, я хочу, чтобы выбранные приложения продолжали работать при активном kill-switch, когда я явно разрешил для них исключение.

**Критерии приёмки:**

* **AC-ROUTE-APP-007.1:** Если приложение добавлено как исключение kill-switch, система должна разрешать его трафик при активной блокировке kill-switch.
* **AC-ROUTE-APP-007.2:** Если приложение не добавлено как исключение kill-switch, система не должна считать его прямой маршрут достаточным основанием для обхода активной блокировки kill-switch.
* **AC-ROUTE-APP-007.3:** Изменение списка исключений kill-switch должно быть отражено в применяемой политике kill-switch при следующем её применении.
