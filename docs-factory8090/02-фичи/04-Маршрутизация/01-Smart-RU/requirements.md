# Smart RU

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/requirements/30aa181e-7c96-4c97-a7c9-9fb923a04ebe

## Обзор

«Smart RU» направляет назначения, связанные с российскими доменами и IP-адресами, напрямую, а остальной трафик оставляет на маршруте через VPN. Это позволяет получать доступ к российским банкам, государственным порталам, магазинам и локальным сервисам с прямого подключения, сохраняя VPN-маршрут для остальных сайтов. Правила учитывают доменные списки и страну назначения IP, поэтому российское назначение не ограничивается только зоной `.ru`.

Функция также поддерживает отдельный выбор для онлайн-карт. IP-сервисы проверки адреса, Google и связанные с ним домены, а также медиадомены, для которых прямой выход создаёт нежелательное поведение, должны оставаться на маршруте через VPN.

## Терминология

* **Smart RU**: режим маршрутизации российских назначений напрямую, а остальных назначений через VPN.
* **Российское доменное назначение**: домен из набора российских государственных и банковских доменов либо домен российской зоны или российского коммерческого сервиса.
* **Российское IP-назначение**: IP-адрес, отнесённый к России набором IP-правил.
* **Набор правил Smart RU**: бинарный набор правил для российских IP и российских государственных и банковских доменов.
* **Локальная копия**: набор правил, доступный на устройстве без сетевой загрузки при запуске VPN.
* **Управляемая копия**: локально сохранённый набор правил, который может обновляться после запуска приложения.
* **Встроенная копия**: набор правил, поставляемый вместе с приложением.
* **Прямой DNS-резолвер**: DNS-источник, используемый для разрешения российских доменных назначений без маршрута через VPN.
* **Онлайн-карты**: домены картографических сервисов, для которых пользователь может выбрать прямой выход или VPN-маршрут.
* **VPN-маршрут**: направление трафика через активное VPN-подключение.
* **Прямой маршрут**: направление трафика через обычное подключение устройства, минуя VPN.

## Требования

### REQ-ROUTE-RU-001: Прямой маршрут для российских назначений

**Пользовательская история:** Как пользователь VPN, я хочу направлять российские домены и IP напрямую, чтобы российские сервисы видели моё обычное сетевое расположение, а остальные назначения продолжали использовать VPN.

**Критерии приёмки:**

* **AC-ROUTE-RU-001.1:** Когда Smart RU включён и трафик соответствует российскому доменному назначению, система должна использовать прямой маршрут.
* **AC-ROUTE-RU-001.2:** Когда Smart RU включён и назначение соответствует российскому IP-назначению, система должна использовать прямой маршрут.
* **AC-ROUTE-RU-001.3:** Когда Smart RU включён и трафик не соответствует правилу прямого маршрута или явному исключению, система должна использовать VPN-маршрут.
* **AC-ROUTE-RU-001.4:** Когда Smart RU выключен, система не должна добавлять правила Smart RU в маршрутизацию.

### REQ-ROUTE-RU-002: Разрешение российских доменов

**Пользовательская история:** Как пользователь VPN, я хочу, чтобы российские домены разрешались через прямое подключение, чтобы маршрутизация использовала IP, видимый из моей обычной сети.

**Критерии приёмки:**

* **AC-ROUTE-RU-002.1:** Когда Smart RU включён и выполняется разрешение российского доменного назначения, система должна использовать прямой DNS-резолвер.
* **AC-ROUTE-RU-002.2:** Когда Smart RU выключен, система не должна использовать прямой DNS-резолвер для правил Smart RU.
* **AC-ROUTE-RU-002.3:** Когда домен относится к IP-сервису проверки адреса, Google или закреплённому медиадомену, система должна сохранять для него VPN-разрешение и VPN-маршрут.

### REQ-ROUTE-RU-003: Выбор маршрута онлайн-карт

**Пользовательская история:** Как пользователь VPN, я хочу отдельно выбрать маршрут для онлайн-карт, чтобы использовать прямое подключение для сервисов, которым нужна моя обычная геолокация.

**Критерии приёмки:**

* **AC-ROUTE-RU-003.1:** До изменения настройки онлайн-карт система должна использовать VPN-маршрут для онлайн-карт.
* **AC-ROUTE-RU-003.2:** Когда для онлайн-карт выбран прямой выход, система должна использовать прямой маршрут и прямой DNS-резолвер для онлайн-карт.
* **AC-ROUTE-RU-003.3:** Когда для онлайн-карт выбран VPN-маршрут, система должна использовать VPN-маршрут и VPN-разрешение для онлайн-карт.

### REQ-ROUTE-RU-004: Доступность локальной копии наборов правил

**Пользовательская история:** Как пользователь VPN, я хочу, чтобы Smart RU не мешал запуску VPN при ошибке загрузки наборов правил, чтобы ошибка обновления не создавала утечку трафика.

**Критерии приёмки:**

* **AC-ROUTE-RU-004.1:** При построении VPN-конфигурации система должна использовать доступную локальную копию набора правил.
* **AC-ROUTE-RU-004.2:** Если управляемая копия отсутствует или неполна, система должна использовать встроенную копию.
* **AC-ROUTE-RU-004.3:** Если обновление управляемой копии завершается ошибкой, система должна сохранить доступную локальную копию и не делать ошибку обновления причиной отказа запуска основного VPN-туннеля.
* **AC-ROUTE-RU-004.4:** Если локальная копия отсутствует или её формат не подтверждён, система должна сообщить о невозможности подтвердить набор правил и не должна считать его готовым к использованию.

### REQ-ROUTE-RU-005: Обновление управляемой копии

**Пользовательская история:** Как пользователь VPN, я хочу обновлять управляемую копию наборов правил через выбранный маршрут, чтобы правила оставались актуальными без отказа от локального резерва.

**Критерии приёмки:**

* **AC-ROUTE-RU-005.1:** Когда включено автоматическое обновление управляемой копии, система должна проверять наборы правил с настроенным интервалом.
* **AC-ROUTE-RU-005.2:** При успешной загрузке система должна атомарно заменить соответствующую управляемую копию и сохранить сведения о результате обновления.
* **AC-ROUTE-RU-005.3:** При ошибке загрузки система должна сохранить предыдущую управляемую копию, если она доступна, и сохранить сведения об ошибке.
* **AC-ROUTE-RU-005.4:** Если набор правил скачан без проверки эталонного хеша или подписи, система должна считать доверие к его содержимому неподтверждённым.
