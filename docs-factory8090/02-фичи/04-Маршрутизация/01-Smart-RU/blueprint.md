# Smart RU

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/ec8e3a91-c9de-48ff-842e-cc938fba39e4

## Feature Summary

Smart RU composes routing and DNS generation in `smartRoute.ts` with the runtime configuration generated by `generateSingboxConfig` in `tunController.ts`. When enabled, curated Russian domain rules and `geoip-ru` send matching traffic to `direct-out`; all other traffic remains on `proxy-out`, while protected checker, Google, Gemini, and media domains are pinned to the VPN path before the Russian rules.

The feature stages bundled `.srs` files for startup and can select a complete managed cache for later refreshes. `ruleSetManager.ts` downloads managed files to a temporary path, renames successful downloads into the cache, records SHA-256 metadata, and falls back to the bundled directory when the managed cache is incomplete.

## Component Blueprint Composition

`@Маршрутизация` supplies the base VPN route and final fallback. `#SmartRouteGenerator` contributes feature-specific route-set definitions, route rules, and DNS rules. `#RuleSetManager` selects the bundled or managed local directory and maintains the managed cache. `#SingboxConfigGenerator` combines these outputs with the VPN outbounds, DNS servers, user domain rules, and TUN configuration.

`#SmartRouteGenerator` emits local `geoip-ru.srs` and `geosite-category-gov-ru.srs` definitions when a rule-set directory is provided. The legacy remote form remains available when no directory is supplied. Its DNS rules bind Russian domains and optional map domains to the direct resolver, while protected domains use the remote resolver.

`#RuleSetManager` keeps a managed copy under the application user-data directory. It checks that each required file exists and is non-empty before selecting it. A failed refresh does not remove the prior managed file, and an incomplete managed cache selects the bundled source.

## Feature-Specific Components

### Routing generation

```component
name: SmartRouteGenerator
container: Electron main process
responsibilities:
	- Generate `SmartRouteOptions`-driven route-set definitions for `geoip-ru` and `geosite-category-gov-ru`.
	- Generate protected-domain, Russian-domain, Russian-IP, map, and Kimi/Moonshot route rules for `proxy-out` and `direct-out`.
	- Generate DNS rules that select `dns-direct` or `dns-remote` for the same routing intent.
```

```component
name: RuleSetManager
container: Electron main process
responsibilities:
	- Select the bundled or managed `SmartRouteRuleSetFileState` source.
	- Refresh managed `.srs` files through configured bootstrap route attempts.
	- Replace a downloaded file through a temporary file and rename operation.
	- Persist file size, SHA-256, route, timestamps, and refresh errors as metadata.
```

`#SmartRouteGenerator` is called by `#SingboxConfigGenerator`, which places its route rules after user domain rules and before the remaining fallback rules. This preserves explicit user routing precedence while allowing Smart RU to classify unmatched Russian destinations.

`#RuleSetManager` supplies the directory consumed by `#SingboxConfigGenerator`. The generator uses local rule-set paths when that directory is supplied, so sing-box startup does not require a remote fetch of the rule-set.

## System Contracts

### Key Contracts

* `SmartRouteOptions.enabled` is the feature switch. Disabled mode emits no Smart RU route-set definitions or rules.
* A complete managed source requires both `geoip-ru.srs` and `geosite-category-gov-ru.srs` to exist as non-empty files.
* The bundled source is selected when managed mode is not selected or the managed source is incomplete.
* The current downloader records SHA-256 but does not compare it with an expected hash or signature. Trust of downloaded content is therefore unresolved.
* The current completeness check verifies file presence and non-zero size, but does not validate the binary rule-set format before activation.
* The default map behavior is VPN routing. The caller can enable direct map routing with `mapsDirect`.

### Integration Contracts

* `#SmartRouteGenerator` emits sing-box `route.rule_set` entries for `geoip-ru` and `geosite-category-gov-ru`.
* Local entries use `type: local`, `format: binary`, and a path to the staged `.srs` file.
* Legacy remote entries use the configured upstream URL, `download_detour: proxy-out`, and a one-day update interval when no local directory is supplied.
* `#SingboxConfigGenerator` adds direct DNS servers and the Smart RU DNS rules only when Smart RU is enabled.
* `#RuleSetManager` uses the upstream URLs declared by `smartRouteRuleSetCatalog()` and stores managed files under the application user-data cache directory.

## Architecture Decision Records

### ADR-001: Use local rule-set files for startup

**Context:** A remote rule-set fetch can fail during sing-box startup. The audit records that this previously prevented the core tunnel from starting and could expose the user's real traffic while the UI reported a connection.

**Decision:** Stage bundled `.srs` files and use local rule-set entries when a rule-set directory is available. Keep remote generation only as a compatibility fallback when no local directory is supplied.

**Consequences:** Startup no longer depends on the remote rule-set endpoint in the normal packaged path. Bundled files must be shipped and remain compatible with the bundled sing-box binary.

### ADR-002: Combine domain and IP signals

**Context:** A top-level-domain check is too narrow for Russian services using non-Russian domains and too broad for foreign services hosted in Russia.

**Decision:** Use the curated government and banking geosite for domain matching and `geoip-ru` for destination-IP matching. Pin known checker, Google, Gemini, and media domains to `proxy-out` before the direct rules.

**Consequences:** The feature covers Russian services beyond `.ru` while limiting known false direct routes. Rule ordering remains part of the correctness contract.

### ADR-003: Keep refresh separate from startup selection

**Context:** Managed updates are useful, but a failed update must not remove a working local source or block the main tunnel.

**Decision:** Download to a temporary file, rename only after a non-empty-file check, retain prior files on failure, and select the bundled directory when the managed cache is incomplete.

**Consequences:** Refresh failures preserve the last usable file and expose refresh state through metadata. Hash/signature verification and binary format validation remain open gaps from the S07 audit.
