# Маршрутизация

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/blueprints/dd03ac0b-2faf-44c8-ba8d-383aad183285

## Feature Summary

«Маршрутизация» реализует базовую схему направления трафика VPN Tunnel Enforcer, соответствующую требованиям @Маршрутизация. `generateSingboxConfig()` собирает правила для TUN-конфигурации: исключения по процессам и доменам, правила Smart RU, затем конечное направление `proxy-out` для остального трафика.

Локальные `.srs`-файлы Smart RU могут использоваться без сетевой зависимости при старте. `ruleSetManager.ts` поддерживает управляемый кэш и bundled fallback. Полная E2E-проверка live-apply в переданных материалах не подтверждена.

## Component Blueprint Composition

* `generateSingboxConfig()` из `tunController.ts` формирует конфигурацию маршрутизации для TUN-входа. Для VPN-трафика конечный outbound имеет тег `proxy-out`; отдельные правила могут выбрать `direct-out` или `block-out`.
* `smartRouteRules()` и `smartRouteRuleSets()` из `smartRoute.ts` добавляют Smart RU только при включённой опции. Используются rule-set `geoip-ru` и `geosite-category-gov-ru`; при наличии каталога локальных файлов они объявляются как локальные `.srs`.
* `ruleSetManager.ts` выбирает managed-кэш только когда все требуемые файлы существуют и имеют ненулевой размер. Иначе используется bundled-каталог.

## Feature-Specific Components

```component
name: SingboxRouteConfigGenerator
container: Electron main process
responsibilities:
	- Собирает правила маршрутизации и конечное направление `proxy-out` в `generateSingboxConfig()`.
	- Размещает правила исключений перед конечным правилом маршрута.
	- Формирует TUN-маршруты `0.0.0.0/1` и `128.0.0.0/1`, исключая локальные адреса и адрес конечной точки VPN, когда он известен.
```

`SingboxRouteConfigGenerator` использует `ruleSetManager.ts` и `smartRoute.ts` как источники состояния и определений rule-set. Сначала применяются правила для `mixed-direct-in`, процессов, DNS, приватных адресов, пользовательских доменов и Smart RU, после чего трафик без совпадения направляется в `proxy-out`.

```component
name: RuleSetManager
container: Electron main process
responsibilities:
	- Хранит состояние managed-кэша rule-set в electron-store.
	- Загружает rule-set во временный файл и заменяет целевой файл после успешной загрузки.
	- Выбирает managed-каталог или bundled fallback для Smart RU.
	- Записывает размер, время обновления, маршрут загрузки, SHA-256 и ошибку последней операции.
```

`RuleSetManager` передаёт выбранный каталог `SingboxRouteConfigGenerator`. Ошибка загрузки не отменяет выбор bundled-каталога, если managed-набор неполон. Код сохраняет вычисленный SHA-256, но не выполняет проверку против эталонного хеша или подписи.

## System Contracts

### Key Contracts

* Если правило не совпало, конфигурация использует конечный outbound `proxy-out`.
* Порядок правил значим: правила, добавленные до `final: 'proxy-out'`, имеют возможность переопределить конечный маршрут.
* Основной туннель не должен зависеть от удалённой загрузки Smart RU rule-set: конфигурация может использовать локальные `.srs`, а `ruleSetManager.ts` предоставляет bundled fallback.
* Managed-каталог считается полным только при наличии каждого требуемого файла с ненулевым размером. Проверка формата, эталонного хеша и подписи в наблюдаемом коде отсутствует.
* Live-apply частично присутствует в документационных материалах, но полная сквозная проверка применения правил к активному подключению не подтверждена.

### Integration Contracts

* `generateSingboxConfig()` получает параметры маршрутизации, включая флаги Smart RU и каталог локальных rule-set, и возвращает объект конфигурации sing-box.
* Конфигурация использует направления `proxy-out`, `direct-out` и `block-out`, TUN-вход `tun-in` и локальный вход `mixed-direct-in`.
* `ruleSetManager.ts` предоставляет состояние источника rule-set, включая active source `bundled` или `managed`, состояние полноты managed-каталога и метаданные обновления.

## Architecture Decision Records

### ADR-001: Конечный маршрут через VPN

**Context:** Функция должна направлять весь трафик через VPN по умолчанию и сохранять исключения управляемыми порядком правил.

**Decision:** В конфигурации sing-box используется `proxy-out` как конечный маршрут после правил исключений.

**Consequences:** Трафик без совпадения следует через VPN. Любое новое исключение должно учитывать его положение относительно конечного правила.

### ADR-002: Локальные rule-set для основного туннеля

**Context:** Документы аудита фиксируют, что удалённый rule-set ранее мог сорвать старт туннеля и привести к утечке.

**Decision:** При наличии локального каталога генератор объявляет Smart RU rule-set как локальные `.srs`; менеджер сохраняет managed-кэш и использует bundled fallback при неполном managed-наборе.

**Consequences:** Ошибка удалённого обновления не должна сама по себе останавливать основной туннель. Код не подтверждает целостность файла эталонным хешем или подписью.
