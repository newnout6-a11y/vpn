# Soft-режим: автонастройка прокси в приложениях

> Источник: https://factory.8090.ai/project/992274e4-1c6b-4d44-8c22-e4c038e690c2/requirements/dbda1c85-e41d-4c05-8b5f-615ad0592582

## Обзор

Soft-режим позволяет пользователю направить поддерживаемые приложения через выбранный прокси без создания TUN-интерфейса. Пользователь включает Soft Autoconfig на Dashboard, после чего VPN Tunnel Enforcer применяет прокси-настройки к переменным окружения, Git, Gradle и Android Studio. При выключении режима приложение откатывает изменения, которые оно применило, и возвращает сохранённые исходные значения там, где они были доступны.

Режим предназначен для случаев, когда пользователю нужна прокси-маршрутизация инструментов разработки, но не требуется системный туннель. Soft-режим не должен работать одновременно с активным Hard-туннелем.

## Терминология

* **Soft-режим**: режим маршрутизации без создания TUN-интерфейса, который применяет выбранный прокси к поддерживаемым целям автонастройки.
* **Soft Autoconfig**: переключатель Soft-режима на Dashboard.
* **Цель автонастройки**: поддерживаемая область конфигурации, к которой приложение может применить или из которой может откатить прокси-настройки.
* **Прокси**: адрес и тип прокси, выбранные для Soft-режима.
* **Переменные окружения**: пользовательские HTTP_PROXY, HTTPS_PROXY, ALL_PROXY и NO_PROXY, доступные приложениям Windows.
* **Глобальная конфигурация Git**: пользовательские значения http.proxy и https.proxy в глобальной конфигурации Git.
* **Конфигурация Gradle**: пользовательский файл ~/.gradle/gradle.properties.
* **Конфигурация Android Studio**: пользовательские файлы настроек Android Studio, которые приложение изменяет для прокси и JVM-параметров.
* **Откат**: операция выключения применённых целей автонастройки с восстановлением сохранённых исходных значений или удалением созданных приложением записей.
* **Hard-туннель**: режим, который использует TUN-интерфейс для маршрутизации.

## Нерешённые вопросы

* Нужно решить, должен ли откат Git и Gradle восстанавливать только ключи или строки, изменённые приложением, чтобы не затирать правки пользователя после применения. Текущая реализация сохраняет глобальные значения Git и целое исходное содержимое файла Gradle, поэтому вопрос влияет на AC-SOFT-003.2 и AC-SOFT-003.3.
* Нужно решить, следует ли поддерживать формат `options/proxy.settings.xml` в новых версиях Android Studio вместо текущей записи в `options/other.xml`. Вопрос влияет на AC-SOFT-002.4 и AC-SOFT-003.4.

## Требования

### REQ-SOFT-001: Включение Soft-режима

**История пользователя:** Как пользователь VPN Tunnel Enforcer, я хочу включить Soft Autoconfig на Dashboard, чтобы направить поддерживаемые приложения через выбранный прокси без запуска TUN.

**Критерии приёмки:**

* **AC-SOFT-001.1:** Когда пользователь включает Soft Autoconfig с валидным прокси, система должна применить Soft-режим без создания TUN-интерфейса.
* **AC-SOFT-001.2:** Когда Hard-туннель активен при включении Soft Autoconfig, система должна сначала остановить Hard-туннель, а затем применить Soft-режим.
* **AC-SOFT-001.3:** Когда применение обязательной настройки переменных окружения не удалось, система должна сообщить об ошибке и не считать Soft-режим включённым.
* **AC-SOFT-001.4:** После успешного включения система должна показывать состояние Soft-режима как активное и не должна сообщать VPN IP как результат работы TUN.

### REQ-SOFT-002: Настройка поддерживаемых приложений

**История пользователя:** Как пользователь Soft-режима, я хочу применить один выбранный прокси к поддерживаемым целям, чтобы инструменты разработки использовали нужный маршрут.

**Критерии приёмки:**

* **AC-SOFT-002.1:** Когда пользователь применяет цель «Переменные окружения», система должна установить пользовательские HTTP_PROXY, HTTPS_PROXY и ALL_PROXY на адрес выбранного прокси и установить NO_PROXY для локальных адресов.
* **AC-SOFT-002.2:** Когда пользователь применяет цель «Git», система должна установить глобальные http.proxy и https.proxy на адрес выбранного прокси.
* **AC-SOFT-002.3:** Когда пользователь применяет цель «Gradle», система должна записать прокси-параметры в пользовательскую конфигурацию Gradle и использовать отдельные параметры для SOCKS5 и HTTP-прокси.
* **AC-SOFT-002.4:** Когда пользователь применяет цель «Android Studio», система должна настроить прокси в конфигурации Android Studio и добавить JVM-параметры прокси в пользовательские vmoptions.
* **AC-SOFT-002.5:** Когда пользователь указывает SOCKS5-прокси, система должна использовать SOCKS5-вариант настроек для каждой цели, где такой вариант поддерживается.
* **AC-SOFT-002.6:** Когда пользователь указывает HTTP-прокси, система должна использовать HTTP-вариант настроек для каждой цели, где такой вариант поддерживается.
* **AC-SOFT-002.7:** Если адрес прокси некорректен для Android Studio, система должна отклонить применение этой цели без записи некорректного адреса.
* **AC-SOFT-002.8:** Если применение одной цели из последовательности целей не удалось, система должна попытаться откатить ранее успешно применённые цели и вернуть результат по целям.

### REQ-SOFT-003: Сохранение исходных настроек и откат

**История пользователя:** Как пользователь Soft-режима, я хочу выключить режим и вернуть исходные настройки, чтобы приложение не оставляло после себя прокси-конфигурацию.

**Критерии приёмки:**

* **AC-SOFT-003.1:** Когда пользователь выключает Soft-режим, система должна откатить применённые настройки переменных окружения.
* **AC-SOFT-003.2:** Когда пользователь выключает Soft-режим, система должна восстановить исходные глобальные прокси-настройки Git.
* **AC-SOFT-003.3:** Когда пользователь выключает Soft-режим, система должна восстановить исходное содержимое конфигурации Gradle.
* **AC-SOFT-003.4:** Когда пользователь выключает Soft-режим, система должна восстановить исходные файлы Android Studio или удалить только созданные приложением файлы и блоки.
* **AC-SOFT-003.5:** Когда исходная переменная окружения, настройка Git или файл отсутствовали до применения, система должна удалить созданное значение или файл при откате.
* **AC-SOFT-003.6:** При повторном применении той же цели система должна сохранить исходную резервную копию и не заменять её текущим Soft-значением.
* **AC-SOFT-003.7:** Если откат отдельной цели завершился ошибкой, система должна сохранить данные, необходимые для повторной попытки отката, и сообщить о неуспешном результате.
* **AC-SOFT-003.8:** При остановке защиты, запуске другого режима, восстановлении после сбоя и завершении приложения система должна откатить активную настройку переменных окружения Soft-режима, кроме случая восстановления после сбоя, когда Soft-режим всё ещё выбран и не конфликтует с текущим режимом подключения.

### REQ-SOFT-004: Состояние и управление целями

**История пользователя:** Как пользователь Soft-режима, я хочу видеть состояние целей автонастройки и управлять ими, чтобы понимать, где прокси уже применён.

**Критерии приёмки:**

* **AC-SOFT-004.1:** Когда приложение запрашивает состояние автонастройки, система должна вернуть для каждой известной цели её идентификатор, название, признак применения, область действия, предупреждение и доступные пути управления.
* **AC-SOFT-004.2:** Когда пользователь применяет или откатывает выбранные цели, система должна обрабатывать цели последовательно и возвращать отдельный результат для каждой обработанной цели.
* **AC-SOFT-004.3:** Когда приложение закрывается, система должна выполнить очистку Soft-настроек независимо от того, был ли активен TUN.

## Наблюдения и ограничения реализации

Текущая реализация применяет переменные окружения через пользовательский `setx`, Git через глобальную конфигурацию Git, Gradle через `~/.gradle/gradle.properties`, а Android Studio через найденные каталоги `AndroidStudio*` в пользовательском каталоге Google. Резервные копии создаются до изменения и сохраняются между повторными применениями. Тесты подтверждают сохранение резервной копии переменных окружения, компенсирующий откат при частичном сбое, строгий разбор адреса для Android Studio и защиту чужих настроек Android Studio без признака владения.

Известные ограничения требуют отдельного решения: разбор IPv6 в Git и Gradle делит адрес по двоеточию; `setx` может обрезать значения длиннее 1024 символов; текущая логика отката Android Studio может удалить весь компонент `HttpConfigurable`; XML-значение host не экранируется; код пишет в `options/other.xml`, хотя журнал указывает на новый файл `options/proxy.settings.xml`; откат Git и Gradle восстанавливает весь сохранённый файл или ключи и может затереть изменения пользователя после применения. Журнал аудита также указывает, что исправления отката Git и компенсации автонастройки заявлены в документации, поэтому их фактический статус должен проверяться по текущему коду.
