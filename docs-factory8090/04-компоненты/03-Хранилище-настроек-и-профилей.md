# Хранилище настроек и профилей

## Capability Summary

Возможность хранит настройки приложения, профили серверов, группы подписок и конфигурацию granular kill-switch в отдельных экземплярах electron-store. `settingsStore` нормализует значения и сохраняет настройки, а shared stores задают формы данных профилей и групп. Аудит фиксирует открытое хранение ключей, несогласованные read-modify-write и нормализацию defaults как F-001, F-063 и F-146.

## Core Components

### Настройки

```component
name: SettingsStore
container: Main Process
responsibilities:
	- Хранит AppSettings в electron-store с именем settings.
	- Объединяет входные значения с defaults и нормализует перечисления, числа, флаги, кэшированные профили и интервалы.
	- Управляет login item и задачей boot recovery при изменении autoStart.
```

### Профили и группы

```component
name: ServerPickerStore
container: Main Process
responsibilities:
	- Хранит массивы ServerProfile и активный идентификатор профиля в electron-store.
```

```component
name: ServerGroupsStore
container: Main Process
responsibilities:
	- Хранит группы подписок и ручных профилей в electron-store.
```

```component
name: GranularKillSwitchStore
container: Main Process
responsibilities:
	- Хранит уровень kill-switch и список исключений в electron-store.
```

#SettingsStore отделяет нормализацию пользовательского состояния от хранения профилей. #ServerPickerStore и #ServerGroupsStore совместно представляют ключи и их источники, поэтому операции обновления должны учитывать общий массив профилей.

## System Contracts

### Key Contracts

* Чтение возвращает нормализованный AppSettings, а сохранение не должно незаметно удалять поддерживаемые поля.
* Значения по умолчанию являются источником формы состояния до нормализации persisted-данных.
* Профили, группы и исключения хранятся раздельно по именам electron-store.
* Read-modify-write над общими массивами должен быть сериализован или выполнен атомарно, иначе возможна потеря изменений, F-063.
* Секретные поля профилей сейчас сохраняются открытым текстом, F-001. Требуется отдельное решение о шифровании и миграции.

### Integration Contracts

* `AppSettings`, `ServerProfile`, `ServerGroup`, `KillSwitchException` и связанные типы определены в исходном коде и shared типах.
* Настройки используются туннелем, маршрутизацией, защитой сети, локализацией и renderer.
* Стор профилей используется импортом, выбором сервера, группами и экспортом.

## Architecture Decision Records

### ADR-001: Раздельные electron-store экземпляры

**Context:** Настройки, профили, группы и исключения имеют разные жизненные циклы.

**Decision:** Использовать отдельные stores `settings`, `server-picker`, `server-groups` и `granular-kill-switch`.

**Consequences:** Области данных разделены, но межstore-операции не образуют одну транзакцию.

### ADR-002: Нормализация при чтении и записи

**Context:** Persisted-данные могут быть неполными или созданными старой версией.

**Decision:** Сливать defaults и входные значения, затем ограничивать и приводить поля.

**Consequences:** Чтение устойчиво к части старых форматов, но drift defaults и схемы может изменить поведение, F-146.
