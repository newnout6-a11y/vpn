# Журналирование и маскировка секретов

## Capability Summary

Компонентная возможность записывает события приложения в JSONL-файл с последовательной очередью записи и ограниченной ротацией. Перед записью и перед экспортом она маскирует секреты, сетевую топологию и чувствительные значения; форензика сохраняет корреляцию адресов внутри одного экспорта через псевдонимы. Возможность используется диагностикой, туннелем, IPC и экспортом артефактов. Связанные находки журнала аудита: F-004.

## Core Components

### Логи приложения

```component
name: AppLogger
container: Main Process
responsibilities:
	- Формирует JSONL-запись с временем, уровнем, областью, сообщением и деталями.
	- Последовательно добавляет записи через очередь, создаёт каталог logs и повторяет запись после ENOENT.
	- Ротирует app.log при превышении 5 MiB в app.prev.log и хранит одну предыдущую генерацию.
	- Ограничивает детали 4000 символами и читает хвост файлов ограниченным объёмом.
```

### Маскировка логов

```component
name: SensitiveLogRedactor
container: Main Process
responsibilities:
	- Применяет redactSensitiveText и redactSensitiveConfig к сообщениям, ошибкам и объектам.
	- Маскирует IPv4, IPv6, MAC и значения сетевой топологии.
	- Обрабатывает app.log, app.prev.log, sing-box.log и sing-box.json перед выдачей диагностике.
```

#AppLogger передаёт нормализованные записи в #SensitiveLogRedactor до помещения строки в очередь. Это отделяет формат JSONL и управление файлом от правил удаления секретов и сетевых идентификаторов.

### Форензика

```component
name: ForensicsRedactor
container: Main Process
responsibilities:
	- Создаёт псевдонимы для IP, MAC и доменов на время одного экспорта.
	- Сохраняет класс адреса и публичный суффикс домена, чтобы поддержать анализ утечек и маршрутизации.
	- Обрабатывает текст, JSON и NDJSON, включая усечённую последнюю строку.
	- Не записывает таблицу соответствий токенов в экспортируемый пакет.
```

#ForensicsRedactor используется экспортом форензики вместо простой замены всех адресов. Такая связь сохраняет корреляцию DNS и потоков, но не выносит исходные адреса с устройства.

## System Contracts

### Key Contracts

* Запись в файл сериализована очередью; ошибка записи не должна выбрасывать ошибку вызывающему журналирование коду.
* `app.log` ограничен 5 MiB на поколение, а `app.prev.log` содержит только одну предыдущую генерацию.
* Логи и диагностические снимки не должны выдавать исходные секреты и сетевую топологию через штатные пути чтения и экспорта.
* Один `ForensicsRedactor` должен использоваться для всех файлов одного экспорта, чтобы токены были стабильными внутри пакета.

### Integration Contracts

* #AppLogger принимает `AppLogLevel`, область, сообщение и произвольные детали.
* #ForensicsRedactor предоставляет операции маскировки текста, JSON и NDJSON, а также статистику замен.
* Диагностический экспорт получает уже обработанные снимки и форензийные артефакты.

## Architecture Decision Records

### ADR-001: Ограниченная JSONL-ротация

**Context:** Частые IPC-события постоянно увеличивают журнал.

**Decision:** Использовать очередь записи, размерный порог 5 MiB и одну предыдущую копию.

**Consequences:** Размер хранения ограничен, но старые поколения журнала недоступны.

### ADR-002: Корреляционные псевдонимы форензики

**Context:** Полная замена адресов уничтожает связь между DNS, потоками и событиями.

**Decision:** Выдавать стабильные токены с сохранением класса адреса и публичного суффикса.

**Consequences:** Диагностика сохраняет полезную структуру, но исходные значения нельзя восстановить из пакета.
