# Системные изменения с откатом

## Capability Summary

Возможность применяет изменения Windows-сети и защиты с сохранением baseline или манифеста и выполняет откат при остановке, сбое и запуске recovery. Она объединяет сетевой baseline, firewall kill-switch и lockdown физических адаптеров. Открытые риски целостности манифестов и неполного отката зафиксированы F-017, F-030 и F-121.

## Core Components

### Сетевой baseline

```component
name: SystemNetworkBaseline
container: Main Process
responsibilities:
	- Экспортирует HKCU Internet Settings, HKCU Environment и HKLM Connections в ProgramData.
	- Сохраняет атомарный latest-tun-network-baseline.json.
	- Сбрасывает WinHTTP, WinINet и proxy environment перед TUN.
	- Восстанавливает backup при rollback и сериализует операции очередью.
```

### Kill-switch

```component
name: FirewallKillSwitch
container: Main Process
responsibilities:
	- Сохраняет DefaultOutboundAction профилей Domain, Private и Public.
	- Создаёт разрешающие правила для runtime, приложения, TUN, loopback и LAN.
	- Переводит исходящий трафик в Block и восстанавливает сохранённые профили.
	- Использует manifest.json и проверку правил как признаки активного состояния.
```

### Lockdown адаптеров

```component
name: PhysicalAdapterLockdown
container: Main Process
responsibilities:
	- Снимает состояние физических Ethernet/Wi-Fi адаптеров, DNS и IPv6.
	- Во время TUN отключает IPv6 и при необходимости направляет IPv4 DNS к TUN resolver.
	- Сохраняет manifest в userData и ProgramData, включая transition adapters и DNS policy.
	- Восстанавливает исходные свойства при stop, crash recovery и ошибке старта.
```

#SystemNetworkBaseline применяет изменения до запуска туннеля и передаёт состояние через manifest. #FirewallKillSwitch и #PhysicalAdapterLockdown применяются вокруг жизненного цикла TUN, а recovery использует их манифесты после аварийного завершения.

## System Contracts

### Key Contracts

* Изменение, которое нельзя безопасно откатить без baseline, не должно выполняться после неудачного backup.
* Откат должен быть идемпотентным и безопасным при отсутствии активного манифеста.
* Частичная ошибка восстановления должна сохранять диагностируемый результат и не скрывать оставшееся системное изменение.
* Firewall kill-switch должен оставаться активным при неожиданной смерти sing-box до явного stop или успешного restart.
* Манифесты требуют доверенной директории и проверки целостности. Потеря манифеста может привести к восстановлению неверной политики, F-017 и F-030.

### Integration Contracts

* #SystemNetworkBaseline предоставляет apply, rollback и rollback-if-applied.
* #FirewallKillSwitch предоставляет enable, disable, status и repair operations.
* #PhysicalAdapterLockdown предоставляет apply, rollback и repair orphaned DNS.
* Tun controller координирует порядок применения и отката, а boot recovery запускается от SYSTEM.

## Architecture Decision Records

### ADR-001: Манифест как признак активного изменения

**Context:** После сбоя процесс может не дойти до обычного stop.

**Decision:** Сохранять состояние до изменения и использовать manifest как источник истины для recovery.

**Consequences:** Recovery может быть автоматическим, но потеря или подмена файла нарушает гарантию восстановления.

### ADR-002: Сохранение разрешающих правил до Block

**Context:** Немедленный Block может остановить sing-box и саму возможность восстановления.

**Decision:** Сначала сохранять исходные профили и создавать Allow rules, затем включать DefaultOutboundAction=Block.

**Consequences:** Порядок снижает риск самоблокировки, но требует корректного отката при ошибке записи манифеста.
