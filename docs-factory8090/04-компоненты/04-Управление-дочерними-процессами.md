# Управление дочерними процессами

## Capability Summary

Возможность запускает и контролирует дочерние процессы Windows, включая процессы с повышением прав, и выполняет безопасную очистку по PID-файлам. `managedChildProcess.ts` проверяет владельца, PID, путь исполняемого файла и путь конфигурации перед остановкой. Туннельный запуск sing-box использует sudo-prompt и хранит PID в статусе как `null`, а cleanup по PID-файлу не подключён к этому пути. Связанные находки: F-012, F-018, F-022 и F-133.

## Core Components

### Управляемый PID

```component
name: ManagedChildProcess
container: Main Process
responsibilities:
	- Записывает JSON PID-файл с owner, pid, exePath, configPath и createdAt.
	- Проверяет, что PID-файл принадлежит ожидаемому owner.
	- На Windows сопоставляет PID с executable path или command line перед Stop-Process.
	- Удаляет PID-файл после подтверждённой остановки и очищает каталоги по префиксу.
```

### Запуск туннеля

```component
name: TunProcessSupervisor
container: Main Process
responsibilities:
	- Запускает sing-box через sudo-prompt с командой из runtime-каталога.
	- Обрабатывает UAC-отказ, выход процесса, таймауты и ограниченный auto-restart.
	- Останавливает stale runtime и процессы Xray перед новым запуском.
	- Публикует состояние туннеля и журналирует жизненный цикл процесса.
```

#TunProcessSupervisor запускает sing-box и Xray, а #ManagedChildProcess предоставляет отдельный механизм проверки владения и cleanup. Текущий код не связывает эти два пути для sing-box, что ограничивает восстановление по PID-файлу, F-018.

## System Contracts

### Key Contracts

* Остановка по PID допустима только после проверки owner и совпадения executable path либо config path.
* PID текущего процесса приложения не должен приниматься как дочерний PID.
* Ошибка запуска не должна оставлять kill-switch или блокировку физических адаптеров без согласованного recovery.
* Повторный запуск должен сначала удалить принадлежащий приложению stale runtime.
* Прямой запуск Xray должен быть согласован с очисткой старого runtime, иначе новый процесс может быть остановлен cleanup-логикой, F-022.

### Integration Contracts

* #TunProcessSupervisor принимает профиль/прокси и параметры запуска sing-box.
* #ManagedChildProcess принимает путь PID-файла, owner и функцию журналирования.
* Состояние туннеля содержит running, proxy, startedAt, restartAttempt и PID, но текущая ветка sing-box возвращает `pid: null`, F-012.

## Architecture Decision Records

### ADR-001: Проверка владения перед остановкой

**Context:** PID может быть переиспользован другим процессом после аварии.

**Decision:** Сопоставлять PID с owner и путём executable/config до Stop-Process.

**Consequences:** Снижается риск остановить чужой процесс, но stale или неполный PID-файл не очищает процесс автоматически.

### ADR-002: Повышенный запуск через системный запрос UAC

**Context:** Создание TUN и сетевые изменения требуют повышенных прав Windows.

**Decision:** Запускать долгоживущий sing-box через sudo-prompt и выполнять команды восстановления через elevated PowerShell.

**Consequences:** Приложение зависит от UAC и асинхронного callback завершения процесса.
