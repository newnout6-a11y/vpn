# Сборка и установщик

## Container Summary

Сборочный и установочный контур Windows-приложения. `electron-vite` собирает main, preload и renderer, `electron-builder` формирует NSIS perMachine installer и portable artifact, а конфигурация добавляет внешние бинарники, скрипты, rule-set и snapshot-файлы.

## Infrastructure

* Electron 42, electron-vite 3 и electron-builder 26 указаны в `package.json`.
* NSIS target собирается для Windows x64 с `requestedExecutionLevel: requireAdministrator`.
* NSIS настроен как `perMachine`, с desktop и Start Menu shortcuts.
* `extraResources` включает sing-box, Xray, Wintun, libcronet, rule-set и recovery scripts; `extraFiles` включает proxy и ETW artifacts.
* `asar: true`, renderer output `out/renderer`, main output `out/main`, preload output `out/preload`.

## Entry Points and Boundaries

* `npm run build` выполняет typecheck и electron-vite build.
* `npm run build:sidecar` собирает native sidecar; `npm run build:snapshot` создаёт V8 snapshot artifacts.
* `npm run dist:win` выполняет sidecar, snapshot, app build и NSIS packaging.
* Установщик разворачивает runtime resources и регистрирует Windows app shortcuts и elevated execution.

## System Contracts

### Key Contracts

* Артефакт должен содержать бинарники и скрипты, на которые ссылается main и recovery.
* NSIS должен поддерживать perMachine installation и сохранение пользовательских данных при uninstall.
* Установочная конфигурация должна быть согласована с путями `process.resourcesPath` и runtime staging.
* Проверки подписи, checksums и auto-update в текущей конфигурации не подтверждены.

### Integration Contracts

* `electron.vite.config.ts` задаёт три build entries: main, preload и renderer.
* `electron-builder.yml` задаёт NSIS/portable targets и resource mappings.
* `package.json` является source of truth для команд build/dist и версий Electron/зависимостей.

### Integration Boundaries

* Installer получает административные права и изменяет machine-wide Windows installation.
* Внешние EXE/DLL и scripts входят в артефакт без описанного в конфигурации механизма подписи.
* Отсутствующий `build/installer.nsh` заявлен как F-162.
* Отсутствие подписи, checksums и auto-update отмечено F-163, F-164 и F-165.
* Electron 42 имеет плановый EOL-вопрос на 2026-10-20, F-166; связанные риски toolchain отмечены F-167.

## Architecture Decision Records

### ADR-001: NSIS perMachine

**Context:** Приложению нужны elevated network operations, runtime resources и machine-wide shortcuts.

**Decision:** Использовать NSIS target с `perMachine: true` и `requireAdministrator`.

**Consequences:** Установка соответствует системному runtime, но требует UAC и строгого контроля содержимого пакета.

### ADR-002: electron-vite как сборочный контур

**Context:** Main, preload и renderer имеют разные entry points и требования к бандлингу.

**Decision:** Разделить сборку на три electron-vite targets.

**Consequences:** Границы модулей ясны, а изменения Electron/toolchain требуют совместной проверки.
