**Покрывает:** F-001, F-004, F-005, F-006, F-038, F-055, F-130, F-132, F-139…F-145, F-158, F-206; AC-SET-CFG-001…003, AC-SRV-EXP-001…003.

### AT-01-001: Миграция секретов на DPAPI/safeStorage с откатом
**Трассировка:** F-001, F-004, WP-1 · **Уровень:** L2 · **Тип:** upgrade/rollback, fault injection
**Фикстуры:** legacy `settings.json` с plaintext-секретами (маркер `FAKE-`).
**Шаги:**
1. Запустить миграцию; проверить, что значения заменены на `SecretRef`, блоб зашифрован.
2. Повтор: инжектировать сбой (исключение safeStorage) на середине миграции; перезапустить.
**Оракул (PASS, если все условия):**
- После успешной миграции plaintext-значения отсутствуют на диске (побайтовый поиск маркеров в `settings.json`, `boxes.json`).
- При сбое старые данные не потеряны: миграция повторяема, приложение стартует со старой схемой с предупреждением, а не с пустыми секретами.
- Записаны события миграции с результатом каждого шага.

### AT-01-002: Скан секретов в логах, диагностическом ZIP и argv
**Трассировка:** F-004, F-130, F-132, WP-1, WP-8 · **Уровень:** L3 · **Тип:** security, dual-oracle
**Шаги:**
1. На чистой VM выполнить полный пользовательский цикл с синтетическими профилями (`FAKE-UUID`, `FAKE-PASS`), включая экспорт диагностики.
2. Сканировать: каталог логов, диагностический ZIP, командные строки всех дочерних процессов (WMI/CIM во время работы), буфер обмена после копирований.
**Оракул (PASS, если все условия):**
- Ноль вхождений `FAKE-`-маркеров и реально-образных UUID/паролей/приватных ключей в сканируемых артефактах; маскировка соответствует политике redactor.
- Позитивный контроль: файл-канарейка с `FAKE-` вне redactor-контекста обнаруживается сканером (доказывает, что скан работал).
- Ни один дочерний процесс не имеет секрета в командной строке.

### AT-01-003: Hostile IPC sender
**Трассировка:** F-139…F-145, WP-1 · **Уровень:** L2/L3 · **Тип:** abuse
**Шаги:**
1. Из renderer открыть сторонний `iframe` и из него вызвать privileged-каналы (через перехваченный `ipcRenderer`).
2. Подменить `senderFrame`/origin в тестовой сборке; повторить вызовы.
3. Инжектировать скрипт в devtools-консоли renderer (prod-сборка).
**Оракул (PASS, если все условия):**
- Каждый вызов с невалидным senderFrame/origin отклонён немедленно; в audit log записано событие отказа с источником.
- Ни один privileged handler не выполнил побочного эффекта (файлы, процессы, реестр — снапшоты до/после идентичны).

### AT-01-004: Фаззинг IPC-payloads
**Трассировка:** F-139, F-140, WP-1 · **Уровень:** L1/L2 · **Тип:** fuzzing, property-based
**Шаги:**
1. Для каждого privileged handler сгенерировать ≥ 100k payload-мутаций (type confusion, гигантские строки, `__proto__`, глубокая вложенность, NaN/Infinity, управляющие символы).
**Оракул (PASS, если все условия):**
- 100% невалидных payload отклонены runtime-схемой типизированной ошибкой валидации.
- Ноль падений процесса; состояние после фаззинга эквивалентно начальному (снапшот store).
- Время обработки одного payload ≤ 50 мс p99 (защита от algorithmic DoS).

### AT-01-005: DNS rebinding / Host header на локальных слушателях
**Трассировка:** F-038, WP-1 · **Уровень:** L2 · **Тип:** abuse
**Шаги:**
1. К каждому локальному HTTP-слушателю приложения обратиться с Host: `127.0.0.1`, `localhost`, `evil.attacker.tld`, `2130706433` (decimal IP), `[::1]`.
**Оракул (PASS, если все условия):**
- Ответы только на разрешённые Host из явного списка; остальные — отказ 4xx без раскрытия данных.
- Отказ зафиксирован в журнале; ни один обработчик не выполнил действия.

**Оракул (PASS, если все условия):**

- Политика идентична заявленной в ТЗ; исключения перечислены явно и покрыты комментарием-обоснованием.

### AT-01-008: Экспорт и копирование секретов — явное согласие
**Трассировка:** F-055, F-130, AC-SRV-EXP-001…003, WP-1 · **Уровень:** L3 · **Тип:** security, functional
**Шаги:**
1. Экспортировать профиль с секретом без подтверждения; затем с подтверждением.
2. Скопировать полный URI в буфер; ждать истечения таймаута очистки.
**Оракул (PASS, если все условия):**
- Без явного подтверждения полный URI с секретом не покидает main-процесс (перехват IPC).
- Экспорт использует одноразовый минимальный контракт (только запрошенные поля).
- Буфер обмена очищен после заявленного таймаута (чтение буфера через Win32 API).

### AT-01-009: ACL доверенного runtime-каталога до запуска
**Трассировка:** F-005, F-006, WP-1, WP-2 · **Уровень:** L3 · **Тип:** security, negative
**Шаги:**
1. Ослабить ACL runtime-каталога (дать Everyone:Write); запустить подключение.
2. Подменить бинарник ядра в каталоге с ослабленным ACL.
**Оракул (PASS, если все условия):**
- Ошибка ACL останавливает запуск до старта elevated-процесса; событие в журнале; частичного состояния нет (0 созданных правил/адаптеров).
- Подменённый бинарник не исполняется: владелец/хэш/подпись проверены до запуска.

**Шаги:**

### AT-01-011: Property-based тест redactor
**Трассировка:** F-004, F-132, WP-1, WP-8 · **Уровень:** L1 · **Тип:** property-based
**Шаги:**
1. fast-check: генерировать строки/объекты, содержащие секрето-образные значения (UUID, base64-ключи, URI с userinfo, токены, пути `C:\Users\*`), прогонять redactor.
**Оракул (PASS, если все условия):**
- Ни в одном из ≥ 100k сгенерированных случаев секрето-образная подстрока не встречается в выводе redactor.
- Несекретные данные не мутируют (метаморфная проверка: redactor(clean) ≡ clean).
- Поле без политики маскирования отклоняется (fail-closed), а не проходит как есть.
