### AT-06-001: Property-based таблица приоритетов правил
**Трассировка:** AC-ROUTE-002, F-007, F-008, WP-6 · **Уровень:** L1 · **Тип:** property-based
**Шаги:**
1. fast-check: генерировать наборы правил с пересечениями (exact/suffix/keyword/regex, user-override/Smart RU/дефолт, домен/IP).
2. Для каждого набора вычислить решение маршрутизатора и сверить с эталонной реализацией таблицы приоритетов (тестовый оракул по спецификации).
**Оракул (PASS, если все условия):**
- Решение детерминировано и совпадает с таблицей приоритетов в 100% сгенерированных наборов.
- Перестановка порядка объявления правил одного класса не меняет решение (метаморфный инвариант).
- Приоритет пользовательских override зафиксирован и побеждает согласно таблице.

### AT-06-002: Exact ≠ suffix
**Трассировка:** AC-ROUTE-DOM-001…006, F-009, WP-6 · **Уровень:** L1 · **Тип:** boundary, negative
**Шаги:**
1. Правило exact `example.com`; запросы к `example.com`, `www.example.com`, `notexample.com`, `example.com.evil.tld`.
**Оракул (PASS, если все условия):**
- Exact-правило матчит только сам домен; suffix-поведение включается только явным выбором.
- Пограничные имена (`notexample.com`, суффикс-обманка) не матчатся; IDN-пуникод эквивалентен Unicode-форме по документированному правилу.

### AT-06-003: Smart RU сквозной сценарий — двойной оракул
**Трассировка:** AC-ROUTE-RU-001…005, F-007, F-078, F-079, WP-6 · **Уровень:** L3 · **Тип:** functional, dual-oracle
**Среда:** OS-W11-24H2, NET-BASE, активный туннель со Smart RU.
**Шаги:**
1. Запросы к `gosuslugi.ru` (в rule-set), `cloudflare.com` (вне), домену с DNS-ответом в RU-подсетях.
**Оракул (PASS, если все условия):**
- `gosuslugi.ru` выходит напрямую (egress = реальный IP), `cloudflare.com` — через туннель (egress = IP сервера); оба факта подтверждены внешним наблюдателем и записями маршрутизатора.
- DNS-резолв доменов из правил соответствует профилю (удалённый/локальный по таблице).
- Hit-счётчики сработавших правил > 0.

### AT-06-004: Подписанные/checksummed rule-set
**Трассировка:** F-010, F-074, WP-6 · **Уровень:** L2 · **Тип:** abuse, fault injection
**Шаги:**
1. Подменить байт в загруженном rule-set; нарушить подпись; оборвать загрузку на 70%.
**Оракул (PASS, если все условия):**
- Набор принимается только после проверки checksum/signature; подмена отклонена, событие безопасности записано.
- При ошибке загрузки активирован локальный проверенный `gov-ru.srs` fallback; UI получил IPC-уведомление и диагностический статус.

### AT-06-005: Атомарная активация rule-set
**Трассировка:** F-075, WP-6 · **Уровень:** L2 · **Тип:** fault injection
**Шаги:**
1. Килл процесса между «новый набор загружен» и «активирован» (управляемая точка сбоя).
**Оракул (PASS, если все условия):**
- После перезапуска активен ровно один набор (старый или новый), смешанного состояния нет; загрузка возобновляется или честно перезапускается.

### AT-06-006: Восстановление active-id DNS-профиля
**Трассировка:** AC-ROUTE-DNS-001…005, F-076, WP-6 · **Уровень:** L2 · **Тип:** fault injection
**Шаги:**
1. Импорт DNS-профилей, заменяющий набор, при котором активный id исчезает; повреждённый список профилей.
**Оракул (PASS, если все условия):**
- Active-id восстановлен по задокументированному правилу (fallback на дефолт) с событием; пользователь видит фактический активный профиль, а не фантомный.
- Импорт заменяет набор атомарно; повреждённые входы отклонены без частичного применения.

### AT-06-007: Старт без удалённых зависимостей
**Трассировка:** F-077, WP-6 · **Уровень:** L3 · **Тип:** fault injection
**Среда:** WAN полностью заблокирован на маршрутизаторе.
**Оракул (PASS, если все условия):**
- Приложение стартует и принимает решения маршрутизации по локальным наборам; UI честно показывает деградацию (не «всё проверено»).
- Все попытки сетевых обновлений с backoff, без шторма запросов (≤ 1 попытки/мин после 3 неудач).

### AT-06-008: Split tunneling по путям процессов
**Трассировка:** AC-ROUTE-APP-001…007, F-076, WP-6 · **Уровень:** L3 · **Тип:** functional, negative
**Шаги:**
1. Добавить `C:\Apps\app.exe` в исключения; запустить копию того же бинарника из `D:\Other\app.exe`; переименовать оригинал во время работы.
**Оракул (PASS, если все условия):**
- Трафик матчится по нормализованному пути процесса; копия по другому пути не попадает под правило (egress-проверка).
- Переименование/перемещение обрабатывается по документированному правилу (правило недействительно → статус, а не молчаливый матч по имени).
