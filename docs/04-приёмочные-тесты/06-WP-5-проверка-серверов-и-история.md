# WP-5. Live-проверки серверов и история — набор тестов

**Покрывает:** F-057…F-062, F-065…F-072, F-181, F-185; REQ-SRV-CHK-001…006, AC-SRV-CHK-001…006.
**Среда по умолчанию:** L1/L2; маршрутные проверки на L3 с реальным туннелем.

---

### AT-05-001: Матрица маршрутов проверок (direct vs tunnel)
**Трассировка:** REQ-SRV-CHK-001, REQ-SRV-CHK-002, AC-SRV-CHK-001, F-057, WP-5 · **Уровень:** L2/L3 · **Тип:** functional matrix
**Шаги:**
1. Состояния: туннель активен / не активен / подключается. В каждом — direct latency, key health, egress IP.
**Оракул (PASS, если все условия):**
- Direct-замеры идут вне туннеля, egress-замеры — через туннель при активном (проверка интерфейса сокета в L3).
- В состоянии «подключается» tunnel-зависимые проверки помечены `not-checked`, а не выполнены мимо туннеля.
- Каждая проверка записывает фактический route в результат.

### AT-05-002: Валидация DNS-адресов включая IPv4-mapped IPv6
**Трассировка:** F-058, WP-5 · **Уровень:** L1 · **Тип:** boundary, property-based
**Шаги:**
1. Входы: `::ffff:8.8.8.8`, `8.8.8.8`, `[2001:4860:4860::8888]`, `999.1.1.1`, hostname, пустая строка, IDN.
**Оракул (PASS, если все условия):**
- IPv4-mapped формы нормализуются/отклоняются по задокументированному правилу; все отказы с указанием причины; ноль исключений.

### AT-05-003: Ограниченный параллелизм и отмена пакета проверок
**Трассировка:** AC-SRV-CHK-003, F-059, WP-5 · **Уровень:** L2 · **Тип:** race, cancellation
**Шаги:**
1. Пакет из 200 профилей (фейковые endpoints с управляемой задержкой). Отмена на 50%; повторный запуск сразу после отмены.
**Оракул (PASS, если все условия):**
- Одновременно активных проверок ≤ заявленного лимита (счётчик в стенде).
- Отмена завершает in-flight ≤ 1 с; осиротевших сокетов нет (счётчик дескрипторов); частичные результаты помечены отменёнными, не «проваленными».
- Повторный запуск после отмены не конфликтует с недобитым пакетом.

### AT-05-004: Ретенция истории — ровно 20 на цель
**Трассировка:** AC-SRV-CHK-004, F-060, WP-5 · **Уровень:** L1 · **Тип:** boundary, property-based
**Шаги:**
1. fast-check: последовательности из 0…100 проверок по ключам `profile:<id>`, `host:<host>`, `global` вперемешку.
**Оракул (PASS, если все условия):**
- На каждую цель хранится ≤ 20 записей, новые впереди; 21-я вытесняет старейшую — во всех сгенерированных последовательностях.
- Ключи не смешиваются: запись `profile:X` никогда не вытесняет `host:Y`.

### AT-05-005: Восстановление повреждённого файла истории
**Трассировка:** F-061, WP-5 · **Уровень:** L2 · **Тип:** fault injection
**Шаги:**
1. `live-server-checks.json`: обрезать на середине, записать мусор, обнулить. Перезапуск.
**Оракул (PASS, если все условия):**
- Файл восстанавливается из backup; при невозможности — пользователь уведомлён, файл карантинирован, но не молча стёрт.
- Запись новых результатов работает сразу после восстановления; атомарность записи (tmp+rename) подтверждена сбоем на середине.

### AT-05-006: Санитизация истории от секретов
**Трассировка:** F-062, WP-5, WP-1 · **Уровень:** L1 · **Тип:** property-based, security
**Шаги:**
1. Проверки над профилями с `FAKE-` секретами и реальными UUID; просканировать файл истории.
**Оракул (PASS, если все условия):**
- Секреты удалены перед записью, UUID замаскированы по политике; побайтовый поиск маркеров — 0 вхождений.
- Маскировка стабильна: одно значение → одна маска в пределах записи (для сравнимости diff).

### AT-05-007: Отрисовка всех полей diff
**Трассировка:** AC-SRV-CHK-005, F-065, WP-5 · **Уровень:** L2 (UI) · **Тип:** functional, snapshot
**Фикстура:** две проверки, различающиеся всеми полями: IP, TLS fingerprint, ASN, страна, задержка, порты, handshake, egress IP, PMTU, скорость.
**Оракул (PASS, если все условия):**
- UI показывает изменение каждого из 10 полей (снапшот DOM); сравнение выполнено с последней успешной проверкой, а не с последней любой.
- Неизменившиеся поля помечены как без изменений; отсутствующие данные — `not-checked`, не «0».

### AT-05-008: Явная очистка истории
**Трассировка:** AC-SRV-CHK-006, F-066, WP-5 · **Уровень:** L2 · **Тип:** functional
**Шаги:**
1. Накопить историю; очистить из UI; проверить файл и UI.
**Оракул (PASS, если все условия):**
- Файл пуст (структура с 0 записей, не удалён молча); UI подтверждает результат очистки; событие в журнале.
- Undo не обещается и не выполняется.

### AT-05-009: Not-checked отличим от успеха
**Трассировка:** F-067, WP-5 · **Уровень:** L2 · **Тип:** negative, UI-contract
**Шаги:**
1. Цель недостижима (фейковый endpoint отверг соединение); цель с невалидным TLS; проверка прервана пользователем.
**Оракул (PASS, если все условия):**
- Вердикты `failed` и `not-checked` визуально и семантически различимы от `passed` (нет зелёного статуса); причина доступна.
- Сортировка/фильтры серверов не трактуют `not-checked` как худший или лучший результат.

### AT-05-010: Проверки во время флапа туннеля
**Трассировка:** F-068, WP-5 · **Уровень:** L3 · **Тип:** chaos
**Среда:** NET-FLAP; цикл подключение/разрыв каждые 30 с на фоне непрерывных проверок.
**Оракул (PASS, если все условия):**
- Каждый результат содержит корректный route момента выполнения; смешанных вердиктов «проверено, но маршрут неизвестен» нет.
- 30 мин цикла: 0 зависших проверок, 0 роста дескрипторов > 5% от baseline.
