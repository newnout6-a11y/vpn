# Сквозные прогоны: pairwise-матрица, производительность, soak, исследовательские сессии

Тесты, не привязанные к одному WP. Выполняются на L3-лаборатории перед каждым релизом (и nightly для подмножества).

---

## 1. Pairwise-матрица конфигураций (AT-X-001)

**Уровень:** L3 · **Тип:** pairwise config matrix

Полный перебор недостижим, поэтому покрытие — все пары факторов (генерация таблицы инструментом pairwise; фактическая таблица хранится рядом с этим файлом как `pairwise-matrix.csv` и пересматривается при изменении факторов).

| Фактор | Значения |
| --- | --- |
| ОС | W10 22H2, W11 23H2, W11 24H2 |
| Режим | Hard TUN (прокси), Direct VPN, Soft |
| Протокол | VLESS Reality, Hysteria 2, WireGuard endpoint, SS2022, VMess |
| Сеть | NET-BASE, NET-LOSS-5, NET-LAT-300, NET-IPV6-ONLY, NET-MTU-1280, NET-FLAP |
| Kill-switch | on, off |
| Smart RU | on, off |

**Оракул для каждой ячейки:** подключение установлено ≤ бюджета, egress соответствует режиму, утечек 0 (выборка 30 с), отключение чистое (снапшот системы идентичен исходному).

## 2. Производственные бюджеты (AT-X-002)

**Уровень:** L3 · **Среда:** OS-W11-24H2, NET-BASE · **Метод:** 10 холодных прогонов, медиана и p95.

| Метрика | Бюджет |
| --- | --- |
| Холодный старт до интерактивного UI | ≤ 3 с (p95) |
| Подключение Hard TUN (от клика до подтверждённого connected) | ≤ 15 с (p95) |
| Direct VPN (VLESS Reality) | ≤ 12 с (p95) |
| Отключение (полный откат) | ≤ 10 с (p95) |
| CPU в простое (main + renderer суммарно) | ≤ 2% |
| RSS renderer после 1 ч мониторинга | ≤ 300 МБ |
| IPC ping (renderer→main→renderer) | ≤ 50 мс p95 |
| Импорт подписки 10 000 серверов | ≤ 30 с, UI остаётся отзывчивым (ввод не блокируется > 100 мс) |

**Оракул:** каждая метрика в бюджете; превышение любого бюджета — релизный блокер или явное переподтверждение бюджета в ТЗ.

## 3. Soak-прогон 72 часа (AT-X-003)

**Уровень:** L3 · **Среда:** OS-W11-24H2, NET-FLAP (фон), ротация профилей каждые 15 мин, UI открыт 50% времени.

Сценарий: циклы [подключение → мониторинг 15 мин → ротация → раз в 4 ч полный restart приложения → раз в 12 ч проверка утечек AT-03-001 в сокращённом окне 5 мин].

**Оракул (PASS, если все условия):**
- 0 необъяснимых FAIL за весь прогон; каждый отказ автоматики объяснён записью в журнале.
- Рост RSS/handles/GDI-объектов ≤ 10% между часом 1 и часом 72 (снимки раз в час).
- 0 утечек во всех выборках; история подключений полна и непрерывна (correlation id каждой операции).

## 4. Исследовательские уставы (L4, AT-X-004)

60–90 мин на устав, протокол: цель, находки, риски, новые идеи тестов → пополнение наборов.

1. **«Злой пользователь»:** гонки кликов, спам toggle во время всех переходов, ввод мусора во все поля, внезапный quit в каждой фазе.
2. **«Злой админ»:** чужие GPO, антивирус с SSL-инспекцией, второй VPN, ручная правка реестра зон autoconfig во время работы.
3. **«Злая сеть»:** DPI-фикстуры (обрыв handshake, подмена SNI-ответов), captive portal внезапно, DNS, отвечающий с задержкой 10 с.
4. **«Археолог»:** апгрейд через 3 старые версии подряд с накопленными данными; проверка всех миграций и итогового состояния.
5. **«Секреты под микроскопом»:** поиск секретов во всех артефактах, какие удастся найти на диске, в памяти (дамп процесса), в crash dumps Windows.

**Оракул устава:** каждая находка либо заведена дефектом с привязкой к WP/F, либо превращена в новый AT в соответствующем наборе. Устав без итогового протокола не засчитывается.

## 5. Регрессионный контур аудита (AT-X-005)

**Уровень:** L0–L3 · **Тип:** regression suite

Каждая подтверждённая находка F-001…F-210 имеет регрессионный тест в наборе своего WP (см. трассировки в файлах пакетов). Перед релизом:

1. Скрипт сверки подтверждает покрытие всех подтверждённых F ссылками из тестов.
2. Опровергнутые находки (F-151, F-162) имеют помеченные регрессионные тесты (AT-09-013, AT-11-009), предотвращающие возврат ложной проблемы.
3. Прогон регрессионного контура целиком — обязательный релизный гейт.
