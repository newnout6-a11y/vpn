# WP-9. Soft-режим, браузерный hardening и доступность UI — набор тестов

**Покрывает:** F-014, F-036, F-037, F-040, F-042, F-120, F-121, F-153…F-161; AC-SOFT-001…004, AC-LEAK-BR-001…004, AC-SET-001…004, AC-SET-UI-001…005, AC-SET-WIZ-001…003, AC-SET-AUTO-001…003.

### AT-09-001: Rollback не затирает поздние правки пользователя
**Трассировка:** AC-SOFT-002, F-153, WP-9 · **Уровень:** L3 · **Тип:** fault tolerance
**Шаги:**
1. Soft Autoconfig применён (системный прокси выставлен). Пользователь вручную меняет прокси в настройках Windows.
2. Отключить Soft-режим.
**Оракул (PASS, если все условия):**
- Откат восстанавливает только собственные изменения VPNTE: значение после отключения равно ручной правке пользователя, а не устаревшему baseline.
- Журнал фиксирует обнаружение внешнего изменения и принятое решение.

### AT-09-002: IPv6-адреса прокси в autoconfig
**Трассировка:** AC-SOFT-003, F-154-смежная, WP-9 · **Уровень:** L1 · **Тип:** boundary
**Оракул (PASS, если все условия):**
- `[::1]:1080`, `[2001:db8::1]:8080` принимаются и корректно записываются в целевые механизмы (PAC/WinHTTP/WinINET) с экранированием по правилам каждого; невалидные формы отклонены с причиной.

### AT-09-003: Лимит `setx` 1024 символа
**Трассировка:** F-155, WP-9 · **Уровень:** L2 · **Тип:** boundary, negative
**Шаги:**
1. Установить переменную окружения длиной 1023/1024/1025/4096 символов через soft-конфигурацию.
**Оракул (PASS, если все условия):**
- >1024: используется альтернативный механизм (реестр) или честная ошибка без усечения; значение на диске побайтово равно запрошенному.
- Никакой «молчаливой обрезки» — diff применённого значения обязан быть пуст.

### AT-09-004: Актуальный путь Android Studio и Git/Gradle
**Трассировка:** F-156, WP-9 · **Уровень:** L2 · **Тип:** compatibility matrix
**Фикстуры:** деревья каталогов 5 версий Android Studio (включая текущую), портативный Git, Gradle home.
**Оракул (PASS, если все условия):**
- Обнаружение по актуальным путям, а не захардкоженным устаревшим; неизвестная версия — честный `not-detected` с подсказкой, а не запись в несуществующий путь.

### AT-09-005: Сериализация apply/rollback браузеров
**Трассировка:** F-036, F-037, F-157, WP-9 · **Уровень:** L2 · **Тип:** race, fault injection
**Шаги:**
1. Одновременные apply для Chrome/Edge/Brave + отказ на середине одного из них.
**Оракул (PASS, если все условия):**
- Операции сериализованы; отказ одного браузера откатывает только его изменения, остальные консистентны; сводка по каждому браузеру отдельная.

### AT-09-006: Динамические alias браузеров
**Трассировка:** F-040, WP-9 · **Уровень:** L3 · **Тип:** compatibility
**Шаги:**
1. Среды: Chrome stable/canary, Edge, Brave, переименованный exe, пользовательская установка вне Program Files.
**Оракул (PASS, если все условия):**
- Обнаружение через реестр/App Paths/стандартные локации, не по хардкоду; отсутствующий браузер — честный статус; DNS браузерных боксов идёт удалённым резолвером (`--host-resolver-rules`) — проверка захватом: 0 локальных DNS-запросов от процесса бокса.

### AT-09-007: Изоляция Chromium Browser Boxes — двойной оракул
**Трассировка:** AC-LEAK-BR-001…004, F-042, WP-9 · **Уровень:** L3 · **Тип:** security, dual-oracle
**Шаги:**
1. Два бокса с разными профилями; проверить UserDataDir, cookies, кэш, DNS, egress IP.
**Оракул (PASS, если все условия):**
- Данные боксов не пересекаются (diff директорий, отсутствие общих cookie); DNS каждого бокса резолвится удалённо (захват: 0 запросов к системному резолверу от PID бокса).
- Закрытие бокса удаляет временные данные согласно политике.

### AT-09-008: Клавиатурный проход ключевых сценариев
**Трассировка:** AC-SET-UI-001…005, F-158…F-160, WP-9 · **Уровень:** L3 · **Тип:** a11y
**Шаги (только клавиатура):**
1. Подключить → открыть настройки → сменить сервер → открыть модальное подтверждение → закрыть → отключиться.
**Оракул (PASS, если все условия):**
- Каждый шаг достижим с клавиатуры; видимый focus indicator на каждом фокусируемом элементе; в модалках focus trap удерживает Tab-цикл, при закрытии focus возвращается на вызвавший элемент.
- Нет вложенных интерактивных элементов и статических дублирующихся id (DOM-аудит в конце прохода).

### AT-09-009: Screen reader (NVDA)
**Трассировка:** F-161, WP-9 · **Уровень:** L3 · **Тип:** a11y
**Оракул (PASS, если все условия):**

### AT-09-010: Таймеры после unmount
**Трассировка:** F-120, WP-9 · **Уровень:** L2 · **Тип:** fault injection, leak
**Шаги:**
1. 100 циклов монтирования/размонтирования страниц с поллингом (мониторинг, проверки).
**Оракул (PASS, если все условия):**
- После unmount ни один callback не срабатывает (счётчик вызовов); число активных таймеров/подписок возвращается к baseline; React не логирует setState-after-unmount.

### AT-09-011: Паритет локализации ru/en — CI-гейт
**Трассировка:** F-121, WP-9 · **Уровень:** L0 · **Тип:** localization, contract
**Оракул (PASS, если все условия):**
- Множества ключей ru и en равны; непереведённая русская строка в en (и наоборот) — ошибка сборки; плейсхолдеры/ICU-формы совпадают по арности; `lang`-атрибут документа переключается вместе с языком UI.

### AT-09-012: Визуальная консистентность селектора частоты (скриншот-регрессия)
**Трассировка:** F-014, WP-9 · **Уровень:** L3 · **Тип:** visual regression
**Оракул (PASS, если все условия):**
- Селектор частоты использует `MacSelect`/design tokens: размеры, отступы, радиусы, цвета, focus/disabled/error состояния совпадают с эталонными скриншотами обеих локалей (порог pixel-diff 0 для состояний).
- Нормализация интервалов: провайдерский 15 мин–24 ч, ручной 1 мин–24 ч, дефолт 30 мин при невалидном значении (property-тест нормализатора).

### AT-09-013: Мастер первого запуска — регрессия F-151
**Трассировка:** AC-SET-WIZ-001…003, F-151, WP-9 · **Уровень:** L2 · **Тип:** regression
**Оракул (PASS, если все условия):**
- `firstRunComplete` сохраняется через родительский callback: после завершения мастера и перезапуска мастер не показывается; при прерывании на шаге k повторный старт ведёт себя по документированному правилу.

### AT-09-014: Мастер первого запуска — импорт ключа и автозапуск
**Трассировка:** AC-SET-WIZ-001…003, REQ-SET-WIZ-001…003, WP-9 · **Уровень:** L3 · **Тип:** functional, end-to-end
**Среда:** чистый профиль приложения и Windows-учётная запись без ранее импортированных профилей; валидная и заведомо невалидная VPN-фикстура.
**Шаги:**
1. Запустить мастер первого запуска, пройти настройку языка и детекцию Happ до шага импорта ключа.
2. Импортировать валидную фикстуру; проверить появление профиля в приложении и продолжить до настройки автозапуска.
3. Включить автозапуск, завершить мастер и перезапустить приложение/проверить зарегистрированный механизм запуска Windows.
4. В повторном чистом прогоне выбрать отказ от автозапуска; в отдельном прогоне попробовать импортировать невалидную фикстуру.
**Оракул (PASS, если все условия):**
- Валидный ключ импортируется ровно один раз и становится доступен как профиль; невалидный ключ не создаёт частичного профиля, ошибка показана пользователю и мастер остаётся восстанавливаемым.
- Выбор автозапуска сохраняется и согласован с фактической регистрацией запуска Windows; отказ оставляет автозапуск выключенным, ошибка регистрации не маскируется.
- Завершение мастера доступно после обработки обоих шагов; после перезапуска сохранённый профиль и настройка автозапуска соответствуют выбранным значениям.
- Секреты ключа не попадают в логи и диагностический экспорт.
