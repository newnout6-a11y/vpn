# WP-2. Процессы, runtime и lifecycle туннеля — набор тестов

**Покрывает:** F-002, F-003, F-012, F-013, F-018, F-022…F-029, F-131, F-133…F-135, F-207; AC-CONN-001…004, AC-CONN-MODE-001…005, AC-CONN-REC-001…004.
**Среда по умолчанию:** L2 с фейковыми дочерними процессами; L3 на OS-W10-22H2 и OS-W11-24H2 для системных сценариев.

---

### AT-02-001: Матрица «чужой/протухший процесс» для PID-супервизора
**Трассировка:** F-002, F-003, F-012, WP-2 · **Уровень:** L2 · **Тип:** negative matrix
**Фикстуры:** сценарии PID: (a) PID переиспользован чужим процессом; (b) чужой процесс с именем `sing-box.exe`; (c) PID-файл указывает на завершённый PID; (d) PID-файл повреждён; (e) процесс запущен другим пользователем.
**Шаги:** для каждого сценария подготовить состояние, вызвать stop/cleanup супервизора.
**Оракул (PASS, если все условия):**
- Чужой процесс не завершён ни в одном сценарии (проверка живости по PID и start time).
- Протухшие/повреждённые PID-записи классифицированы как `stale` и удалены; событие записано.
- Владелец определяется по нормализованному абсолютному пути + PID + command line (+ подпись/хэш, где доступно) — спуфинг только по имени образа не проходит.

### AT-02-002: Порядок запуска Xray + sing-box (регрессия F-022)
**Трассировка:** F-022, AC-CONN-MODE-004.2, WP-2 · **Уровень:** L2 · **Тип:** integration, race
**Шаги:**
1. Запустить Direct VPN с REALITY-профилем (Xray) при активном sing-box TUN.
2. Во время инициализации Xray инициировать cleanup/перезапуск sing-box runtime.
**Оракул (PASS, если все условия):**
- Запуск сериализован: cleanup sing-box никогда не завершает процесс Xray (проверка живости PID Xray на каждом шаге).
- Системный туннель и защитные меры остаются под управлением основного движка; исходящее соединение идёт через локальный SOCKS Xray (проверка маршрута сокета).
- При отказе движка попытка завершена ошибкой; UI не показывает работающую защиту (AC-CONN-MODE-004.3).

### AT-02-003: Аварийное завершение ядра — crash policy
**Трассировка:** F-013, F-018, WP-2 · **Уровень:** L3 · **Тип:** chaos
**Среда:** OS-W11-24H2, NET-BASE; активный Hard TUN.
**Шаги:**
1. `taskkill /F /PID <ядро>` во время активной передачи трафика.
2. Наблюдать реакцию супервизора; повторить 5 раз подряд (проверка backoff).
**Оракул (PASS, если все условия):**
- Обнаружение падения ≤ 3 с; kill-switch удерживает блокировку всё время до восстановления или безопасного отключения (0 пакетов мимо туннеля по pktmon на физическом адаптере).
- Политика рестарта с экспоненциальным backoff; после исчерпания попыток — типизированное состояние ошибки и уведомление, без «молча висящего» состояния.
- Каждое событие записано с correlation id.

### AT-02-004: Таймаут запуска ядра — полный откат
**Трассировка:** F-023, F-024, WP-2, WP-3 · **Уровень:** L2 · **Тип:** fault injection
**Шаги:**
1. Фейковое ядро, которое никогда не сигналит ready (hang). Запустить подключение с включёнными системными изменениями (TUN, маршруты, DNS).
2. Дождаться deadline.
**Оракул (PASS, если все условия):**
- Deadline срабатывает в заявленный бюджет; запуск признан неуспешным.
- Откат системных изменений выполнен полностью: 0 осиротевших адаптеров Wintun (`Get-NetAdapter`), маршруты/DNS восстановлены к baseline (побайтовое сравнение снапшотов).
- Осиротевший процесс фейкового ядра завершён.

### AT-02-005: Гонка завершения приложения во время подключения
**Трассировка:** F-025, F-026, WP-2 · **Уровень:** L2 · **Тип:** race, fault injection
**Шаги:**
1. Начать подключение; в случайный момент фазы (seeded) инициировать quit приложения. 100 итераций.
**Оракул (PASS, если все условия):**
- Во всех итерациях: дочерние процессы завершены, listeners закрыты, история подключения содержит финальную запись.
- Следующий запуск стартует из чистого состояния (нет stale lock/PID/manifest-конфликтов).
- Ни одна итерация не оставляет сетевых изменений без манифеста.

### AT-02-006: Ограничение буфера stderr дочерних процессов (F-207)
**Трассировка:** F-207, WP-2 · **Уровень:** L2 · **Тип:** boundary, fault injection
**Шаги:**
1. Фейковое ядро пишет в stderr непрерывный поток (1 МБ/с) в течение 10 мин.
**Оракул (PASS, если все условия):**
- RSS main-процесса растёт ≤ 20 МБ за тест (ring-buffer с фиксированным лимитом).
- Ядро не блокируется по pipe; поток логов в UI/файл продолжается с маркером усечения.
- При превышении лимита событие `stderr.truncated` записано однократно на интервал, без шторма.

### AT-02-007: Парсинг адресов прокси — границы и property-тесты
**Трассировка:** F-027, AC-CONN-MODE-002.1, AC-SRV-XP-001…006, WP-2 · **Уровень:** L1 · **Тип:** property-based, boundary
**Шаги:**
1. fast-check: генерация валидных/невалидных адресов (IPv4, IPv6 `[::1]:10808`, hostname, IDN, порты 0/1/65535/65536/-1, пробелы, `127.0.0.1:10808abc`).
**Оракул (PASS, если все условия):**
- Все валидные по RFC-адреса приняты и нормализованы детерминированно; все невалидные отклонены типизированной ошибкой.
- Метаморфное свойство: `parse(format(parse(x))) ≡ parse(x)` для всех принятых входов.
- Ни один вход не вызывает исключения наружу (только Result-тип).

### AT-02-008: Совместимость sing-box 1.13 / 1.14 — golden-компиляция
**Трассировка:** F-028, WP-2, WP-12 · **Уровень:** L1 · **Тип:** golden/snapshot, contract
**Шаги:**
1. Скомпилировать каждый golden-профиль под схемы 1.13 и 1.14; сравнить с эталонными JSON.
**Оракул (PASS, если все условия):**
- Для 1.14 отсутствует `download_detour`; endpoints WireGuard присутствуют по спецификации; `http_clients` генерируются корректно.
- Профиль, несовместимый с фактической версией runtime, отклоняется preflight-проверкой с понятной причиной до запуска (AC-CONN-MODE-003.3).
- Любое отклонение снапшота требует явного обновления эталона с комментарием в PR.

### AT-02-009: Graceful stop с активной передачей
**Трассировка:** F-029, WP-2 · **Уровень:** L3 · **Тип:** functional, fault tolerance
**Шаги:**
1. Активный туннель, идёт загрузка 100 МБ. Инициировать остановку.
**Оракул (PASS, если все условия):**
- Ядру дан заявленный grace-период; принудительное завершение — только после таймаута (событие `stop.escalated`).
- Flush статистики выполнен до выхода; итоговая запись истории содержит счётчики трафика.
- После остановки подтверждено удаление TUN и откат системных изменений (порядок остановки из ТЗ §3.1).

### AT-02-010: Проверка владельца прокси-процесса
**Трассировка:** F-030-смежная, AC-CONN-MODE-002.2, WP-2 · **Уровень:** L2/L3 · **Тип:** security, negative
**Шаги:**
1. Поднять легитимный локальный прокси (Happ-фикстура) — определить владельца.
2. Подменить процесс на тот же порт другим бинарником с тем же именем образа.
**Оракул (PASS, если все условия):**
- Легитимный владелец определён по пути+PID+cmdline.
- Подмена обнаружена (подпись/хэш/путь), правила, зависящие от владельца, не применяются; UI сообщает о неподтверждённом владельце.

### AT-02-011: Model-based тур «подключение–сбой–восстановление»
**Трассировка:** AC-CONN-REC-001…004, F-131, WP-2 · **Уровень:** L2 · **Тип:** state-machine model-based
**Шаги:**
1. Сгенерировать 500 случайных сценариев: подключение → {падение ядра | обрыв сети | отмена пользователем | таймаут} → {автовосстановление | ручной retry | отключение}.
**Оракул (PASS, если все условия):**
- Автовосстановление соблюдает заявленную стратегию (число попыток, интервалы, джиттер) в каждом сценарии.
- После исчерпания попыток — безопасное состояние: защита снята штатно или kill-switch активен с явным статусом; ничего промежуточного.
- Счётчики восстановлений в истории равны фактическому числу попыток.
