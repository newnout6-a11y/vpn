# WP-4. Импорт, совместимость протоколов, подписки и группы — набор тестов

**Покрывает:** F-045…F-056, F-063, F-064, F-073…F-079, F-093, F-097…F-101, F-140, F-144…F-148; AC-SRV-001…005, AC-SRV-IMP-001…006, AC-SRV-SUB-001…006, AC-SET-CFG-001…003.
**Среда по умолчанию:** L1/L2; сетевые сценарии на L2 с фейковым HTTP-сервером подписок.

---

### AT-04-001: Property-based парсер импорта
**Трассировка:** AC-SRV-IMP-001…006, F-045, WP-4 · **Уровень:** L1 · **Тип:** property-based, fuzzing
**Шаги:**
1. fast-check-генераторы для каждого формата: `vless://`, `hy2://`, `ss://` (SIP002), `vmess://`, `trojan://`, WireGuard INI, JSON/YAML-конфиги, смешанный текст, Happ payloads.
2. Прогон ≥ 100k сгенерированных входов на парсер в nightly (seed в отчёте).
**Оракул (PASS, если все условия):**
- Ноль необработанных исключений; каждый отказ типизирован с позицией ошибки.
- Инвариант round-trip для принятых входов: `serialize(parse(x))` парсится в эквивалентный профиль.
- Пиковая память парсинга ограничена линейно от размера входа (защита от бомб вложенности).

### AT-04-002: Golden-фикстуры протоколов
**Трассировка:** AC-SRV-IMP-002, F-046, WP-4 · **Уровень:** L1 · **Тип:** golden/snapshot
**Шаги:**
1. Эталонный набор: по 3 валидных профиля на протокол (включая ECH, SIP002-плагины, IPv6-адреса в host), каждый — через полный конвейер импорт → нормализация → компиляция в конфиг ядра.
**Оракул (PASS, если все условия):**
- Вывод конвейера побайтово равен утверждённым golden-файлам; изменение golden требует отдельного ревью.
- AmneziaWG-параметры (`Jc`, `Jmin`, `Jmax`, `S1`, `S2`, `H1..H4`) разбираются и валидируются по диапазонам.
- VMess `alter_id` нормализуется в `0`; отличные значения — предупреждение, а не молчаливое поведение.

### AT-04-003: Отсутствие двойного декодирования (метаморфный тест)
**Трассировка:** F-047, WP-4 · **Уровень:** L1 · **Тип:** metamorphic, negative
**Шаги:**
1. Подписки в вариантах: plain, base64, base64(base64), base64 с URL-safe алфавитом и отсутствующим padding, смесь plain+base64 построчно.
**Оракул (PASS, если все условия):**
- Единый decode-pipeline декодирует ровно один раз: `decode(pipeline(x))` идемпотентен на всех вариантах.
- Множество профилей из base64-варианта равно множеству из plain-варианта того же источника (метаморфное равенство).
- Битый base64 отклонён с диагностикой, не «молча пропущен».

### AT-04-004: IPv6 и SIP002 границы
**Трассировка:** F-048, WP-4 · **Уровень:** L1 · **Тип:** boundary
**Шаги:**
1. Адреса: `[::1]`, `[2001:db8::1]:443`, zone-id `[fe80::1%eth0]`, IPv4-mapped `::ffff:1.2.3.4`; SIP002 plugin query-строки с закодированными и «голыми» параметрами.
**Оракул (PASS, если все условия):**
- Валидные формы приняты и скомпилированы с корректным bracket-форматированием в конфиге ядра.
- Невалидные (несбалансированные скобки, двойные порты) отклонены до записи в store.

### AT-04-005: Happ-форматы: `happ://add`, crypt3/4/5
**Трассировка:** F-049, WP-4 · **Уровень:** L1 · **Тип:** golden, negative
**Шаги:**
1. Известные good-векторы каждого crypt-варианта; неизвестная версия crypt9; усечённые payload.
**Оракул (PASS, если все условия):**
- Good-векторы декодируются в эталонные профили.
- Неизвестная версия — явная ошибка «формат не поддерживается»; усечение — ошибка целостности. Ни один payload не интерпретируется «по guess».

### AT-04-006: Нормализация без молчаливой потери полей
**Трассировка:** F-050, WP-4 · **Уровень:** L1 · **Тип:** metamorphic
**Шаги:**
1. Профили со всеми поддерживаемыми полями (Hysteria 2 TLS-поля, obfs, ALPN, ECH) → импорт → экспорт → diff по полям.
**Оракул (PASS, если все условия):**
- Все поддерживаемые поля сохраняются; diff пуст.
- Неподдерживаемые поля не удаляются молча: профиль помечается несовместимым с явным перечнем полей до запуска (AC-CONN-MODE-003.3).

### AT-04-007: Транзакционное обновление подписки
**Трассировка:** AC-SRV-SUB-001…006, F-051, F-052, WP-4 · **Уровень:** L2 · **Тип:** fault injection
**Шаги:**
1. Фейковый сервер подписки с точками сбоя: обрыв на fetch, на 50% тела, невалидный payload, HTTP 500, таймаут.
2. В каждом случае проверить состояние профилей и групп.
**Оракул (PASS, если все условия):**
- Конвейер fetch→decode→parse→validate→diff→persist сериализован; при любой сетевой ошибке `ok: false`, предыдущие профили и группы нетронуты (diff хэшей store до/после пуст).
- Пустой результат никогда не отображается как успешное обновление.
- persist атомарен: kill процесса на середине записи (fault) → store остаётся в одной из двух целостных версий.

### AT-04-008: Гонка импорта и автообновления
**Трассировка:** F-053, WP-4 · **Уровень:** L2 · **Тип:** race
**Шаги:**
1. Параллельно: ручной импорт 200 профилей, автообновление подписки, удаление группы — 100 seeded-прогонов.
**Оракул (PASS, если все условия):**
- Операции сериализованы очередью; финальное состояние равно результату последовательного применения (проверка моделью).
- UI отражает результат каждой операции отдельно; ни одна не «потерялась».

### AT-04-009: Фильтрация private/loopback в DoH и редиректах
**Трассировка:** F-054, WP-4 · **Уровень:** L1/L2 · **Тип:** abuse, security
**Шаги:**
1. Подписка/DNS-настройки, указывающие DoH на `127.0.0.1`, `169.254.169.254`, RFC1918; URL подписки с редиректом 302 на `http://192.168.0.1/`.
**Оракул (PASS, если все условия):**
- Private/loopback цели отклонены с объяснением; cross-origin редирект на private IP заблокирован; цепочка редиректов ограничена (≤ 5) и журналируется.
- Ни один запрос к отклонённой цели не уходит в сеть (перехват на фейковом сокете).

### AT-04-010: Архив ключей и TTL секретов
**Трассировка:** F-056, WP-4 · **Уровень:** L2 · **Тип:** functional, security
**Шаги:**
1. Удалить профиль → он попадает в архив; подождать истечения TTL (сжатое время); проверить хранилище.
**Оракул (PASS, если все условия):**
- У удалённых профилей есть срок/политика хранения; секреты не остаются в архиве бессрочно без явного TTL.
- После TTL секреты уничтожены (побайтовый поиск), метаданные архива сохраняются согласно политике.

### AT-04-011: Выборочный импорт/экспорт конфигурации — атомарность
**Трассировка:** AC-SET-CFG-001…003, F-063, F-064, WP-4 · **Уровень:** L2 · **Тип:** fault injection
**Шаги:**
1. Экспорт подмножества настроек; импорт в изменённую конфигурацию; сбой на середине импорта.
**Оракул (PASS, если все условия):**
- Импорт атомарен на выбранном подмножестве: после сбоя конфигурация целостна (вся старая или вся новая), отчёт по каждому элементу.
- Schema-versioned store: конфиг неизвестной версии отклонён с понятным сообщением, без попытки частичного применения.

### AT-04-012: HWID не передаётся в argv
**Трассировка:** F-073, WP-4 · **Уровень:** L3 · **Тип:** security
**Шаги:**
1. Активировать подписку с HWID-привязкой; перечислить командные строки всех процессов (CIM) и перехваченные HTTP-запросы.
**Оракул (PASS, если все условия):**
- HWID присутствует только в заявленном канале (header/body по спецификации), отсутствует в argv любого процесса и в логах.
