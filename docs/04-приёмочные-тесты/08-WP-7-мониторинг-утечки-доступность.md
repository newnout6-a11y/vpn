# WP-7. Проверки утечек, доступность, скорость и мониторинг — набор тестов

**Покрывает:** F-010, F-080…F-096, F-102…F-112, F-177, F-179; AC-MON-001…004, AC-MON-LIVE-001…007, AC-MON-AV-001…006, AC-MON-SPD-001…005, AC-DIAG-LEAK-001…005.

---

### AT-07-001: Типизированная матрица вердиктов
**Трассировка:** AC-MON-LIVE-001, F-080, WP-7 · **Уровень:** L2 · **Тип:** contract matrix
**Шаги:**
1. Фикстуры, провоцирующие каждый вердикт: `passed` (чистый контур), `failed` (настоящая утечка — фейковый резолвер сливает), `not-checked` (источник недоступен), `indeterminate` (противоречивые сигналы двух сервисов).
**Оракул (PASS, если все условия):**
- Каждый вердикт достижим и выставлен ровно в своём сценарии; матрица «сигнал × вердикт» соответствует документированной.
- UI локализует и различает все четыре вердикта; `not-checked`/`indeterminate` никогда не рендерятся как успех.

### AT-07-002: Отсутствие лога ≠ «утечек нет»
**Трассировка:** F-081, WP-7 · **Уровень:** L2 · **Тип:** negative
**Шаги:**
1. Отключить источник логов ядра; выполнить проверку утечек.
**Оракул (PASS, если все условия):**
- Вердикт `not-checked` с объяснением, какого источника не хватило; никакой формулировки «утечек не обнаружено».
- Событие фиксирует причину недоступности источника.

### AT-07-003: Семантика HTTP-статусов сервисов проверки
**Трассировка:** F-082, F-083, WP-7 · **Уровень:** L1 · **Тип:** boundary matrix
**Шаги:**
1. Фейковые сервисы отвечают: 200 (валидный JSON), 200 (битый JSON), 401, 403, 429 (+Retry-After), 500, таймаут.
**Оракул (PASS, если все условия):**
- 401/403 → отказ сервиса, вердикт `not-checked`; 429 → backoff с учётом Retry-After; 500/таймаут — ретрай по политике, затем `not-checked`.
- «200 с битым телом» — не успех; ошибка парсинга отражена. Ни один не-200 не трактуется как отсутствие утечки.

### AT-07-004: Нормализация URL проверок
**Трассировка:** F-084, WP-7 · **Уровень:** L1 · **Тип:** property-based, boundary
**Шаги:**
1. fast-check: URL без схемы, с `//`, с пробелами, IDN, с портом, с userinfo (должен резаться), uppercase host.
**Оракул (PASS, если все условия):**
- Нормализация детерминирована и идемпотентна (`normalize(normalize(u)) ≡ normalize(u)`); userinfo не уходит в запросы и логи.

### AT-07-005: Anycast / split-route противоречия
**Трассировка:** F-085, WP-7 · **Уровень:** L2 · **Тип:** metamorphic, negative
**Шаги:**
1. Два фейковых leak-сервиса отвечают разными egress IP; затем один недоступен.
**Оракул (PASS, если все условия):**
- Противоречие → `indeterminate` с показом обоих сигналов; единственный источник → вердикт с пометкой о единственном источнике, не «полная уверенность».

### AT-07-006: Egress mismatch — неподтверждённый результат
**Трассировка:** F-086, WP-7 · **Уровень:** L2 · **Тип:** negative
**Шаги:**
1. Speed test / availability / leak check при egress IP, не совпадающем с ожидаемым сервером профиля.
**Оракул (PASS, если все условия):**
- Несоответствие egress сохраняется как неподтверждённый результат во всех трёх проверках; UI показывает mismatch отдельной пометкой.

### AT-07-007: Rate limiter и privacy-политика гео/ASN
**Трассировка:** F-087, F-088, WP-7 · **Уровень:** L2 · **Тип:** security, functional
**Шаги:**
1. Выключить передачу геоданных в privacy policy; выполнить проверки. Включить; вызвать 50 проверок подряд.
**Оракул (PASS, если все условия):**
- При выключенной политике ноль запросов, содержащих IP/ASN/гео, к внешним сервисам (перехват); UI объясняет ограничение функции.
- При включённой: rate limiter ограничивает частоту согласно бюджету; backoff после 429.

### AT-07-008: Таймзоны в истории трафика
**Трассировка:** F-089, WP-7 · **Уровень:** L1 · **Тип:** property-based
**Шаги:**
1. fast-check: временные метки с зонами `+0300`, `+03:00`, `Z`, отрицательные смещения, DST-переходы America/New_York и Europe/Moscow.
**Оракул (PASS, если все условия):**
- Все формы парсятся в корректные instant (сверка с эталонной tz-базой); сортировка истории хронологична независимо от исходного формата зоны.

### AT-07-009: Числовая история трафика
**Трассировка:** F-090, AC-MON-HIST-001…006, WP-7 · **Уровень:** L1 · **Тип:** property-based
**Оракул (PASS, если все условия):**
- Счётчики монотонны в пределах сессии; конверсии KiB/MiB/GiB точны (1024-базис, округление только на отображении); переполнение >4 ГБ не даёт отрицательных значений.

### AT-07-010: Скрытая вкладка и фоновый поллинг
**Трассировка:** F-091, WP-7 · **Уровень:** L3 · **Тип:** performance, functional
**Шаги:**
1. Свернуть окно/скрыть страницу на 30 мин при активном мониторинге; затем восстановить.
**Оракул (PASS, если все условия):**
- Поллинг в скрытом состоянии соответствует политике (снижен/приостановлен); CPU main+renderer в фоне ≤ 2% суммарно.
- При восстановлении — плавное обновление без шторма запросов (≤ 1 волна catch-up).

### AT-07-011: Двухстековые проверки утечек
**Трассировка:** AC-DIAG-LEAK-001…005, F-092, WP-7 · **Уровень:** L3 · **Тип:** security
**Шаги:**
1. Проверки утечек по IPv4 и IPv6 отдельно, включая попытку WebRTC local/remote candidates.
**Оракул (PASS, если все условия):**
- Оба семейства проверены; результат раздельный по семействам; WebRTC-кандидаты не раскрывают реальный IP (при активной защите).

### AT-07-012: Полная недоступность внешних сервисов
**Трассировка:** F-093, WP-7 · **Уровень:** L3 · **Тип:** fault injection
**Среда:** NET-CAPTIVE + блок всех внешних check-эндпоинтов.
**Оракул (PASS, если все условия):**
- Все проверки — `not-checked` с причиной; приложение остаётся полностью функциональным; нет циклических ретраев чаще политики.
