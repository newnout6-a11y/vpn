Главная/Возможности

Всё, что нужно, чтобы доверять соединению

Клиент собирает защиту из независимых слоёв, и каждый можно проверить отдельно. Где защита зависит от прав администратора или от настройки, это сказано прямо.

Режимы

Два способа подключиться

{{icon:plug-zap|icon}}

«Прокси» — без прав, по умолчанию

Движок слушает loopback-вход mixed: HTTP и SOCKS5 на 127.0.0.1. Приложение обратимо направляет на него системный прокси пользователя.

  • По выбору — переменные окружения, Git, Gradle, Android Studio
  • Программы, которые не используют системный прокси, идут напрямую, и интерфейс это пишет
  • Kill switch: off откатывает настройки сразу, standard держит прокси на мёртвом порту до переподключения
{{icon:shield-check|icon}}

«Туннель» — от имени администратора

sing-box поднимает TUN-адаптер Wintun для всего трафика системы: auto_route и strict_route, IPv4 и IPv6, перехват DNS. Kill switch и защита от утечек — фильтры WFP.

  • standard — динамическая сессия WFP, исчезает вместе с процессом
  • strict — постоянные фильтры, переживают выход и перезагрузку
  • Без прав режим показан недоступным с причиной, а не работающим
{{icon:gauge|icon}}

Движок: «авто», sing-box или Xray

В «авто» профиль, которому нужен Xray (XHTTP, VLESS Encryption и другие), идёт через Xray, остальные — через sing-box. VLESS с REALITY тоже уходит на Xray: sing-box 1.14.4 к серверам Xray 26.9.8 и новее по REALITY не подключается. TUIC, NaïveProxy и AnyTLS есть только в sing-box, и интерфейс говорит об этом, а не переключает молча.

DNS мимо туннеля закрыт

С защитой DNS (порты 53 и 853) вне TUN заблокирован для всех, кроме движков и приложения. Внутри по умолчанию — Cloudflare DoH через туннель.

IPv6 отклоняется

IPv6 через VPN выключен: соединения отклоняются внутри sing-box, программы сразу переходят на IPv4.

STUN в туннеле

STUN (3478, 3479, 5349, 19302–19309) закреплён за туннелем, чтобы WebRTC не выдал реальный адрес через прямой маршрут.

Защита браузеров

Политики WebRTC пишутся в HKLM и работают только от имени администратора. К Firefox защита WebRTC не применяется и помечена «не проверено».

Проверка утечек

Публичный IP, утечки и самопроверка маршрута. Вердикт отличает утечку от возможной утечки и от результата, который определить не удалось.

06
Маршрутизация

Что напрямую, а что через туннель

Smart RU отправляет напрямую госсервисы и банки из набора gov-ru и адреса, которые geoip-ru относит к России. IP-чекеры, Google и YouTube закреплены за туннелем, остальное идёт через него по умолчанию. Закрепления стоят выше ваших правил, и у каждого правила интерфейс показывает итоговый маршрут. По умолчанию Smart RU выключен.

Раздельное туннелирование

Через VPN, напрямую или без правила для каждого приложения, по пути к exe или по имени программы. Работает и в «Прокси».

Свои доменные правила

Через VPN, напрямую или блок, по точному имени, поддоменам или ключевому слову. Список импортируется из файла до 4 МБ. Блок проверяется первым.

Внешние прокси и API

Нумерованные слоты 127.0.0.1:<порт> для других программ, API управления на 127.0.0.1:17873 с токеном и консольный клиент vpnte-proxy.exe.

PowerShell
# статус слотов внешних прокси
vpnte-proxy status

# то же через API; токен лежит в папке данных
$t = Get-Content "$env:APPDATA\VPN Tunnel Enforcer\external-proxy-control-token"
curl.exe -H "X-VPNTE-Control-Token: $t" http://127.0.0.1:17873/status
